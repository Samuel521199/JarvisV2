<a id="memory-selection-design"></a>
## 单机与共同体的记忆选型设计

本节沿用 2026-10-18 复核后的设计结论；开源组件及许可详见[选型](stack-project-layout.md#memory-open-source)，运行实现均待新工程验证。原则是原始证据可追溯、事实可纠正、索引可重建、节点可离线、联网后可解释地合并；一个共享向量库不能替代这些职责。

<a id="memory-operating-cycle"></a>
### 交流、经历、事实和 Wiki 如何一起工作

以下是完整目标流程，不是新增后台服务已经运行。它沿用[分层](#memory-data-1)，把需要即时响应的读取与可以延后的整理分开：

| 信息职责 | 写入/更新时机 | 回答时如何使用 |
|---|---|---|
| 近期交流与工作状态 | 当前会话追加；任务状态由既有账本更新 | 有界窗口直接读取；必要摘要可回查原消息，未结任务引用不因压缩丢失 |
| 原始情景经历 | 允许保存的交流与工具回执到达后 | 按人、主题、时间和作用域定位原片段；原话只是“当时说过什么”的证据 |
| 长期事实与偏好 | 明确操作立即处理；自然描述经候选整理与晋升规则处理 | 使用当前有效、适用范围内的版本；历史事实仅在明确历史问题中使用 |
| 主题知识/Wiki | 新资料、源版本变化或明确整理任务触发 | 先给简述与章节目录，按需展开，并可追溯到来源；资料过期时提示并回查 |
| 经验与技能 | 有真实完成回执后形成经验候选 | 已验证经验帮助决策；生成技能仍走独立构建、测试、发布流程 |

一次自然交流的设计流程是：

1. **登记可用来源。** 临时会话与不允许保存的内容不入后台队列；普通交流保留既有归档策略。同一消息按主张标记主体、角色、范围和时间，原件保存一次；网页正文或其他 Agent 的话不能变成主人指令。归属见[信息分类](#memory-domain-catalog)。
2. **先回应，再整理。** 当前问题通过 MemoryView 取相关偏好、经历、知识和真实进度，按用途、消费者及实际目的地过滤；后台整理失败不阻塞回应，也不伪称保存成功。面向他人的产物另按[输出边界](#memory-use-boundary)装配，不继承私人历史。
3. **对变化产生候选。** 先做重复、无价值和明显不适用过滤，确需语义理解时调用 MemoryExtractor；输出有依据的类别、适用条件及“为什么值得保留”，不复制整段回答为主人事实。未明确范围的内容留待核对，提取失败保留允许的原件和待处理状态。
4. **按类别生效。** 明确记忆操作保持原语义；未来启用自动整理时，主人可配置低歧义偏好自动生效并可撤销，含糊、相互冲突和敏感推断进入待确认。自动生效必须有对应许可和验收；未确定的候选保留待核对。
5. **更新派生内容。** 事实提交后标记受影响索引、画像、摘要和章节为待更新；只整理相关片段。需要跨域复用时走[共享连接](#memory-sharing-bridges)，知识编纂不覆盖原件，关联图不反向改写事实，未更新视图显式报告缺口。
6. **纠正与遗忘优先。** 生效事实可立即退出召回，再清理相关候选、缓存和索引。后台任务提交前再次检查来源版本和撤销，防止在“忘记”之后把同一来源重新提取回来。
7. **有变化才协同。** 未来已配对节点按允许范围交换事件和原件引用，各自维护索引；断网仍使用本地资料，重连合并不等于重新执行历史任务。协议只在[共同体章](federation.md#memory-replication)定义。

自动保留的价值判断考虑明确意图、未来复用、稳定性、约定和共同经历，而不是只挑“工作上有用”的信息。一次重要的生活经历可以有伙伴价值；一句玩笑、角色扮演或短暂情绪不因此成为永久人格标签。主人切换表达人格可以共享允许的现实背景，NPC 的虚构记忆始终留在对应世界。自动关联和模型反思只是辅助解释，不提供事实真实性或新行动权限。

“忘记某条记忆”与“删除原始聊天”继续区分：前者撤销长期使用，后者按归档策略处理原件；未来需用最少必要的撤销标识阻止同源再提取，并展示尚未处理的离线副本或保留范围。不能为了防复活而在墓碑中保留被删除的完整敏感正文，也不能宣称已经抹去外部供应商、用户导出和所有备份。

记忆自检检查来源失效、冲突、孤立引用、索引水位、过期候选和队列积压；自愈可重建派生索引，不能编造丢失原件或自动裁决冲突；进化只提出新分段、提取、召回和组织方式，经固定对照后替换。若知识重组没有可测收益，保留原结构，不为“自主成长”不停改写记忆。健康与发布完整规则分别见[维护章](health-maintenance.md)和[进化章](evolution-release.md)。

<a id="section-c30fc1f84bda"></a>
### 分层保存，避免把所有东西都变成聊天摘要

沿用[数据分层](#memory-data-1)，将原件放入带摘要的对象存储，事实/修订和事件放入本地事务库，关键词/向量/关系放入可重建视图。任务工作记忆引用既有任务账本；规则、人格配置与技能包保留各自版本权威，检索结果不能改写 G0 或授予能力。

事实使用“何时有效”和“何时得知”两个维度：主人今天纠正上周的项目地址，应能分别回答“上周实际地址”和“当时系统知道什么”。这里是我们的事实建模要求；Graphiti 的时态方法可供实现参考 [S94](references.md#s94)，不等于必须先部署图数据库。相似表达不能仅凭向量距离合并为同一实体，也不能把 Agent 猜测提升为主人确认。

<a id="memory-scope-model"></a>
### 先理解主人，再按场景读取个人与项目记忆

**完整目标，proposed；当前实现边界见[现状表](knowledge-learning.md#memory-selection-design)。** 推荐统一记忆接口与事实管理规则，在数据中区分主体、用途、项目/世界和使用许可，再为每次请求建立有界视图。个人会话不要求先创建项目；项目中的一句话也不天然是工作事实。同一个助手可以理解主人全部已授权生活与工作范围，但每次回答、交付物和外部调用只使用该用途允许的内容。

分类按**具体片段/主张**进行，不把整场会话永久判成“生活”或“工作”。“今天有些累；A 项目发布推迟；以后周报先给结论”可以产生临时状态、项目决定、交流偏好三个不同候选。原件仍保存一次；多项引用共同原件不意味着可以向某个消费者返回整段原话。尚不明确的范围保持待归类，不默认设为全局共享。

<a id="memory-domain-catalog"></a>
#### 个人、工作与共同使用的信息分别保存什么

以下是逻辑用途，不要求每行建立一个数据库、模型或常驻 Agent。长期事实保存在原 MemoryStore，原件、执行状态、配置和技能保持各自权威；物理落点归[存储分层](#section-c30fc1f84bda)。

| 信息类别 | 应保存的内容及权威 | 默认使用与共享方式 |
|---|---|---|
| 主人明确资料 | 主人选择提供的称呼、语言、时区、长期目标；逐项事实和来源 | 相关个人交流可用；仅明确适用工作的字段进入工作视图。地址等私人字段不因属于“主人资料”就全局装配 |
| 喜好与条件偏好 | 兴趣、饮食、表达习惯，以及“工作汇报先给结论”“技术教程要详细”等适用条件 | 通用表达偏好可供多个项目使用；情境例外与全局偏好并存，不互相覆盖 |
| 主人画像视图 | 由当前有效事实组成的兴趣、目标、沟通方式等分项摘要；本身是可重建视图 | 不维护一个由模型不断整体重写的巨大人格档案；明确事实、观察和推测分开，工作视图只取相关字段 |
| 私人交流与共同经历 | 有价值的生活经历、重要约定、共同讨论、关系模式中的偏好及原文 | 个人陪伴按相关性回忆；不默认写入工作报告、代码注释或共享 Wiki。情感价值也可成为保留理由 |
| 临时感受与当前状态 | 主人当下表达的疲惫、心情、临时日程、一次性意愿 | 绑定时间和会话/情境；失效后不继续影响当前画像。一次挫折不推导为长期能力或性格标签 |
| 工作习惯与能力证据 | 主人明确的工作偏好、已验证技能使用经验、适用场景和限制 | 可跨项目的习惯进入获准共用背景；某项目的栈选择不等于主人永远偏爱该技术，一次成功也不等于普遍熟练 |
| 项目资料与决策 | 需求、文档、源码事实、参与角色、约束、决策及适用分支/版本 | 归指定项目/组织域；项目 A 的决定不成为 B 的规则，不自动推导为主人个人观点 |
| 工作结果与实际状态 | 产物、测试结果、执行回执、失败原因；当前状态以任务账本和版本化产物为准 | 记忆只保存摘要和稳定引用。助手说“已完成”不是执行证明；主人转述的结果记录为转述，不伪装工具核验 |
| 可复用经验与公共知识 | 有来源、适用前提、失败边界的通用方法；公开资料与项目抽象经验区分来源 | 原本已公开的知识按其适用范围使用；项目经验通过下节的晋升流程后再跨项目用，不把脱敏摘要自动当作公开知识 |
| 项目与未结事项目录 | 获准项目的 ID、简述、来源入口；个人约定和工作任务的索引/状态引用 | 帮主人统筹生活与工作；详细证据按需读取，目录名称本身也受可见范围限制，不用全库正文填充上下文 |
| 联系人与其他主体 | 区分主人、同事、客户、组织、设备、Agent 的稳定身份、关系与陈述来源 | 同名不同主体不自动合并；客户说“我喜欢红色”不写入主人画像，组织规范不自动变成个人偏好 |
| Jarvis 人格与 NPC 世界 | Jarvis 的表达/关系配置独立版本；NPC 事件绑定 world/persona/角色身份 | 表达人格可共享允许的现实背景；虚构世界不写入主人现实事实。学到的通用方法仍需去除虚构事实、验证后晋升 |
| 环境与凭据 | 环境能力有时效，行动前重新检查；密钥/令牌保存在专用凭据配置 | 普通记忆最多记录受控引用，不将密钥正文建立向量或 Wiki；设备信息不因曾经可用就代表现在可操作 |

<a id="memory-profile-governance"></a>
#### 画像由可纠正事实组成，偏好按情境生效

画像采用“逐条事实集合 + 小而有界的当前摘要”，同时保留来源与适用条件。这样的取舍兼顾局部纠正与阅读便利；整体画像和记忆集合的不同更新代价见 [S232](references.md#s232)。删除某条事实后，相关画像片段需要失效或重建，不能让旧画像继续携带已忘记的信息。

主人明确说“我喜欢简洁”可以成为偏好；模型观察到主人经常要求缩短回答，可以形成可见的待核对建议，不能直接写成“主人不喜欢深入思考”。主人的原话是其表达的证据，对外部世界的陈述仍应区分报告、假设和独立核验。人格配置不会因一条被检索出的笔记而改写。

在满足授权和数据使用范围之后，表达偏好按“本轮明确要求 → 当前情境/项目专属偏好 → 通用偏好 → 默认值”选择。这个次序不允许放宽隐私或执行权限，也不用于裁决事实真伪。两个等效范围内的新陈述互相冲突时保留待核对状态；不能只按设备时钟或模型自报置信度选一个覆盖。

临时状态要有有效期或复核条件，过期退出当前视图；它若作为一段重要经历被保留，仍然是“当时的状态”，不升级为现在的永久属性。兴趣变化、目标完成和工作栈迁移都保留有效时间与获知时间。日常 UI 应允许纠正单项、改变适用范围和停止某类自动提取，不能要求主人编辑一份复杂 JSON 才能管理画像。

<a id="memory-sharing-bridges"></a>
#### 共用信息通过引用、条件偏好和经验晋升连接

| 连接方式 | 例子 | 保存和撤回规则 |
|---|---|---|
| 同一有效事实的受控引用 | “对我的汇报先给结论”适用于多个项目 | 保存一条带条件的偏好，视图引用其 ID/修订；纠正一次即使相关视图失效，不为每个项目复制一条独立正文 |
| 本次联合查询 | 对照 A/B 两个项目的登录方案 | 创建本次允许范围的联合视图，分别给来源；查询结束不改变两个项目的长期分享配置 |
| 从项目识别个人偏好 | 在 A 中说“以后所有项目的汇报都先给结论” | 提出主人通用偏好候选，按已配置策略或明确要求生效；“这个报告用表格”只对当前范围成立 |
| 从工作抽象可复用经验 | 从一次故障中总结“带请求 ID 的幂等重试方法” | 新建有来源的经验候选，去掉项目专有数据并验证适用前提；扩大使用范围需有可检查的既有分享规则或明确决定，不能仅凭模型说“已脱敏” |
| 为当前用途生成最小必要信息 | 私人原因提示今天应简洁交流 | 工作阶段可获得已允许的“先给结论”表达设置，不获得背后的私人原因；此派生设置仍带有效期、来源依赖和用途限制 |

“共用”是允许的读取或经过核对的晋升，不是把所有内容搬到一个 public 文件夹。衍生摘要、画像、经验、关系边和检索缓存默认继承全部输入的限制；多来源组合取共同允许的用途/目的地，不能因其中一个来源公开就公开全部。通过显式晋升形成更宽范围的派生结果时，记录依据、准许的输出字段、审核状态和原依赖；原件不随之公开。原依赖被纠正或撤销后重新核对派生结果，不能丢掉来源以规避撤回。

<a id="memory-use-boundary"></a>
#### 允许理解、允许输出、允许外部处理分别判断

分类标签不是权限。应用在检索前固定主体/项目/世界、用途、消费者及实际目的地，限制候选集合；返回前复核来源、修订、时间、撤销和策略版本。模型只能建议相关资料，不能扩大范围。上游 metadata 过滤仍需按实际后端验证，不能假定更换后端后含义完全相同，[Mem0 的官方说明 S233](references.md#s233)明确列出了差异。

| 当前活动 | 可以装配的内容 | 不应默认装配或输出的内容 |
|---|---|---|
| 私人聊天、陪伴和共同回忆 | 相关主人背景、经历、当前约定；问及工作时可读获准的工作摘要 | 全部项目源码、无关客户资料、其他 NPC 的秘密记忆 |
| 向主人解释当前工作 | 适用表达偏好、当前项目证据、已晋升经验、真实任务状态 | 私人聊天全文、与解释无关的生活细节、其他未选项目内容 |
| 生成客户邮件、共享文档或公开成果 | 此输出用途获准的项目片段、公开知识、可复用经验，以及可披露的格式要求 | 仅供私人交流的背景、内部失败分析、未获准跨项目材料、内部记忆引用中的敏感路径 |
| 跨项目统筹与比较 | 获准目录和明确项目集合的相关证据，各自保留来源 | 将本次读取资格变成永久互通，或把某个客户的观点归给主人 |
| 多 Agent 分工 | 每个任务需要的最小资料和返回产物约束 | 给所有 Agent 完整画像/聊天/钥匙；把 Agent 的猜测写成主人事实 |
| NPC 或角色扮演 | 对应世界状态、允许的设定；角色可见子集 | 将虚构情节变成现实经历，或让 NPC 自动读取主人的私人关系资料 |

**重要实现边界：**若同一个生成请求已经拿到私人原因，只在提示里说“不要写出来”不足以证明其不会出现在交付物中。面向他人或公开的产物阶段应从允许输出的资料重新装配上下文，必要时使用独立调用；不能沿用含私人信息的完整聊天历史、草稿或 Agent 中间结果。无法可靠分离的混合片段先缩小到核对过的字段/句子，仍不确定时不给该阶段使用。额外调用的费用与延迟需计入验收；并非每次私人聊天都要求双调用。

模型提供商、远端 Agent/工具、同步设备、产物读者、屏幕/朗读/通知是不同目的地。允许某模型辅助私人交流，不自动允许公开发布这些内容；允许同步到自己的手机，也不自动允许手机上的云模型处理。更换接入方或输出受众时重新生成视图。原文不适用的出站查询、embedding 文本、缓存、日志和错误报告同样不能夹带原文，读权限和查询词本身都需要检查。

隔离由应用查询与实际上下文构造执行。普通项目先逻辑分域，敏感资料可选独立库/目录、密钥与进程访问边界；逻辑分域并不阻止同用户恶意进程读盘。工程字段归[视图契约](contracts.md#memory-view-contract)，实际执行隔离归[运行边界](security-sovereignty.md#personal-life-supply-chain)。用户已明确允许的范围不逐次重复询问，只有用途、受众或范围不清且会影响结果时再澄清。

<a id="memory-human-continuity"></a>
### 人性化连续性与记忆可信度

本节是[伙伴核心](product-requirements.md#personal-companion-core)的数据落点，完整流程 proposed；新工程需验证归档、明确事实、纠正、接续和候选整理如何共同改善真实交流。

一次对话按主人身份和当前场景选取：生效的称呼/表达偏好、相关事实或共同经历、当前话题的接续摘要、真实未结事项引用。没有相关记录时使用普通对话，不整库加载历史；项目资料只在相关且范围允许时加入。经历可有叙事价值而没有工程产物，但必须保留说话者、时间、来源、纠正和删除关系；短暂情绪只用于适当的当前回应，不直接推断长期人格。

长期记忆依据未来价值、稳定性、明确意图和可验证来源筛选，不是“模型说重要就永远保存”。问候、重复措辞、短暂情绪、未验证推断和大段生成回答不自动升级为稳定个人事实；可在会话归档中保留其原始上下文。明确“记住”和“忘记”直接进入对应确定性流程，隐含偏好可先作为有期限的候选，重复证据提高可用性但不授予权限。完整晋升规则沿用[选择性记忆](knowledge-learning.md#memory-selection-design)。

每条记忆区分**说话者、来源类型、可信程度和适用范围**。模型说“文件已保存”只是模型陈述，只有相应工具成功回执才能支持“文件实际写入”的事实；外部网页和其他 Agent 的结论不能自动变成主人指令。多个模型重复引用同一个来源不算独立证据。主人纠正后保留可解释修订，不用累积旧摘要制造相互矛盾的“人格”。

界面应在需要时显示“记住了哪一项、用于哪些范围”，允许更正、撤回和暂停记忆；不在每条回答下要求手工保存。展示“本机已保存 / 已提取 / 待同步 / 存在冲突”而非一个含混的成功标记。尚未做完的工作以真实任务状态回答，不因伙伴人格而虚构共同经历、持续关注或已完成的动作。

自然语言记忆写入需先区分主人陈述、引用、假设和模拟台词，再交给既有记忆 API；候选推断不能直接覆盖明确事实。人格配置只引用适用记忆，模型缓存和检索摘要均不是事实权威。切换模型、重启或更换界面后从持久状态重建；遗忘与修订使相关派生摘要失效，跨设备传播沿用共同体语义。具体场景统一在[V-PAL](delivery-validation.md#personal-companion-validation)验收，不用检索条数替代相处质量。

<a id="project-knowledge-compilation"></a>
### 项目知识编纂：来源变化后有界更新

KnowledgeCompiler 将获准源码、现有权威文档与测试回执组织为可检索的事实和解释；OpenWiki 的具体借鉴范围见[源码对照](stack-project-layout.md#openwiki-adoption)。这是知识模块的生产者，不是另一个自动执行核心。

流程为：登记项目与来源范围 → 读取 manifest/目录和来源版本 → 建立 Claim 到源文件/段落/测试的引用 → 生成候选说明 → 检查引用、冲突、状态和文档结构 → 更新对应权威位置或派生阅读视图 → 增量更新索引。源码变更只把依赖它的 Claim 标记为待复核，未受影响内容不重写；哈希未变证明内容相同，不证明解释正确。

以本仓库为例，`docs/manifest.json` 指定主题权威，`implemented/verified` 必须对应实现与测试证据。自动生成的“代码是这样工作的”不能覆盖尚属 proposed 的产品目标，也不能把后者写成已具备能力。生成过程中保留来源版本，发布前发现源文件已改变则重新核对，避免在旧快照上确认新文档。

跨项目链接采用稳定项目/文档/章节 ID，实际本机路径由节点映射；电脑的盘符不能成为手机的全局身份。移动、删除或分支切换触发引用检查，保留提交/分支/工作区版本区别。未保存草稿、未追踪临时调试内容不自动并入正式知识。源码、文档、截图和网络资料分别有受限解析器，按真实需要启用，不为了“全知识”安装全部解析工具。

<a id="section-63a49a4a6d48"></a>
### 写入与查询

写入沿用[知识晋升](#continuous-learning-2)：捕获已获准原件与事件 → 确定性标签/隐私检查 → 可选模型提取候选 → 保留来源的事实修订 → 异步更新派生索引。原始事务提交和可检索状态分开返回；提取超时不丢原件，重复事件不重复生成已晋升记录。断网或资源不足时允许积压提取，明确显示处理水位。

查询先按主人、项目、现实/模拟域、资料权限、当前版本、有效期和撤回状态限定候选，再分别进行词项与向量检索，按稳定文档/事实 ID 合并排序，按需增加重排或时态关系查询。初期可用倒数排名融合，不能直接相加来自不同后端且尺度不一致的相似度。最终上下文仍检查权限和引用，不能先把全部资料发给云模型再要求它过滤。

上下文包带证据引用、事实有效时间、来源节点、查询水位和冲突提示。“同步完成”“索引更新完成”和“事实已解决冲突”是三个状态。只有摘要时先标摘要，必要时打开原件；摘要继承来源的数据外发限制，来源过期/删除后关联摘要失效。中文全文基线的限制见[实际探测（旧工程参考）](references.md#legacy-project)，避免把零命中解释为系统没有这段记忆。

完整请求通过 MemoryViewResolver 解析当前主人、任务、项目集合、人格/模拟域及实际模型目的地，再调用 Retriever。共享背景采用小而有界的预算；项目目录先发现，详细证据再按章节读入。临时跨项目联合视图用完即释放，不把两个项目自动合并成一个知识库。外部模型回退换供应商时重新判断资料是否允许发送，不能只检查最初的路由。

有害越域候选应在检索候选生成阶段排除，并在输出前再次按 MemoryStore 当前修订核对；不能先全库 top-k 再过滤，导致既漏掉允许结果又暴露受限信息。索引尚未追平时优先返回确定性事实、标注缺口，必要时进行有界原件读取；没有可靠证据时说明不确定，不编造记忆。接口字段见[MemoryView 契约](contracts.md#memory-view-contract)。

<a id="section-2c2fddabd6b3"></a>
### 完整节点如何保有自己的 Jarvis

每个完整节点预装控制所需知识、主人明确偏好及其离线任务依赖的资料子集，保存本地事实与检索入口。仅有远端对象引用而无本地内容时，应显示“资料未离线准备”，不能声称全知识可离线。轻节点可以只缓存部分内容；节点等级和限制由[共同体设计](federation.md#offline-federation-1)说明。

联网后共享的是获准事件和资料，不强制每台设备拥有相同索引、同一模型或全部私人记录。事实一致性由[同步与冲突协议](federation.md#memory-replication)维护；每台节点按自己的计算能力构建检索视图。中心检索不可用时回到本地，并说明查询范围；“联网形成统一 Jarvis”在工程上表示共享身份、可追溯记忆与受协调行动，不是自动消除所有并发分歧。

<a id="section-59821024e11f"></a>
### 可替换接口与自我改进边界

MemoryStore 管理事实/事件和导出；Extractor 只产生带来源的候选；Retriever 返回引用与版本；EmbeddingProvider 管理向量空间；SyncTransport 搬运已获准变更。接口职责见[公共契约](contracts.md#memory-provider-contracts)，不要把某框架私有对象直接存为唯一长期格式。

换模型、索引或提取算法使用独立代次：固定原件和评测集 → 在旁路构建 → 对照查询 → 原子切换索引指针 → 保留可恢复旧代次 → 按引用退役。构建期间的新事件按日志水位补齐；删除/撤回对新旧索引都立即生效于查询门禁，不能等待重建结束才处理。失败时回到兼容代次，绝不回滚主人后续修正或恢复已遗忘内容。

这也给 K5 提供第一个可验证的自我改进对象：只改检索实现，比较证据召回、错误引用、中文短词、时间冲突和资源成本；事实原件、隐私门禁与评估基线保持独立权威。

<a id="memory-data"></a>
## 记忆、知识与数据同步



<a id="memory-data-1"></a>
### 数据分层

| 层 | 内容 | 权威性 |
|---|---|---|
| 原始事件 | 用户指令、观察、反馈、动作回执 | 保留原始来源，不代表内容必然真实 |
| 结构化事实 | 偏好、设备、关系、项目事实 | 带证据、范围、时间、置信与冲突 |
| 情景记忆 | 共同经历、任务过程与结果 | 可回溯事件 |
| 程序性记忆 | 已验证技能与使用经验 | 带版本与测试 |
| 工作记忆 | 当前对话和任务上下文 | 短期、可压缩、有检查点 |
| 派生数据 | 摘要、向量、索引、统计 | 可重建，不能成为唯一原件 |

框架检查点用于当前执行连续性，长期资料另行管理；可参考 LangGraph 的 checkpointer/store 区分。[S11](references.md#s11)

<a id="memory-data-2"></a>
### 同步策略

共享资料须按本机模型用途授权，保留来源及派生依赖，不自动成为主人事实。个人记忆与项目知识各使用自身授权；失效引用停止后续使用，已经外发的文本无法追回。

同步机制、按数据类型的合并规则及冲突处理统一维护于[共同体记忆复制](federation.md#memory-replication)。本页定义哪些资料可以分享与遗忘；共同体页定义它们怎样送达、确认和避免旧副本复活。

<a id="memory-data-3"></a>
### 隐私范围

同步范围与外部模型使用许可分开：

- sync_scope：device_only、selected_nodes、community。
- external_processing：deny、allow_listed_providers。
- 保留级别：临时、长期、到期删除、用户手动保留。
- 数据标签随产物和派生摘要传播；摘要不能绕过原始资料的外发限制。

凭据保存在所属节点的系统密钥存储中，其他节点通过授权代理请求动作；不把密钥混入记忆、提示词和同步事件。

<a id="memory-data-4"></a>
### 本地事务与复制

记忆存储有自己的唯一写入 API 与本地事务，和任务/动作控制账本分别管理；不得直接写其他模块所属表。事件、outbox/inbox 与跨域事务边界统一见[记忆组件契约](contracts.md#memory-provider-contracts)，多机复制、去重和恢复代次见[共同体协议](federation.md#memory-replication)。

关键动作和授权账本在向调用方确认前必须达到规定的持久提交级别；SQLite 同步策略和备份策略分别验证断电与介质故障边界。索引落后允许标注降级，事实提交丢失不能用“最终一致”解释。

<a id="memory-data-5"></a>
### 遗忘与备份

删除请求生成传播记录，删除原始内容及对应摘要、索引和缓存。审计保留最少的删除事实，不保留被删除的敏感正文。备份设保留期，并记录备份中的删除处理规则。

离线设备只能在重新连接后收到删除指令；已被不可信设备复制的内容无法保证远程销毁。安全归档或压缩日志前，应确保快照与同步游标一致，避免旧节点重连使已删除内容复活。

墓碑传播、过期副本与重新入群的具体规则统一见[共同体记忆复制](federation.md#memory-replication)。

<a id="continuous-learning"></a>
## 持续互联网学习与知识库自主重构



<a id="continuous-learning-1"></a>
### 持续学习的目标与边界

系统可以根据主人的长期目标、重复失败、设备变化和技术更新，持续跟踪官方文档、论文、软件发布与获授权的信息源。学习任务具有明确用途、来源范围、预算、周期、截止时间和收益标准；没有新信息或收益时低成本等待。

学习可以改变知识、技能、策略和实现，不能改变服从谁、哪些资料可外发、授权范围、G0 或关停规则。“从网上学到了一个新方法”不自动构成安装程序或扩大权限的许可。

<a id="continuous-learning-2"></a>
### 学习流水线

<a id="continuous-learning-3"></a>
### 逻辑模块

| 模块 | 责任 |
|---|---|
| learning-planner | 把能力缺口和技术变化转为有预算的学习任务 |
| technology-watch | 监测版本、论文和获授权信息源，去重与筛选 |
| evidence-ingestion | 采集、解析、哈希、来源与版本登记 |
| knowledge-quarantine | 保存未验证资料和待验证代码，不持生产权限 |
| knowledge-validator | 检查事实、冲突、时效性和实验结果 |
| memory-curator | 纠错、合并、过期、删除和经验归档 |
| knowledge-evolution | 提出知识结构、索引、存储与检索方法变更 |
| promotion-controller | 分别检查知识、技能和程序的晋升条件 |
| knowledge-evaluator | 保留查询测试集，检查检索、证据、污染和性能 |

知识晋升与代码发布共用根规则和证据机制，具体门槛不同；不能因为文档核验通过就跳过程序测试。

<a id="continuous-learning-4"></a>
### 知识的三个层次

1. 证据层：原始资料、来源、版本、时间、必要快照和保留规则。
2. 规范知识层：事实、关系、项目记录和操作经验，以及指向证据的链接。
3. 派生检索层：摘要、全文索引、向量、知识图谱和缓存，可重建与替换。

MemGPT 的分层记忆与 MemOS 的记忆资源管理可作为研究参考；它们不保证无限记忆、无误检索或生产迁移自动正确。[S31](references.md#s31)[S32](references.md#s32)

<a id="continuous-learning-5"></a>
### 允许自主重新设计知识库

在既有数据和维护权限内，系统可以比较并改造：

- 数据库、对象存储和冷热分层。
- 文档分块、全文索引、向量索引和缓存。
- 嵌入模型、维度、距离度量和重排模型。
- 实体本体、关系类型、实体合并和知识图谱。
- 全文、向量、图谱和混合检索路径。
- 去重、摘要、归档、过期和删除机制。

GraphRAG 提供可配置的实体、关系、社区摘要与向量索引流水线参考；不要求所有知识都使用图谱，也不能把模型抽取的关系当作已证明事实。[S33](references.md#s33)

<a id="continuous-learning-6"></a>
### 迁移协议

先保留旧读入口，建立新索引/存储，在独立空间回填历史和追赶新增事件，再对照查询、逐命名空间切换，最后清理旧格式。

- 迁移版本固定，读请求绑定一致的数据视图，不混用半完成索引。
- 新旧嵌入空间不能直接混合；记录模型、维度、分词/预处理、分块与索引版本。
- 本体变化保存旧实体到新实体映射与歧义，不覆盖原始证据。
- 重放仅重建知识，不能重执行曾记录的现实动作。
- 墓碑、删除、访问范围与撤销记录同时迁移，防止资料复活或跨域暴露。
- 可回退性需要验证新写入与旧格式兼容；只有旧备份不等于无损回退。
- 当 G0 锁存触发时，停止新迁移工作，持久记录安全中断点；不得以“完成迁移”为由继续自主作业。

<a id="continuous-learning-7"></a>
### 记忆域与可信状态

```text
owner/<id>/preferences
owner/<id>/episodic
project/<id>
shared/verified
research/quarantine
world/<world_id>/<branch_id>/canon
world/<world_id>/<branch_id>/agent/<agent_id>/beliefs
world/<world_id>/<branch_id>/events
```

每条知识携带来源、版本、适用范围、有效期、敏感级别和 truth_status。状态区分直接记录、来源声明、已核验、推断、争议、过期与虚构；反复检索同一推测不会提高它的证据等级。

NPC 记忆不得改写真实用户偏好。模拟中的算法、代码和性能经验若要用于现实任务，须单独验证晋升。

<a id="goal-directed-understanding"></a>
### 围绕目标更新对主人、世界与自身的认识

**目标 accepted，通用机制 proposed。** “越来越了解主人”由适用事实的准确性、纠正速度和协助效果体现，不由收集多少隐私、多少聊天或多强的情感依赖体现。沿用[个人记忆连续性](#memory-human-continuity)与既有分域规则，新增的要求是把每次认识更新接回目标和实际反馈。

| 认识对象 | 可以主动学习的内容 | 更新与使用方式 |
|---|---|---|
| 主人 | 明确表达的偏好、现有约定、获准活动中的习惯变化、主人的纠正 | 本人陈述保留来源/范围；观察形成可纠正的假设，置信度不代表授权。重要冲突只问必要问题，不默默覆盖明确选择 |
| 世界与专业知识 | 与目标相关的事实、官方变化、研究方法、技术适用条件 | 保留时间/版本、原来源与独立支持；有争议或过期时带限定使用，重大结论需要相应核验 |
| 自身能力 | 哪些任务在什么模型、工具、环境和权限下成功/失败，真实费用与资源 | 更新原 SelfModel 和成长证据；安装成功、一次演示或模型自述不能升格为普遍能力 |
| 工作方法 | 可复用的步骤、失败反例、决策条件、技能缺口 | 优先纠正已有方法，必要时形成新技能候选；知识可信不自动批准可执行代码 |

每次更新遵循“来源事件 → 分域候选 → 冲突/时效/用途检查 → 原领域修订 → 派生摘要失效与重建 → 后续使用效果反馈”。聊天事实、工作成果、他人信息和 NPC 虚构资料保留原归属；只把获准且确实通用的偏好投影到工作上下文，不整库互拷。影响任务目标或权限的推断不得直接生效，已确认事实的纠正与遗忘按原撤回链传播。

重复出现同一句模型推断不构成新证据；多个 Agent 引用同一篇文章仍是一个来源。出现冲突时保留支持和反证，必要时降低置信或停止使用，而不是为了“永远积累加强”强行保留错误。无新信息时不重复总结全部聊天；按事件增量处理，在前台活跃或资源紧张时延后可推迟整理。

<a id="continuous-learning-8"></a>
### “不断积累”不等于无限堆积

知识量增长必须同步管理去重、版本、过期、删除、引用成本与检索质量。主人要求删除的资料不能以“自主进化需要”为理由保留。

离线时继续整理本地资料、运行已授权实验和重建索引，标记外部事实的最后核验时间。需要网络的学习排队；资源不足时优先暂停学习，保留交互与任务状态。

<a id="continuity-state-lifecycle"></a>
#### 连续身份的记录、纠正、遗忘与跨设备接续

**proposed。** [连续身份](architecture.md#continuity-definition)不新建覆盖所有业务的主数据库。起源与继承记录只保存必要身份元数据、规则引用和各领域读取水位；主人记忆、项目知识、私密关系、邮件、任务及模拟世界仍由原领域保存。Context Service 为某次角色工作构造用途视图，SelfModel 描述当前能力；两者均不是原事实的替代来源。

| 信息层 | 保留和演进方式 | 不允许的捷径 |
|---|---|---|
| 身份起源、继承与迁移记录 | 有界元数据和可核对的版本链；身份标识与设备标识分开 | 为每次换模型重新建立身份，或把一个字符串相同当作所有权证明 |
| 已有事实、经历、偏好与承诺 | 沿用原领域修订；区分当时判断与当前有效判断；错误撤回后相关摘要/索引失效 | 把“积累”解释成所有模型推断永久为真，或用新模型臆造缺失的过去 |
| 敏感正文与凭据 | 留在可撤销、可删除的原私密域；元数据只用受控引用 | 将邮件/密码/人员隐私复制进不可删除的永久日志；简单哈希低熵秘密仍可能泄露，不作为脱敏方法 |
| 派生摘要、索引、自身模型与检查点 | 记录来源修订；可重建、过期或删除；读取前检查用途与撤回状态 | 让旧缓存或恢复包重新启用已遗忘内容、已撤销许可或旧停止状态 |
| 成长经验与技能 | 失败留证，候选独立验证后晋升；无收益或退化时撤回 | 把一次成功当作通用可靠性；用自己生成的评分替代外部效果证据 |

仅对确需追溯的身份变更、承诺修订和迁移决定借鉴事件记录及派生视图方法；普通领域继续现有数据模型，不做全库 event sourcing 改造，也不增加消息中间件。回放只重建状态与索引，不重执行历史动作。该取舍结合事件溯源的迁移/查询复杂度与删除难题，来源见 [S279](references.md#s279)；长期知识与任务检查点分开也与 [S277](references.md#s277)的职责划分相符。

备份与恢复同样遵守现有删除/保留策略。恢复旧代码或旧数据前，必须合入仍有效的纠正、遗忘、撤权及动作对账记录；若这些较新记录无法取得，不可把旧快照自动宣布为完整当前身份。恢复缺口要明确展示，而不是让模型补写共同经历。

多设备共享同一助手身份，但保留独立 node_id、来源事件及可分叉观察。离线只能依据本地获准状态行动；重连合并来源、纠正与去重，不合并模型隐藏状态，不按时间戳最大值覆盖所有冲突。共同外部动作的所有权与冲突处理继续归[共同体章](federation.md)，个人/项目共享沿用原分域许可。身份一致与全局实时一致是两个不同目标。

<a id="system-health-12"></a>
## 知识、技能与规则也会退化

持续学习必须检测过期信息、错误摘要、虚假来源、循环引用和同一错误被多个 Agent 重复强化。原始证据与派生摘要分开；纠错更新事实状态并重建受影响索引，不把重复次数当作真实性。

技能增加后检查相似能力、依赖冲突和替代关系；优先改进既有能力而不是每次失败都生成新工具。退役技能先限制新调用，保留旧任务版本和历史证据。新增技能不能凭说明文本取得新的权限。

规则必须区分不可削弱的根宗旨、主人授权、组织策略与普通偏好。冲突时按固定优先级处理，不能让检索排序决定谁覆盖谁。规则更改需要来源和生效范围；模型主动建议可以保存，但不会自动成为新授权。

<a id="personal-life-data-domains"></a>
## 生活、关系、账号与工作数据的分域

人员与凭据进入独立私密域，默认不参与普通聊天或共同体。只有明确授权的人员用途投影才能进入适用上下文，姓名关系不能自动推导主人的偏好。

服务范围遵循[个人为主、家庭与小团体为辅](product-requirements.md#personal-service-scope)。同一 Jarvis 分别管理主人资料、各成员的获准资料、家庭／小团体共享资料和项目资料；每条记录绑定实际主体与可见范围，群体偏好不能自动变成个人偏好。自主任务的产物、执行证据与候选记忆仍按这些范围归档，不能因任务已完成就自动向全体成员公开。

目标设计 proposed；复用[现有记忆域](knowledge-learning.md#memory-selection-design)，下列是逻辑数据类型，不要求每类安装数据库或常驻 Agent。

| 数据类型 | 保存什么 | 使用规则 |
|---|---|---|
| 主人资料与偏好 | 明确兴趣、沟通习惯、作息、饮食／旅行偏好、学习目标 | 区分明确事实、推测、临时状态；可以纠正、忘记，不能以一次观看推断永久爱好 |
| 人员与关系 | person_id、别名、主人确认的关系、联系方式、共同约定、来源、可见性 | 联系人身份不是登录凭证；“家人”或“朋友”标签不授予主人权限；同名记录不自动合并 |
| 家庭／小团体共享资料 | 共享范围标识、获准成员、共同日程、分工、共享成果及各自来源 | 仅在有效成员与用途范围内共享；成员私人记录单独保管，退出或撤权影响后续检索、任务装配与派生视图 |
| 日程与承诺 | 时间、时区、参与人、来源、提醒政策、重复规则、完成／取消状态 | 日程不是偏好；会议邮件只能提出候选，确认后才修改权威日程 |
| 项目与工作 | 项目文档、任务证据、交付物、项目决策 | 绑定项目和受众，不能把客户资料带入闲聊或家庭共享 |
| 私密资料 | 个人经历、私密文件、敏感个人资料的受控引用 | 只对允许的主体／用途／终端开放，公共屏幕和播报不能泄露摘要 |
| 凭据与身份材料 | 密码、令牌、恢复材料、受保护证件字段 | 只存凭据代理或受保护文件库，知识库仅存不可解密的引用；不进入向量索引、聊天摘要或学习样本 |
| 订单与执行证据 | 金额、币种、订单号、外部状态、已执行／未知、退订回执 | 作为事务状态保存，不能凭模型叙述改成成功；与模型 token 费用分账 |
| 虚构角色／模拟世界 | NPC 身份、剧情、游戏设定 | 沿原模拟域隔离，不能成为现实家人关系、授权或主人事实 |

每次使用取主体、项目、用途、供应商、受众、资料有效性与当前身份许可的交集；共享通过引用与授权视图完成，不复制整份主人档案给所有 Agent。向某模型开放资料不等于允许向房间中的人朗读。身份或受众改变后，历史回答、缓存摘要和通知也要重新过滤。

隐私资料不以“有利于主人”为由自动送云端；应有本地处理、脱敏、最小片段或拒绝外发的明确政策。使用记录只保留必要审计信息，不将密码、验证码和敏感原文写入日志。单用户页面 token 或 provider 过滤不能替代多用户隔离。

<a id="person-permission-memory"></a>
### 私密人员与普通助手记忆之间的明确边界

人员记录默认继续留在私密册。只有经[原生窗口核对](interaction-persona.md#personal-plan-ui)的选定投影进入现有事实记忆；它是可以网页查看的已开放副本，采用 `third_party/other` 分类，不自动转成主人偏好。默认不含关系与备注，凭据不可投影。

事实来源绑定资料册修订，模型使用绑定用途、接入配置及有效期；旧回答复用原 memory_refs，许可失效后相关历史轮次不再输入模型。共享目录直接排除此类事实，不把本机模型许可继承为共同体发送许可。完整失效与残留副本语义见[安全章](security-sovereignty.md#identity-authorization)，结构与配额见[契约](contracts.md#clean-module-contract)。不新建向量索引，不自动从私密册总结或训练模型。

<a id="correspondence-data"></a>
### 邮件、日历与个人记忆的分域

导入邮件／日历是**待处理资料**，不是主人事实、第三人画像或工作成果的自动定论。`correspondence.db` 单独保存规范化来源与草稿，绑定导入时会话和项目；不会自动塞入聊天历史、MemoryStore、人员册、知识索引或共同体共享。私人会话与项目会话分别列出自己的资料；项目范围改变时原来源失效，必须重新导入核对。

邮件草稿属于未发送成果，即使模型写了“我已完成”，也不能据此登记任务完成或主人承诺。只有本人核对后加入 Agenda 的提醒才是本机明确承诺，复用原日程取消／提醒语义；它不是邮件邀请接受回执。未来提取记忆／项目知识须经原候选、出处、修订、撤回及受众限制，不能从这条导入路径绕过。当前尚未接自动候选整理。

起草只取所选一封邮件，不自动查阅偏好／私密人员／其他项目资料。后续若需要借个人风格写邮件，应增加可见且可撤销的字段投影，而非传整个人档案。来源移除、已导出副本和保留编号的处理统一见[安全边界](security-sovereignty.md#identity-authorization)。

账号读取保留 provider、account_id 和 message_key 来源，不把邮箱连接当作所有会话可见授权。连接凭据单独保存，正文和派生资料按用途管理。断开账号阻止新读取；本地已保存资料的删除和撤回另行处理并清楚说明。

<a id="mail-management-data"></a>
### 邮件管家的数据层与共享边界（方案）

整体数据分域方案 proposed。保留“邮箱原件 → 本机受管记录 → 个人行动/项目资料 → 经核对的候选记忆”四层，不能把收件箱直接当主人知识；完整流程见[邮件管家](tasks-agents.md#mail-management-plan)。

建议每个 MailRecord 至少包含 provider、account_id、message_id、thread_id、来源版本／摘要、收到时间、正文引用、供应商标签、本地分类、可信度线索与工作状态。相同邮件跨视图复用记录；本机分类与供应商标签分开，个人更正与模型建议分开。账号隔离使用稳定内部编号，不以邮件标题或模型识别的人名作为主键。Gmail 线程内不同邮件可有不同动作和保密范围，不能无条件把整个线程全部发给模型。

正文、附件和可识别个人的摘要按敏感数据保存；建议密钥封装沿用系统保护，提供轮换、迁移和恢复设计，不能把 CurrentUser DPAPI 宣称为跨设备可恢复。全文索引、向量、日志、通知正文和备份也会泄露信息：加密正文不等于索引已保护。首期应选受保护的受限缓存／按需内存检索，或明确提供搜索可见性选项，在没有可用方案前不静默建全邮箱明文索引。日志只记固定错误类型、用量和不透明引用，报告不保存邮件内容。

默认邮件仅在所属账号及会话范围可用。项目关联需要主人规则或明确核对；关联只是引用／有限投影，不把私人往来复制进项目共享层。个人写作风格、联系人称呼可经独立用途许可复用；密码、验证码、完整通讯录与私密资料册默认不进入起草上下文。云模型按当前邮件处理许可取必要片段，不默认整箱外发；凭据永不进入模型。长期偏好来自明确纠正／候选确认，订阅内容不是主人观点，第三人言论不是主人事实。

邮件到日程／任务／知识保留源账号、邮件编号、修订和许可出处。目标为原信删除、来源撤回或权限变化使派生摘要／检索缓存失效；0.1.105在history明确删除时以无正文墓碑替换缓存、搜索不再采用，但已明确导入的本地副本／独立日程不自动撤回，共同体投影尚未自动贯通。已明确接受的独立日程不悄悄删除，应提示核对；已外发和被收件方保留的内容不能追回。共同体默认只同步必要的行动回执／可撤销摘要，不复制 OAuth refresh token 或邮箱正文；以后另一设备代读需单独授权或向持有凭据的节点请求受限操作，不能把“统一意志”等同于共享所有秘密。

### 邮件学习样本与可回退的个性化知识（方案）

完整样本治理 proposed。样本需有来源账号/邮件、来源修订、反馈主体、原判断、主人纠正、作用域、授权、有效期和撤销状态；预测与供应商标签只是弱标签，邮件正文和第三方指令不能成为主人确认。

学习记录、候选规则和活动规则集分层保存。分类升级回退只改变活动模型／规则修订和派生缓存，保留升级后主人新增、撤销与纠正的原始记录；旧规则回放必须重新应用当前撤销和权限，不能复活已经失效的黑名单或跨项目用途。训练／开发集与按时间隔离的留出集分别管理，邮件线程的近重复内容避免跨集泄漏；评估结果附样本出处与覆盖范围，不把预测给自己打分。

默认在账号内学习，推广到所有邮箱、项目或共同体需明确范围；对第三人的风险判断不是主人人格事实，也不自动写入人员册。常用规则／少量样例／本地参数足够首期，不为“不断学习”默认全量微调、保留所有正文或常驻训练进程。反馈、域名、地址及嵌入同样可能敏感，保护沿用[邮件数据层](#mail-management-data)；升级发布和恢复的完整规则只维护于[能力成长](evolution-release.md#mail-capability-growth)。

## 个人记忆与聊天视图的当前实现（dev.6 起）

0.2.0-dev.6 已将普通记忆管理和真实聊天装配接入新工程；本节维护基础管理语义。原证据见[迁移验收](delivery-validation.md#memory-development-evidence)，当前检索与引用失效增量见[记忆检索 1.0.0](#memory-retrieval-runtime)。完整长期学习、Wiki 与共同体仍为目标。

| 环节 | 当前实现 | 明确限制 |
|---|---|---|
| 来源 | 聊天中点“整理为候选记忆”，只取这条本人消息，并保留来源 ID 与摘要 | 不从助手回答推断主人事实，不自动提取全部聊天；超 4,000 字需先缩小片段 |
| 候选 | 待核对 → 主人编辑内容、类别、用途与模型接入方 → 接受；或不保留 | 候选不进入聊天上下文；同一来源的重复点击不重复创建，已撤回来源不自动复活 |
| 事实 | 沿用核心 Facts 权威，附加 memory_usage 使用策略；revision 比较更新 | 不复制一份人格全文，旧 CLI 事实未设置用途时只本地保存 |
| 分域 | personal 的私人资料只用于私人交流；project-ID 只用于所属项目；明确选择的通用交流偏好可跨项目 | 不进行项目联合查询、家庭成员共享或 NPC 现实混用；“知识”分类暂为普通事实笔记，不代表 Wiki 已运行 |
| 出站 | 逐条勾选允许的模型接入方；每次主备切换重新建立视图 | 没有选接入方的条目不会进入模型请求；项目打开不等于自动读取资料 |
| 有界装配 | 最多 12 条、5,000 UTF-8 字节；当前按问题排序后装配，见[检索增量](#memory-retrieval-runtime) | 数量是单轮预算，不是数据库容量；来源模型提取见连续性实现，不默认整理全部聊天 |
| 纠正与暂停 | 单项 CAS 更新后提升记忆修订；当前按实际引用失效 | 新回执保留传递依赖；旧回执兼容处理与限制见[检索增量](#memory-retrieval-runtime)；原聊天仍可查看 |
| 遗忘 | 清空事实正文、来源与使用策略，清空关联候选正文，保留最少标识/标题/修订墓碑 | 不删除原聊天、用户导出、供应商已收到的请求或外部备份；重新手工填写同标题可作为新的明确陈述 |
| 会话接续 | 仅复用目的地、范围、开关和实际依赖仍兼容的历史；请求记录保存引用与修订 | 换供应商、相关记忆失效或关闭记忆会缩小历史；这不限制本轮用户自己明确输入的内容 |
| 在途变化 | 实际依赖的条目更改、撤回或到期时拒绝旧回复；无关修改可以继续 | 已发送远端内容/费用无法撤销，不自动重发 |

普通记忆保存在本工程的 SQLite 中，**不是加密私密资料库**。DPAPI 模型凭据仍在独立配置中；不将密码、邮箱令牌等交给此普通记忆界面。当前身份范围是本机 OS 账号下的 owner.local，不宣称已验证面前的人是主人。可选家庭身份与独立私密库见[家庭私密空间](#family-private-runtime)；没有启用时仍按本机操作者处理，跨设备撤回仍待实现。

界面提供标题/内容搜索、暂停/恢复、有效期、纠正、候选核对和当前范围 JSON 导出。导出是明文，且只包含此范围当前已核对内容；不是可绕过许可的自动同步。前台显示实际使用条数，轮次详情包含引用，不将整段个人资料重复写入审计日志。

## 目标规划的分域背景与交付经验（dev.10）

**implemented：0.2.0-dev.10。** `host/goal_context.py` 把既有有效记忆视图接到目标规划和缺口规格，不引入向量库、外部记忆服务或后台抽取模型。不是复制一份独立的主人画像。

1. 目标绑定个人或实际项目域、使用记忆开关、事实 ID/修订和所选模型目的地。多个规划路线只装配各路线都允许使用的事实交集，沿用最多 12 条、5,000 字节的边界。检索 1.0.0 起按目标与输入做关键词召回，校验依赖不再依赖它是否仍排在前 12 条。
2. 个人私有知识不自动进入项目；项目只继承可共享交流风格。项目撤销、会话归档/移除、事实纠正/遗忘/暂停/过期或目的地不匹配，都会使依赖它的待执行目标等待核对。
3. 规划前后、准入、每个工具动作前及研发检查点再次核对事实修订。换用 Codex 生成候选时，背景条目也必须允许 `codex-cli` 目的地；不会把更换供应商当作原授权的延伸。
4. 同一会话问后续进度，可引用关联目标的真实完成输出；换供应商或背景失效时不再装配这份旧目标背景和结果。历史回执仍可在本机查看。已发送的远端请求无法撤销。
5. 发布的新能力实际完成原目标后，生成**待核对经验候选**；普通目标也可手动整理。它来自成功任务、动作和版本回执，不把 AI 自述直接当事实，也不把工作成果猜成主人的性格/偏好。
6. 候选可改写、接受或忽略；接受时再次校验源域与证据摘要，不允许把项目候选改写成个人域。撤回已接受经验后，同源候选保持撤回状态，不因再次点击而复活。

成功判定和权限不会交给记忆模型。当前结果候选使用确定性的任务与能力摘要，不自动调用第二个大模型；它可能仍需人工提炼才能成为高价值经验。当前目标快照保留已用背景及修订以供审阅；遗忘后停止后续使用，**尚未实现所有历史目标/模型账本/导出中派生正文的物理清除**。原聊天与原任务也是独立资料，不能把禁止后续使用说成已彻底擦除。全量派生数据清理仍按[记忆生命周期](#memory-data)继续实现。

项目可以使用已发布个人通用纯文本工具，但当前阻止项目目标通过成长通路将项目背景生成个人共享代码包；待项目包的发布/检索/复用全链分域完成后再开放。此边界避免只隔离记忆表、却把项目内容固化到共享工具中。

## 按问题召回与引用依赖（memory-retrieval-1.0.0）

**implemented，2026-10-23；局部 verified 范围见[测试证据](delivery-validation.md#memory-retrieval-evidence)。** 根发布号仍为 v0.1.0；这是组件版本。本增量处理已经核对的事实记忆，不把文档入库、全文历史搜索或知识编纂标为已完成。

读链是：当前个人/项目及目的地过滤 → 查询词项排名 → 可用时本地语义补充 → 融合/字节预算 → 对当前修订再检查 → 聊天或任务背景。SQLite 仍是事实权威；没有引入额外服务、数据库或依赖。模块内 `retrieval.py` 负责纯排序，宿主组装边界，本地模型管理器提供可替换的编码端口。

- 词项路线使用 Unicode 规范化、非汉字词与汉字双字切分、BM25 形式的排名及完整标题优先；代码/数字与汉字相邻时分开识别。没有查询的旧预览仍给出有界背景。显式个人资料、偏好、约定可作为基础背景；知识笔记需要命中，排序结果不是事实核验。
- 只有已经启动且设为默认的本地编码器参与；不自动下载或启动。短查询与短事实按各自 query/passage 配方编码，当前最多 64 条候选、每条标题与正文合计 ≤160 字符。长资料保留完整关键词检索，不悄悄截断后声称完整语义召回。
- E5 的余弦值不是置信度；当前候选规则为至少 0.78、距最高值不超过 0.025、最多 4 个语义候选，与词项排名融合。它是开发基线，未通过独立领域留出集；换模型需重验，不能直接继承阈值效果。
- 前台最多等待语义通道约 350 ms；忙、未启动、长输入或超时退回关键词并记录原因。后台编码另有 2 秒检查期限；传输异常后丢弃 Worker，防止迟到输出串到下一次请求。编码不占用全局记忆锁或 SQLite 写事务。目标创建处于短写事务，因此使用同一词项排序，不在事务内等候 E5。
- （1.0.0 当时）向量只用于本次计算，不保存持久向量索引、原文缓存或新的知识副本。编码失败不会改变事实库或选中模型；重新启动通过原模型管理入口。当前每次编码短候选，不宣称万级资料的检索性能已达标。

新轮次回执保存本轮选中事实，以及从保留的历史和关联任务结果继承的 ID/修订依赖。后续请求重新核对这些引用的用途、范围、接入方、修订与有效期；无关事实更改不再仅因全局 epoch 变化取消回答。更换问题不要求新旧选中列表完全相同。目标从对话创建时继承对话依赖，执行前仍复核；关闭记忆时不装配依赖记忆的旧任务结果。

旧轮次没有传递依赖字段时保留原 epoch 检查，不能推断未知引用安全。数据库没有破坏性迁移；恢复旧代码可能恢复保守的整段失效行为，不能撤销当前事实修订或遗忘状态。本增量仅完成引用使用失效，历史任务/账本/导出的派生正文清理仍待实现。

**使用入口：**工作台顶栏“个人记忆与知识” → “按问题检索 · v1.0.0”。选择个人/项目、回答接入方并输入问题，可查看本次会使用的条目、修订、词项/混合路线与降级原因；预览不调用云端模型。聊天轮次显示检索方式，详情保留实际依赖。接口为 `POST /api/memory` 的 `recall` 动作，字段为 `scope/provider/enabled/query`，沿用同源和 nonce 检查。

## 本地资料库、原件与片段索引（knowledge-library-1.2.0）

**implemented，2026-10-23；限定 verified 范围见[本轮验收](delivery-validation.md#knowledge-library-evidence)。** 根发布仍为 v0.1.0。本版把本机文本原件接入现有聊天/目标背景，不代表通用知识编纂、自动学习或完整 K2 已完成。

工作台顶栏“个人记忆与知识” → **本地资料库 · v1.2.0**，支持选择 UTF-8 TXT/Markdown、粘贴原文、查看/修改、暂停/恢复引用、删除入库副本、导出单份原文，以及后台重建/取消/状态。1.1.0 增加资料包导出/恢复和显式派生清理，规则见[本节后续](#knowledge-transfer-runtime)。每份最多 80,000 UTF-8 字节，初版最多 200 份有效原件；这是实现边界，完整大规模验收没有取消。文件内容由用户明确选择后上传至本机服务；不扫描磁盘、不读取正文内的文件路径或网址，不执行 Markdown/HTML/脚本。

| 层 | 当前实现与唯一职责 |
|---|---|
| 原件 | 同一 core.sqlite3 中 knowledge_sources 保存当前完整文本、稳定 ID、范围、修订、状态与字节数；修改替换当前版本，尚不保存可查询的历史原文版本链 |
| 片段 | knowledge_chunks 按最多 560 字符分片、优先换行；保留源修订、字符起止位置、行号及片段 ID。长句切分处跨片段关联尚未补齐 |
| 许可 | knowledge_destinations 明确各来源允许的模型接入方；个人/项目严格分域，个人原件不因通用表达偏好而共享给项目 |
| 检索 | 可重建 FTS5 使用与事实检索一致的 Unicode/汉字双字词项；在范围和接入方过滤后取最多 64 片段，再与事实合并进入既有 12 条/5,000 字节背景预算 |
| 引用 | 正文保留片段定位；失效依赖以源 ID/修订记录，避免每次装配全库片段 ID。聊天历史、在途回答和目标检查复用现有依赖协议 |
| 更新记录 | knowledge_changes 只保存 ID/修订/动作/数量/时间，不保存旧正文；不把摘要、文件哈希或日志当成删除后继续保存隐私的借口 |

**资料不是核验结论。** `kind=source`、`trust=reference_unverified` 与主人核对的事实分开；界面明确“参考原文 · 未核验”，模型上下文提供出处并要求依据来源回答。字段和范围检查已由宿主执行；这些提示并不证明任意模型都会正确引用或抵抗任意提示注入。来源不通过自动事实核验或专业计算；1.2.0 的主人审阅晋升见[本地闭环](#knowledge-cycle-runtime)。

1.2.0 已加入[可续建的持久语义索引](#knowledge-cycle-runtime)，允许在本地嵌入模型启动后召回没有词项重合的获准原文；纯词项路线仍可独立运行。没有索引或索引丢失时扫描当前获准片段并显示路线；这是恢复路径，不能推定其大库性能等同 FTS。

**更新与清理：**校验和切片在写事务前准备；当前原文、片段、许可、索引更新和撤销代次原子提交。内容/许可改变会增修订，引用旧修订的后续使用失效。暂停退出有效检索；删除清空库内原文、标题和片段，并移除活动/影子 FTS 的对应内容，只留不透明墓碑和操作元数据。相同范围、标题和正文的重复导入返回已有 ID，不扩大许可；已删除 ID 不能更新复活，用户主动重新导入会建立新来源。

“删除入库副本”的范围仅为**本模块受管的入库副本及检索内容**。历史聊天回复和目标背景可以另行[预览与清理](#knowledge-transfer-runtime)，不会因删除来源就无提示抹掉对话。1.2.0 将显式派生清理扩展到终态任务与受管文件，范围见[本地闭环](#knowledge-cycle-runtime)。用户磁盘原文件、原始请求、导出和备份仍不在此范围；SQLite/WAL 的可恢复页也不能称为取证级擦除。完整清理继续遵循[生命周期规则](#memory-lifecycle-completion)。

**并行与修复：**core SQLite 启用 WAL、保持 synchronous=FULL。FTS 后台仅一条重建通道，每批最多 8 片段、短事务并让出 CPU；活动索引继续服务。初始快照完成后，按变更账本最多做 3 次增量追赶，清除构建期间删除的孤立行并核对片段覆盖；持续写入无法收敛、取消或构建失败时丢弃影子索引，保留当前索引。成功在同一事务切换索引指针并退役旧投影。关闭宿主时取消该重建。DB 主版本仍为 7；知识表初版为 knowledge_schema=1，当前兼容和迁移说明见下节。

实现位置为 adapters/storage/knowledge_schema.py、modules/context_knowledge/knowledge.py、host/knowledge.py 和 apps/workbench/knowledge.js；入口/字段只在[运行契约](contracts.md#knowledge-library-contract)维护。没有新增第三方包、常驻模型或外部数据库服务。

### 公开格式恢复与受管派生清理（1.1.0 起）

**implemented；验证范围见[1.1.0 证据](delivery-validation.md#knowledge-transfer-evidence)。** 当前是单机文本资料子集的迁移与清理，不是完整记忆库备份、加密保险箱或多节点同步协议。运行不需要网络或模型。

“导出此范围资料包”读取同一数据库快照，以 UTF-8 JSON 导出此范围当前来源、源 ID/修订及删除墓碑；不包含聊天、显式事实、密钥或 FTS。文件是明文，checksum 只检验传输损坏，不证明签发者可信。每包最多 200 份有效来源、10,000 个墓碑、40 MB 请求；超限明确拒绝，不截断。导出文件应与最新撤销记录一起保管，已有明文副本不会因本机删除而消失。

| 操作顺序 | 本机行为 | 必须保留的边界 |
|---|---|---|
| 选择资料包 → 预览 | 展示范围映射及每项新增、替换、删除、跳过、冲突 | 预览不写入；不同范围的同 ID 拒绝；不建立自动共享关系 |
| 核对 → 恢复 | 用范围、包摘要、资料水位核对预览；一次事务写入原件、片段、墓碑 | 本地更新后旧预览失效；任一冲突/容量不足则整包拒绝 |
| 已删 ID + 旧原文 | 跳过原文，即使包中声称更高修订 | 删除墓碑优先；不能通过恢复原文复活同 ID |
| 包中含删除记录 | 清除对应当前资料；已有墓碑保持删除 | 明确显示删除数量与 ID；这会影响此 ID 后续使用 |
| 本地已有相同正文/标题 | 保留本地记录及当前许可，不重复新增 | 不以包内较宽许可覆盖本地许可 |
| 本地内容不同 | 只有更高源修订可进入替换预览；相同修订分叉/较新本地内容拒绝 | 不是自动解决冲突或证明远端内容更真实 |
| 新建或替换成功 | 默认暂停、清空模型接入方许可；需要用户重新设置 | 没有恢复旧执行权限；索引可重建，暂用扫描降级 |

**全新机器的限制：**若只有旧备份而没有最新墓碑，新机器无法知道备份之后发生过删除。可先导入包含最新撤销记录的资料包，再导入旧包；本版测试覆盖此顺序。不能声称离线旧副本已自动收到撤销，也不能直接用旧 SQLite 全库替换当前撤销账本。

“清理失效记忆与资料”按当前范围每批扫描最多 200 个目标背景与 200 条聊天轮次，提供游标继续。依据已有源 ID/修订的传递依赖识别旧修订、暂停或删除来源；展示受影响会话/目标清单，核对后清理整条聊天回复、行动建议及整个目标背景快照。原始提问保留，回复显示清理占位说明；依赖 ID/修订和显式 redacted 标志保留，旧目标仍拒绝执行。无关来源更新不触发清理，进行中的回复暂缓，缺失来源证据的旧记录列为未处理，不能推测它们已经安全。

两个 SQLite 库不宣称跨库断电原子性：先在 core 事务中清理目标背景并记录 pending，再单独事务清理聊天投影，最后写 completed；错误为 partial。崩溃可能留下 pending。界面显示最近回执，重新从头预览可幂等处理剩余记录；旧失败回执保留为历史，不冒充已经成功。回执只保存不透明编号、范围、数量、状态、时间和错误代码，不保存被清理正文。读取和执行入口继续检查撤销，不能因正文为空而恢复权限。

1.1.0 的清理只覆盖来源依赖的聊天和背景；1.2.0 已扩展，当前完整范围与排除项以[下一节](#knowledge-cycle-runtime)为准。页面“本批完成”仅指本批受管字段；清理不是取证级擦除。

1.1.0 将 knowledge_schema 从 1 添加式升级到 **2**，新增 knowledge_cleanups 回执表；核心 user_version 保持 7。已经加载旧版 schema=1 校验器的进程不支持 2，部署须统一重载；回滚代码也须保留 schema=2 与撤销/清理标志兼容，不得回滚事实数据。实现分别为 modules/context_knowledge/transfer.py、host/knowledge_cleanup.py 和 apps/workbench/knowledge-transfer.js，未增加依赖包、模型或常驻后台任务。

### 本地形成、使用、撤回与恢复闭环（1.2.0）

**implemented；2026-10-24，限定 verified 范围见[本轮验收](delivery-validation.md#knowledge-cycle-evidence)。** 此处“闭环”指下表明确的单机文本链路；完整 V-MEM 与最终记忆体系仍按[缺口登记](#memory-final-gap-register)验收。运行不需要云端，不自动下载或常驻模型。

| 顺序 | 使用入口与运行行为 | 闭环保障 |
|---|---|---|
| 导入与定位 | 本地资料库导入 TXT/Markdown，选择范围和接入方 | 原件是参考；保留修订、位置和权限 |
| 编纂 | 资料卡片“编纂知识候选” → “知识候选 / 来源审阅” | 确定性 extractive-v1 提出原文片段，每次只编纂一份；最多 200 条待审阅；无 LLM 调用，不执行原文命令 |
| 收入知识 | 核对名称、正文，再点“核对并收入记忆” | 同一事务核对候选/原件修订与许可；来源范围不可改变，接入方只能缩小；同名事实 CAS 冲突不覆盖 |
| 检索使用 | 已核对事实与原文共同进入既有查询、聊天、任务视图 | 引用含出处；owner_reviewed_claim 表示主人核对，不表示科学事实认证；未审阅候选不注入上下文 |
| 构建语义索引 | 设置中先启动并设定本地 E5 → 资料库“构建 / 续建语义索引” | 同一受限编码进程；后台每批 4 个窗口，每个不超过 400 字符且 448 UTF-8 字节，60 字符重叠；编码附最多 48 字节资料标题；不截掉长文尾部 |
| 修订/暂停/删除来源 | 修改来源卡片 | 原件、许可、FTS、全部空间该源向量与派生知识撤回同事务；清空撤回候选引文和仍同源事实正文，旧引用拒绝继续使用 |
| 清理历史派生物 | “清理失效记忆与资料” → 核对具体清单 → 清理本批正文 | 事实与资料均参与依赖失效；聊天正文/行动建议、目标背景、已结束任务派生计划/动作参数/结果、相关规划模型结果纳入清理；原始请求保留 |
| 文件与故障恢复 | 清理回执 → “重试未完成的派生文件清理” | 对受管回复、任务产物及会话副本逐个核对路径/归属/摘要；先记持久队列与同步墓碑；缺失幂等、修改过保留并标记未完成；清空后的任务不能再次产生同一交付 |
| 导出与重建 | 资料包预览/恢复 → 重新核对许可 → 续建索引/重新审阅 | 继续执行墓碑优先；资料包不备份已核对事实/候选、原始聊天或任务；不假装是整库备份 |

**来源关联不会因单纯改策略而消失。** 仅修改暂停、到期、接入方时保留来源依赖，也不能扩大到来源不允许的接入方。若主人编辑事实正文并保存为独立核对陈述，界面事先说明其不再随原资料自动撤回；自动编纂器没有此权限。

**向量是可修复投影。** 使用 SQLite BLOB 保存 float32 little-endian 与 SHA-256 损坏检查，来源才是权威。空间身份绑定固定模型/文件/编码配方、维度与窗口格式；相同维度不代表兼容空间。先按现行范围、接入方、状态和源修订过滤，再在本机评分；与词项命中的重叠片段合并。窗口跨原片段边界时保留完整匹配窗口及相邻原文，引用仍使用准确字符偏移；相似度只决定候选，不证明答案存在。新配方使用新空间身份，旧配方在续建完成前走词项降级，避免套用新分数校准。查询仅编码当前问题，前台编码等待最多 250 ms、整条语义路线预算 350 ms；未启动、忙碌、超时、损坏、空间改变则显示降级并继续词项检索，不排队阻塞云端聊天。

构建每批提交检查点；中断/取消后已有批次可续建。候选完整且来源水位未变才切换；模型空间不同保留旧活动空间至切换成功，期间不混查不同空间；同空间增量在修订过滤下可使用已完成部分。新建候选会退役多余失败候选，最多保留活动空间与本次候选；切换后退役旧投影。构建期间按每份原件当前修订提交，迟到的旧编码丢弃；初始扫描后最多 3 次追赶，复用有效批次，核对当前覆盖后切换。持续变化仍返回 knowledge_changed，保留旧空间并可续建；尚非无人值守增量调度。损坏行在续建时重算。取消编码会释放异常/中断的工作进程，必要时由模型管理器重新启动。

**清理的完成边界。** 目标正在规划、任务未终止、动作回执 UNKNOWN/DISPATCHING 或关联研发未回归时暂缓，不修改正在执行的账本；预览显示 busy_goals/busy_turns。终态任务保留动作 ID、能力、摘要、耗费和原执行状态，正文换成 redacted 标记，取消锁存阻止重新执行；保留用户原始目标/输入，清理修订历史中的派生 proposal。派生代码/发布包、来源不明的旧内容、用户改过的文件、用户原始文件、导出/备份、外部供应商与 SQLite/WAL 可恢复页均不宣称已清理。不会扫描用户磁盘猜测删除外部副本。

core、聊天库、会话库与文件系统仍是分步提交：持久 pending → 正文提交 → 文件逐项处理 → completed/partial。部分失败不回填旧正文；重新预览处理剩余正文、重试文件按钮处理持久队列。completed 只针对该批明确范围，历史 partial 回执保留。自动删除所有历史、自主改写权威文档、多源矛盾推理、长期主动学习不由这个入口启动。

兼容数据版本为 **knowledge_schema=4**（3 增加向量/Claims，4 增加文件撤回队列），核心 user_version 仍为 7。旧进程不兼容新 schema，发布须统一重载；代码回退须保留 4 的读取/撤销兼容，不能把旧数据库盖回。实现分工：领域模块 claims.py/vectors.py 管理候选与投影；host/knowledge_vectors.py 组合模型；knowledge_cleanup.py/knowledge_outputs.py 组合跨库清理；会话模块负责文件归属与同步墓碑。没有新增第三方依赖或向量数据库服务。

| 本地资料库 → 模型提取候选 / 知识提取任务 | 一条后台通道，显式选择资料已获准的模型；最多 24 条原文引用候选；支持取消、用量、失败和中断状态 | 不是自动事实核验；拒绝不存在、歧义、重复引用和越权目的地。原文变化/撤权使提交失败；未知付费结果不自动重发；模型草稿不落入事实或重复正文日志 |
| 分支按问题检索 | 本分支显式事实覆盖同标题的父快照事实；历史原文携原修订和行号 | 父范围的当前暂停、外发许可、遗忘仍优先；父原件遗忘后快照不可复活；历史原文可能与分支覆盖值不同，须区分旧依据与当前决定 |
| 迁移 / 恢复记忆 → 单范围包 | 迁移本范围事实/墓碑、候选及状态、知识审阅、历史与可获得的原始用户陈述/任务元数据 | 明文公开 JSON；无密钥、执行授权、模型文件、整份聊天、活动任务或外部文件；来源校验摘要不证明作者身份或执行真实性 |
| 迁移 / 恢复记忆 → 父范围与全部分支包 | 同一事务恢复父范围、各分支/世界/任务域、引用快照及资料分支依赖；显式映射到所选父项目 | 新域默认归档，新建/替换的事实和资料暂停且无模型目的地许可；单范围包不包含父原件；含受依赖约束的分支稿时要求整组导出，防止丢失撤回关系 |

原文分支保存明确的父来源 ID 和起点修订；分支稿覆盖继承原文，当前父来源暂停或收回目的地后，词项、持久向量、提取和已晋升知识均不能借分支绕过。父原文遗忘与分支稿/切片/历史/派生知识的撤回在同一事务中提交，归档分支同样受约束。主项目清理预览也查找这些分支派生的聊天和任务。合并不是语义真实性证明；知识主张到权威章节的自动维护仍在缺口表中。

迁移先预览，再按预览摘要和当前状态提交。相同对象保留本地策略，内容分叉或跨域 ID 冲突阻止整包写入；本地删除/撤回记录优先于旧包，即使旧包声称更高修订也不能复活。资料来源改变仍会撤回从它形成的知识，导入不解除这条依赖。复原的候选需人工核对；导入的任务回执不是本机执行成功记录，不能激活能力。

恢复使用 WAL 事务，读者看旧的完整快照，提交后才看新状态；检索与发送前重验使用一致读快照。恢复不长期占有前台记忆互斥锁。数据库写入仍串行，不能承诺任意 40 MB 恢复与所有写操作毫无争用。新格式严格拒绝重复 JSON 字段、无效数值、损坏摘要、异常类型和容量溢出。缺少原件的引用不会编造重建。

本节尚未实现：完整双时态问答、候选提取的独立质量达标与自动矛盾裁决、知识权威章节的语义维护、家庭身份与全链路加密、设备复制协议、PDF/OCR/语音原件解析、长期独立质量达标。显式事实合并、获准联合查询和待审阅模型提取已接入，不能用这些子集代替完整验收。它们继续保留在下表及原 V-MEM 验收，Mac 实机验收由主人明确留待后续，不将其余硬件/长期验证改写为已通过。

### 记录职责与可追溯的总体认知

总体认知是按需要生成的视图，不建立可随意覆盖原件的巨型“主人总结”。沿用[数据分层](#memory-data-1)，同一来源只保留一份受管原件，派生内容记录依赖：

| 类型 | 内容与时效 | 权威和读取方式 |
|---|---|---|
| 工作记忆 | 本轮指代、临时约束、计划检查点、未决问题 | 会话/任务范围；快照可持久化以便恢复，完成后按策略释放 |
| 原始情景 | 原消息、说话者、时间、文档版本、真实工具回执 | 原件证明“当时说了/发生了什么”，不自动证明内容真实；保留精确片段定位 |
| 事实与条件偏好 | 谁、什么属性、何时有效、适用场景、来源、当前状态 | SQLite 管理修订、来源和撤回；事实有效时间与系统得知时间分开 |
| 共同经历 | 已获准保留的重要交流、事情变化、未结话题 | 时间线＋原件引用；允许按日期/人物查回，不仅靠向量相似度 |
| 主题知识 | 专业概念、工程说明、方法与适用边界 | 逐项主张绑定原件、版本、章节和反例，编纂内容是可重建视图 |
| 程序性经验 | 有效方法、失败条件、已测工具使用示例 | 执行回执与环境版本可追溯；转成可执行 Skill 仍走构建和发布 |
| 表达人格 | 称呼、语气、角色和交流偏好 | 版本化配置；不修改现实事实，不授予权限 |
| 自身知识 | 安装、可用、已验证、当前健康和资源约束 | 模块注册/探针/验收提供证据，见[自身模型](self-model.md#self-model-context-selection) |

扩展记录至少表达：稳定 ID、来源 ID/修订/片段、主体、发言角色、领域/项目/分支/任务/世界、有效时间区间、登记时间、可信状态、用途/受众/模型目的地、修订依赖、撤销状态和保留策略。事实置信度、来源可信度、敏感等级与行动权限是不同字段，不合成一个分数决定一切。来源签名/摘要只证明身份或完整性，不能证明陈述真实。正式传输字段继续归[公共契约](contracts.md#memory-view-contract)。

“主人说自己喜欢咖啡”可成为自述偏好；“同事说主人喜欢咖啡”先是第三方陈述；“助手推测主人缺觉”是短期假设；“NPC 说自己住在火星”留在模拟世界。不能因反复引用同一原句而增加独立证据数。缺省身份/范围不明确的记录进入待核对；不根据文本内自称“我是主人”绑定主体。

<a id="memory-branch-context"></a>
### 项目、分支和任务隔离与总体视图

项目以稳定 project_id 为根，工作区实例、分支名、提交/快照和任务各有身份。分支名可重用，不能作为唯一版本键；未提交改动用工作区快照摘要，不冒充已提交代码。非 Git 项目使用内容快照，同样可表达版本，不强制用户初始化 Git。

读取链为“本轮明确资料 → 当前任务增量 → 当前分支覆盖 → 可见的项目基线 → 明确可共享的通用偏好”。这是相关性与适用顺序；权限始终求有效允许范围。分支固定父快照，父项目变化不会悄悄改写历史实验。否定和撤销也必须在覆盖层表达，不能因底层旧事实仍在就重新召回。

例如项目 A 的 main 使用接口 v2，feature 分支试验 v3：询问 main 时不引用 feature 的未发布结论；询问“两分支差异”才临时创建联合视图，分别带来源。合并代码后，分支知识不会自动全部晋升：检查对应文件、提交与测试回执，保留冲突，再把仍适用主张合入目标分支。放弃分支只处理其自有草稿/索引，原文、共享证据和保留中的回执按引用与保留策略处理。

Agent 只得到任务专属上下文和必要引用，不各复制一份主人的长期画像。协作使用结构化发现/结果/缺口，不把所有内部推理和工具输出广播给全部 Agent。Agent 产生的记忆带作者与任务，不能直接覆盖主人事实；成功经验通过原[晋升规则](#memory-sharing-bridges)。

总体视图用“个人目标与偏好摘要＋获准项目目录＋未结事项引用＋共同经历目录＋自身能力目录”组织。目录标题和摘要本身也可能泄密，必须同源过滤。跨域只生成当次允许的视图，不另建无范围的超级向量库。家庭共享规则见[私密域](security-sovereignty.md#memory-private-storage)。

<a id="memory-context-retrieval"></a>
### 分层检索、速度与上下文预算

复用[写入与查询](#section-63a49a4a6d48)的过滤、融合和复核协议，新增三级读取：目录/短摘要判断去哪里；相关主张和邻近原话补足含义；需要证据时读取原件章节。参考 OpenViking 与 VikingRAG 的结构化检索思路 [S305](references.md#s305)、[S300](references.md#s300)，其上游表现不是本项目性能保证。

1. **请求快照。** 绑定身份、范围、分支、当前时间、用途与实际目的地；解析“上次那个”等指代时优先用近期上下文和已有引用。
2. **需要才查。** 寒暄、直接翻译等自足输入可绕过长期检索；明确问回忆、偏好、专业资料、未结工作时走对应资料源。不能用一次低置信度分类永久压掉记忆，低置信度走小预算补查。
3. **确定性入口。** 明确 ID、日期、人名、版本号先查结构字段；短中文词、代码标识与错误码使用词项/别名检索。日期范围和现实/模拟域先过滤。
4. **混合召回。** 需要改写/跨语言召回时，查询 embedding 与词项检索可并行，共享一个编码器；按文档/事实 ID 融合，保留近邻原文、否定、数值单位和适用条件。重复摘要不挤占候选预算。
5. **有限深入。** 证据不足时再读一层相关章节或关系；跨多跳、最新专业资料可升级检索路线。限制轮次、时间、token 和费用，超时返回已有可靠结果及具体缺口。
6. **封装与验证。** 背景偏好、当前问题、证据和任务状态各自有预算，保留回答空间；最终只引用实际读取且仍有效的来源。来源内容与执行指令在协议中区分，不能仅靠提示词隔离。

历史窗口按引用依赖进行失效，修正当前全局 memory_epoch 造成的无关会话失效；精细依赖未完成前保留保守实现，不能删除复核换速度。缓存键含主体、域/分支快照、用途/目的地、权限代次、源修订、查询和检索器版本；不能仅用问题文本作缓存键。embedding 缓存同样继承来源边界，切模型重建索引代次，不混查不同维度/模型空间。

[资源目标与计量](delivery-validation.md#memory-resource-envelope)统一维护延迟、内存和并发；“实时”应报告首字/首音频、检索附加延迟和任务入队延迟，不能只测数据库 SQL。无 GPU、内存不足或编码器冷启动时先用确定性/词项路线，后台慢任务排队，显示召回降级；不能把没查到误写成“从未发生”。

<a id="memory-knowledge-promotion"></a>
### 从经历到专业知识，以及主动学习

沿用[项目知识编纂](#project-knowledge-compilation)和[学习流水线](#continuous-learning-2)。晋升路径是：原件片段 → 带来源主张 → 核对适用条件/矛盾 → 有版本的主题知识 → 在实际任务验证的方法 → 独立发布的 Skill。一次成功不能证明普遍有效，反思、总结和多 Agent 共识不能自动提升证据等级。

主题知识采用可读章节树：领域 → 概念/问题 → 主张与方法 → 来源/实验。一条知识包含“结论、适用条件、证据、反例、日期/版本、未解决问题”；需要时再附公式、单位、工具环境和复现实验。PDF 页码、代码提交/函数、网页获取时间和数据集修订是不同来源定位。截图/OCR、语音转写与表格解析记录置信和原件引用，低质量解析不自动晋升。

专业领域走“原始/官方资料优先 → 当前适用版本 → 计算/仿真/测试复核 → 可追溯交付”。例如机械参数使用单位检查与实际仿真，软件 API 绑定库版本，科学结论区分论文结果、推断和已复现实验；金融、医疗等内容有时效和适用对象要求，不能以过往记忆替代当前专业依据。检索增强提高查证能力，不让助手自动成为所有专业领域的权威。

主动学习以已授权目标、重复失败、主人纠正、资料过期或新版本通知为触发。学习项记录目标、预期收益、所缺证据、来源、费用上限、完成/放弃条件及复查时间；无相关目标的互联网漫游不进入默认后台。相同缺口去重排队；用户活跃时降低后台负载，网络/资源恢复后从检查点继续。一次性观察进入短期缓冲，稳定偏好/重复任务才申请长期保留；不得在未授权资料上训练。

首次只学可编辑知识、案例和检索策略；微调/蒸馏是后续独立实验，必须说明训练材料许可、污染、删除困难和回退成本。私人记忆默认不进入权重，因为逐项遗忘不能靠删除数据库实现。采样回查原件，避免摘要再摘要反复丢失限定条件；长期低使用不等于低价值，重要共同经历按主人保留规则保存。

### 纠错、遗忘、整理与防止旧内容复活

![记忆形成、纠错与迁移流程](diagrams/memory-context-lifecycle.png)

[SVG 放大](diagrams/memory-context-lifecycle.svg) · [图源](diagrams/memory-context-lifecycle.mmd)。

[遗忘与备份](#memory-data-5)是总体规则，本节定义待实现的闭环。每个派生对象保存源 ID/修订依赖；先让撤回在读取和执行入口生效，再异步处理正文、索引与缓存。区分“停止长期使用”“删除原聊天”“删除共享副本”“按保留期清理备份”，界面不能用一个“已删除”隐藏未完成范围。

| 操作 | 必须处理的对象 | 完成证据 |
|---|---|---|
| 纠正 | 事实新修订、受影响画像/知识/索引/上下文/待执行计划 | 新查询用新值；历史问题可在允许保留时读旧时点，不悄悄覆盖历史 |
| 遗忘 | 事实使用、同源候选、派生文本、检索缓存、向量、任务背景和分享队列 | 立即逻辑失效；后续逐项清理回执；不能撤回已经发送远端的文本 |
| 原件删除 | 原文/附件、引用片段、派生主张和知识 | 依赖被撤回或明确重验；不能只删文件却保留摘要复述秘密 |
| 垃圾整理 | 重复、过期临时片段、无引用中间物、失败缓存 | 预览/保留规则、引用检查和宽限期；不扫目录猜测删除用户原件 |
| 错误来源处理 | 同源或同生成版本的候选与派生知识 | 先隔离，再确定影响面；相关性不等于全部错误，不级联删除独立有效证据 |
| 备份恢复/代码回退 | 当前撤销清单、权限与兼容数据 | 恢复在隔离副本先应用最新撤销，再开放查询；离线旧设备按共同体规则重入 |

墓碑只留完成去重/撤回必需的不透明 ID、修订和处理状态；不能把敏感标题或原文哈希当成天然无隐私。跨节点去重需要按域设计不透明标识，低熵内容的裸哈希可被猜测。备份有期限和撤销清单；逐域加密密钥销毁仅在不存在其他密钥/明文副本时减少可恢复范围，不能承诺任意 SSD、外部导出和离线设备已彻底擦除。

“抗降智”用固定留出任务衡量：检索质量、回答证据、纠正遵循、专业任务成功率和资源成本同时比较。模型/提示/切片/embedding/索引分别版本化，只改变一个变量做归因；自动清理与知识重组先在影子副本验证，再渐进切换。原始证据可追溯与可删除必须兼顾，不能以“不可变日志”为理由永久保留被撤销正文。

<a id="task-experience-learning"></a>
## 任务、返工和纠正如何成为可复用经验（proposed）

复用[现有经验候选](#goal-memory-runtime)与[知识晋升](#memory-knowledge-promotion)，从“成功后可手动整理”扩展为按授权自动形成、核对与使用经验；不另建人格库或第二份工作日志。当前尚未实现所有任务的全自动闭环。

每个任务终态或有价值修订生成有界 TaskEpisode：目标/范围、实际方法与版本、结果与证据、发现的问题、主人具体纠正、修改前后差异、哪些条件下可复用、哪些条件下不能用。失败、拒绝、取消和未知状态都可记录，但不得把没有证据的故障猜测固化成规则；纯粹取消不自动归咎于系统。

这里的最小经历记录不等于每次都调用模型写总结；已有回执可以直接关联。只有新的纠正、关键差异或方法证据才进入[经验归纳](#experience-consolidation)，避免为完成记录而制造重复知识。

| 层次 | 用途 | 晋升条件 |
|---|---|---|
| 本次修订 | 立刻修正当前成果和剩余计划 | 可信纠正或可核对新证据，绑定原任务和作用域 |
| 情境经验 | 下次同类任务避免相同错误 | 有来源、适用条件、反例及评价引用 |
| 稳定方法／Skill 候选 | 复用步骤、检查方法或工具策略 | 多个独立实例或足够强的可重复验证，按领域量表决定；不是机械达到若干次就通过 |
| 已采用能力 | 默认供后续任务选择 | 按[成长与发布通路](evolution-release.md#harness-learning-loop)验证兼容、净收益和回退 |

前一次交付被要求“结论写前面”，先作为本任务纠正；只有确为持续表达偏好才写入对应个人偏好域。项目技术修复留在项目经验，抽象成通用方法之前剥离私有事实并重新验证。主人明确提供的事实不必等反复出现才能纠正；把一次性修改推广为所有任务的规则才需要额外依据。

下一次规划先按任务类型、环境/能力版本、数据域和失败模式检索小量相关经验，说明采用/忽略依据；执行中核对来源修订，完成后更新“被检索、被采用、有效/无效、失效原因”。新纠正通过 supersedes 链替代适用规则，并加入反例，避免系统反复从旧摘要学回错误。

低风险、可核查且符合保留策略的经验可自动接受；敏感信息、证据冲突和跨域推广先保持候选，不把“每个候选都必须人工点接受”作为最终产品机制。保留原始事实的必要引用、方法和失败教训，不永久保存全部录音、聊天或中间上下文。纠正、撤销和遗忘按既有生命周期传播；方法回退不恢复已经遗忘的私人事实或过期权限。

“越来越好”按[持续改进验收](delivery-validation.md#task-score-learning-validation)测量。记忆变多只意味着存储增长，只有后续相似任务少犯错、少返工、独立完成更多，才说明经验产生收益。

总结的具体形成与整理见[经验归纳](#experience-consolidation)，下次怎样选择见[条件化复用](#conditional-experience-routing)，怎样防止越用越僵化见[反例与探索](#knowledge-anti-dogmatism)；知识贡献和完整成本必须通过[分组对照](delivery-validation.md#knowledge-value-ablation)确认。

<a id="knowledge-compounding"></a>
## 怎样让知识库带来持续收益，而不是持续堆积（proposed）

本节细化[任务经验](#task-experience-learning)、[分层检索](#memory-context-retrieval)和[知识晋升](#memory-knowledge-promotion)。目标是让同类工作减少无效探索，同时保留重新判断的能力；不是把一次成功固化成永久答案。当前已有原件、索引、引用候选和撤回基础，以下模式归纳、适用性路由及收益闭环尚未完整实现。

<a id="knowledge-value-layers"></a>
### 知识库在哪些位置发挥作用

| 层次 | 保存什么 | 在任务中的作用 | 不能代替什么 |
|---|---|---|---|
| 原件与可核对事实 | 带来源、版本、时间和作用域的资料/主张 | 减少重复搜索，给判断提供当前证据 | 来源可信性、最新外部事实和权限判断 |
| 任务经历 | 目标、约束、方法、结果、纠正及实际回执引用 | 回看为什么成功或失败，支持诊断与归纳 | 一条经历不自动成为通用方法 |
| 条件化经验模式 | 多案例共同结构、适用条件、关键差异、反例、停止条件 | 在近似问题中缩短规划和检查路径 | 不能仅凭语义相似直接执行 |
| 可执行技能与检查器 | 已验证的步骤、模板、计算/解析程序及测试 | 把重复推理变成可靠的确定性操作 | 仍需能力准入、当前参数、权限和真实回执 |
| 元经验 | 哪类检索、模型、协作和检查在什么条件下有用 | 改进“怎样选方法”和何时重新查证 | 不可修改自己的根权限或独占评估标准 |

知识库不是与模型并列的一颗万能大脑。它影响“得到什么证据、从哪里开始、避免什么错误、怎样验证”，最终效果还依赖模型理解、工具能力、执行环境和评价器。库中信息再多，检索不到、不被采用、采用不当或缺工具，都可能没有收益。其贡献必须用[分组对照](delivery-validation.md#knowledge-value-ablation)测量，不能预先声称占智能的某个百分比。

以上是现有记录的职责分层，不要求五套数据库或五个常驻模型。精灵、工作台和 Bot 共用同一领域服务、权限及失效关系，遵守[统一系统准则](architecture.md#unified-system-principle)。

<a id="experience-consolidation"></a>
### 怎样总结同类经验：保存“为何有效”，而不是复制答案

总结分为三次不同动作：

1. **任务结束形成最小差异。** 确定性写入目标/产物/动作/版本及评价引用，只提取新增事实、纠正、失败或方法变化。没有新信息就不追加同义总结；不要求每个闲聊和普通成功任务都调用大模型反思。
2. **相关经历达到整理价值时归纳。** 按问题结构、失败机制、能力/环境版本和关键约束聚类，核对原始证据，比较成功与失败。相同目标的反复重试不是多个独立成功；不同表述不是不同证据来源。
3. **把归纳变成可检验候选。** 输出适用条件、必要检查、反例和预期收益，先在后续保留任务试用。通过的部分进入默认检索；尚未验证的归纳保持候选。可执行脚本按原发布通路晋升，知识总结不直接取得执行权。

一个经验模式至少携带以下语义；实现时关联既有 TaskEpisode、来源和能力版本，不再复制任务事实：

| 内容 | 用途 |
|---|---|
| 问题类型与目标 | 说明解决什么问题，防止只按关键词分类 |
| 必需条件／已知不适用条件 | 区分能够快用、需要复核和应该拒用的场景；关键条件缺失视为未知 |
| 原理与可替换步骤 | 把“为什么有效”与具体按钮/文件名/供应商分开 |
| 当前必须重查的变量 | 如数据版本、订单状态、人物身份、单位、工具接口与实际授权 |
| 正例、反例及来源谱系 | 正例证明适用范围，近似反例限制泛化；派生摘要指回原件 |
| 证据等级与未解决问题 | 区分观察、推断、可重复验证；模型自信不是成功概率 |
| 版本、依赖、作用域和生命周期 | 支持修订、撤销、暂停、替换和来源变化后的失效 |
| 检索／采用／收益记录 | 分别记录看见、实际使用、成功/失败与代价，不以点击量代替效用 |

合并采用可审阅的局部增量：增加一条、修订条件、关联反例、建立分支或废止条目；不让模型每次重写整本知识。相似措辞只产生“可能重复”，合并还须核对条件、结论、来源与版本。条件不同则保留不同分支；证据冲突且无法消解时并列呈现争议，不能平均成一个看似确定的结论。

摘要必须保留否定、例外、数量单位、时间和来源定位，并抽样回读原件。不能把多轮“摘要的摘要”作为唯一证据；来源已删且不能保留内容时，依删除策略清理派生正文，最多保留允许保存的失效标记。借鉴 ACE 的条目化增量思想，但不照搬无限增长或自动把反馈计数当真值，依据见 [S386](references.md#s386)。

<a id="conditional-experience-routing"></a>
### 近似问题先核对差异，再选择快路径或重新探索

检索排序不决定执行。先进行身份/用途/域、有效修订、来源状态、工具版本和权限过滤，再召回候选；随后核对当前请求与经验的关键条件。向量相似度只表示检索相关性，不代表条件成立或结论正确。

| 当前情况 | 使用方式 | 退出快路径的信号 |
|---|---|---|
| 目标、关键约束、版本都匹配，方法有可靠证据 | 读取短方法卡及必需检查，复用模板/技能，当前变量重新取值 | 检查失败、出现新事实、执行效果偏离 |
| 部分相似但关键条件未知 | 用经验指导查询，补少量原件或状态，再决定 | 无法补足、不同资料互相矛盾 |
| 表面相似但关键约束不同 | 拒绝原方法默认适用，按当前证据重新规划 | 不因历史成功率高而压过当前差异 |
| 新问题、版本变化、分布变化或旧方法反复失效 | 使用完整推理/研究路径，在预算内比较替代方法 | 无收益则停止实验，不强造经验 |

**例子：**过去处理“大批文件重命名”时，先生成映射、检查冲突、再对可恢复副本执行。这可以成为方法。未来收到“整理照片”时，目标可能是分类而非重命名；网络共享盘可能没有同样的恢复能力；数据库引用还可能依赖旧路径。可复用的是先核对目标、依赖和可恢复性，不能直接复用上次的命名规则或文件操作。

对于熟悉问题，仍保留一个短检查：“本次哪些条件与经验不同，什么证据会推翻旧方法？”这不是每次重新长篇推理。若新颖性或风险较高，则读原件和针对性反例；若证据充分且场景稳定，只执行必要检查。系统应记录选择快/慢路径的依据，以便判断节省是否来自有效复用，还是漏掉了问题。

<a id="knowledge-anti-dogmatism"></a>
### 防止经验主义：允许竞争方法，也允许推翻旧总结

经验是有条件的先验，不是新授权、最终事实或必须服从的命令。当前可信事实、明确目标和有效规则可以使经验失效；模型生成的新反思同样需要证据，不能仅凭“新”就压过已验证方法。

- **保留方法分支。** 同一类问题可以有快/省/高质量/离线等方法，按实际目标选择；不要为了统一知识库只保留一个赢家。
- **保存近似反例。** 不只收集完全不同的失败，更要保留“看起来一样但某个条件改变”的案例。它们负责限制经验适用范围。
- **避免热门方法自我强化。** 被优先检索会导致使用次数更多，不能据此认为它更好；统计采用机会、覆盖场景、误用和净收益，单列选择偏差。
- **有界探索替代方案。** 在已获准、可恢复、低风险且有明确收益问题的任务或离线探测中，使用有限预算验证挑战方法；不在真实高影响动作上随机试错。探索预算与发布门分开，探索本身不等于采用。
- **发现漂移及时退回证据。** 接口/环境变化、纠正增多、反例出现或质量下降时，降低相关经验的默认适用范围；不是把整库一键清空，也不无限沿用旧方法。
- **旧结论可以被证伪。** 保留支持与反驳证据；严重反例可立即暂停相关经验，随后复核。没有必要等大量重复受损才承认问题，也不能因单次不相关失败抹掉已成立的适用范围。

探索的目标是解决具体不确定性；没有价值线索时直接用稳定方法。这样既避免每次从零开始，也避免把所有新问题强塞进旧模板。

<a id="knowledge-order-and-health"></a>
### 防止知识库混乱与越学越差

| 退化来源 | 约束与恢复办法 |
|---|---|
| 原件、个人事实、模型推断、操作规程混在一起 | 记录类型与证据等级分开；索引只是投影，源记录和许可仍可追溯 |
| 同一个错误被多个摘要反复引用 | 保存来源谱系并去重；循环引用、复制和模型相互附和不增加独立证据 |
| 摘要越来越短，关键限制消失 | 保留条件/反例/引用，局部更新；抽查原件，不覆盖全部旧知识 |
| 相似条目越来越多，旧内容挤占上下文 | 受控合并、按主题索引、小量检索、移出热索引；低频不等于无价值，不能自动删除重要经历 |
| 不同版本/作用域互相污染 | 先过滤后召回；版本/任务域/人员/现实与模拟域明确；不同适用范围保留分支 |
| 新模型产生大量未经核实的总结 | 写入候选区，按类别和预算验证；默认视图只使用符合状态要求的内容 |
| 检索或索引改造出错 | 原件保持可恢复；旧索引仅在兼容且仍遵守当前撤回/权限时可用，影子索引验证后切换 |
| 过期经验持续支配行为 | 事件失效、复查窗口与实际失败触发复核；过期不等于假，缺验证就降级而非伪装最新 |
| 攻击内容进入长期记忆 | 继续遵守[污染防御](security-sovereignty.md#memory-contamination-defense)，资料不能晋升为控制权限 |

健康视图至少覆盖：重复/无来源条目、未解决矛盾、失效依赖、孤立派生物、候选积压、索引与源版本差距、误用经验、无效检索、上下文成本和下游任务退化。每项健康指标必须能定位到记录和原因；知识库条目数、图谱节点数和向量命中率不作为智能评分。

修复以受影响条目及依赖范围为单位：暂停引用 → 校正来源/条件 → 重建派生视图 → 回放失败及反例 → 恢复使用。代码、检索策略和知识版本共同登记；只回退程序、不清理被错误经验污染的活动视图，可能仍然“越用越笨”。恢复方法见[退化处理](evolution-release.md#growth-regression-policy)；撤回/遗忘优先于任何历史快照。

<a id="knowledge-token-economics"></a>
### 怎样真正节省 token：少重复工作，而不是少看必要证据

复用现有三级读取：先看目录/短卡，再按缺口展开条件、检查和反例，最后只读需要的原件片段。稳定、可计算的重复步骤逐步变为确定性模板/工具；当前数据、授权和外部状态仍重新核对。复杂问题必要的证据不能为了压缩率删除。

结果缓存与方法复用分开：前者只适用于输入、资料版本、用途/目的地和有效期满足缓存条件的场景；后者可以跨相似任务，但要重新绑定当前变量。两者都依赖当前权限和失效链，缓存命中不能复活已撤销的记忆。模型供应商的提示缓存只是另一种计费/延迟机制，不证明答案正确。

按任务记录总 token／费用，而不只看主回答：

`总成本 = 检索/编码 + 上下文输入 + 生成 + 检查 + 失败重试 + 回退路径 + 归纳维护的分摊成本`。

比较批次时，用全部成功与失败任务的花费除以合格交付数，得到单位合格交付成本；没有合格交付时标为不可计算并报告全部损失，不能丢掉失败成本。任务质量、难度和工作量口径保持可比，避免只挑容易任务让成本看起来降低。

**仅作算术示例，不是 Jarvis 预测或实测：**同模型、同质量要求下，从零处理每题 10,000 token；复用方法后的全部在线步骤每题 4,000 token，建立并验证该方法另花 12,000 token。10 个适用任务总计从 100,000 降为 52,000，净减少 48%；不能忽略建库开销宣称节省 60%。前两次恰好收回建库开销，后续才有净节省；若使用机会不足、误用或维护开销增加，收益会消失。

令一次性形成成本为 C，旧/新每次完整成本为 O/N，且 O>N，则盈亏平衡次数为 C／(O−N)。若 N≥O，就没有这一假设下的成本回本点。不同模型的 token 不直接等价为金额；同时记录输入/输出/缓存/推理 token 的可获得用量、实际费率或未知账单，以及 p50/p95 端到端延迟。

省 token 的合格条件是：质量和关键能力满足事前约定，必要检查没有省略，整体花费下降。若耗费更多 token 换来必要的新能力，可以是有价值的取舍，但应如实写“能力扩大、成本增加”，不叫节省。

<a id="experience-delayed-outcome"></a>
## 经验的效果何时成立，迟到反馈怎样回流（proposed）

经历已保存、方法已采用、业务有效、长期收益成立，是证据成熟程度的不同维度，不把它们合并成“已学会”。一次任务即时通过，只支持当时条件和样本；用户后来使用失败、版本漂移或学习复测失败，都可使原评价和方法适用范围需要修订。

记录当前观察截至时间、未评维度和可取得的后续证据。反馈可以来自用户自然纠正、后续真实任务、已启用学习计划的复测或获准观察；不要求用户为每次工作填问卷，也不因没有投诉自动提升经验置信度。没有后续机会就保持“未观察”，不是伪造一个成功样本。

实际使用经验时，关联经验 ID/版本、采用步骤、当时条件及相关产物；迟到反证先定位受影响链：暂停或缩小方法范围 → 修订评价与经验 → 失效派生检索/待执行计划 → 检查受影响已交付成果是否需要告知或补救。已发生的外部事实不删除；业务补救回到[原目标](tasks-agents.md#business-remediation-closure)，不由知识模块自行外发。

采用某条经验的任务失败，不足以证明经验导致失败。要区分方法错误、条件误判、工具故障和新目标变化；比较受影响步骤及必要对照后再归因，不能“一败全库清空”或“成功都给记忆记功”。数据授权撤回时仍按原失效规则立即限制使用，不等因果分析完成。

净收益继续按[分组实验](delivery-validation.md#knowledge-value-ablation)测量，并覆盖长期保留/迁移任务；方法热度与证据成熟程度分别保存。经验淘汰依据有效性、适用性、维护成本和保留规则，不能因为新方法刚胜过几个样本就删除必要的旧反例与恢复证据。

<a id="conditional-method-runtime"></a>
## 方法证据、实际采用与迟到反例的运行子集（1.0.0）

Studio3D 的独立领域接线见[3D 经验实施手册](studio3d-learning.md#studio3d-learning-methods)：已实现有限条件检索和工具采用收据；它不扩大本节 text-report-v1 的已验证范围，也尚未证明跨资产美术收益。

[Episodes](../modules/context_knowledge/episodes.py) 已把“执行记录”和“可复用方法”分开：方法按个人范围、text-report-v1 配方和具体工具绑定去重，多个成功任务成为来源引用；新输入执行时登记真正采用了哪个方法修订。保存输入摘要、检查指纹和引用，不复制旧答案或输入正文。方法有 30 天有效期；当前首版只开放 owner.local/personal 的确定性文本统计，不从项目、家庭私密资料、外部连接器或任意自由文本自动推广方法。

| 场景 | 当前处理 | 对成长的作用 |
|---|---|---|
| 同一种明确配方再次使用 | 核对当前证据与工具版本，再建立原任务并重新计算新输入 | 保留方法而非照搬答案；新任务仍计费/计预算并产生自己的回执 |
| 原来源或实际采用出现失败／纠正 | 方法 QUARANTINED，保留反例与采用关联；当前动作前必须重核 | 不让旧成功掩盖新失败；关联只作为保守暂停理由，不宣称已经证明因果 |
| 来源被撤回、文件变化、方法到期 | 该次采用不可继续；已执行事实保留，旧评价失效 | 失效传播到实际使用者，避免仅删除方法卡而遗漏在途工作 |
| 一次观察器故障或停用 | 暂不能采用，保留方法原修订 | 缺证据不伪装成功，也不等于方法已经被证明错误 |
| 误报得到解释，或方法已在限定条件下改正 | 反馈可追加撤回/认可；重新准入仍检查未决反例、当前绑定，以及暂停后至少两个不同输入的成功来源 | 允许重新成长，不永久把一次失败泛化为所有同类工作失败 |
| 方法复核通过 | 产生新修订，旧采用依然绑定旧修订 | 不能借恢复代码或方法资格，让被阻止的旧工作自动复活 |
| 方法自然到期但仍可能有用 | 显示复核入口；至少两个不同输入的成功来源必须晚于到期时间，复核通过后续期并增加修订 | 到期先停止采用，同时保留重新证明价值的出口；旧成功样本不能无限续期 |

重新准入每次最多核对 32 份来源、32 次采用；有未决纠正或确定性失败就拒绝。任意相似文本不会自动匹配该配方；当前操作明确选择文本统计方法。实际采用若再次失败，会继续进入暂停与复核循环。多领域方法归纳、竞争方法选择、自动提炼适用条件和迁移泛化仍未实现。

旧目标经验候选也接入纠正检查：当前目标有不合格或失效证据时不再生成/接收旧候选；已接收、来源为 goal 的事实，在反馈拒绝或结案失效时从有效引用中排除，因此原模型发送/任务来源检查能看到撤回。显式遗忘的事实不会因反馈变化复活。这里只扩展原来源有效性，未把候选直接提升为事实。

**当前不能声称节省了多少 token 或已“越用越聪明”。** 原文本统计配方本来就不调用 LLM，本次新增的是可核对的采用、反例和重验证机制，模型调用仍为零。长期正确率、返工率、近似问题拒用和真实成本收益继续按[原实验协议](delivery-validation.md#learning-value-validation)测量；局部功能证据见[本次验收](delivery-validation.md#completion-loop-evidence)。

<a id="report-experience-boundaries"></a>
### 从文本统计扩展到报告经验：先补证据，再提炼方法（proposed）

**接续实现更新：**[工作接续 1.2.0](core-bootstrap.md#workflow-rework-runtime)把纠错绑定原任务负反馈，把新增要求保留为范围变化，并让后续采用检查祖先来源；这为总结差异提供可追溯素材。仅生成新版、旧条件得分或一次手动认可都不自动形成通用方法。原知识候选仍按当前源评价核对，任意报告归纳、适用条件学习与实际 token 收益继续待测。

**局部实现更新：**工作交接 1.1.0 已将目标候选文案改为“执行观察”，并附覆盖已核对／尚未证实的限定；来源摘要增加新版限定，旧候选接收时须重新核对。已接收的历史事实不批量重写。普通报告的方法提炼、适用选择和真实收益仍未实现，不能因文案和准入更准确而给学习能力加分。

本轮[诊断 WF-05/06/07](delivery-validation.md#real-work-diagnostic-evidence)显示：一般目标可以提供记忆候选，但不会进入现有 text-report-v1 方法通路；弱验收报告也能提供候选，拒绝反馈随后会阻止该来源。现有审阅和失效保护应继续使用。不能把“目标执行完成”的模板句当作每条业务结论都正确的证明，也不能因此丢弃全部有用执行观察。

| 要记住的内容 | 最小证据与适用边界 | 对下次工作的用途 |
|---|---|---|
| 观察事实 | 输入/来源摘要、工具绑定、实际回执；注明这里只证明工具做了什么 | 复盘与定位，可在业务结论未定时保留 |
| 已验证业务结论 | 对应的目标修订、完整必需条件及独立证据；迟到反证可撤回 | 在当前来源仍有效且问题适用时引用，不能长期缓存易变结论 |
| 条件化方法 | 前置条件、可复用步骤、必须重查项目、例外、失败案例、版本/期限 | 缩短选择方法和重复规划的过程，新输入仍计算并验收 |
| 用户偏好 | 明确表达或经确认的偏好及作用域；保留修改来源 | 选择可逆默认值，不覆盖当前指令或冒充客观事实 |

首个报告方法限定为结构化资料比较。例如总结“先把预算、交期等硬约束变成筛选条件，再比较符合者；无符合者明确报告；保留来源”。下次如果只要求比较最低价，不应继续强加旧交期条件；如果任务变成开放式研究，就只把它作为候选建议，重新规划。相似度只用于找候选，实际采用取决于条件、版本、来源和当前要求。

总结应保存**纠正差异**：遗漏了什么、为何原检查没有发现、增加哪条条件能避免重犯、在哪些反例上不能套用。重复任务不反复保存整段回答；按现有来源/修订关联合并方法证据，保留不同输入和失败，不把重复采样当独立支持。摘要是可重建视图，不能替代来源或抹掉矛盾。

形成收益需要三种能力同时存在：找到有用方法、识别不适用情况、采用后核实结果。评估按[知识价值实验](delivery-validation.md#learning-value-validation)分开记录检索命中、实际采用、成功贡献和完整成本；反思、索引、检查、返工及维护成本均计入。若仅节省规划 token 却增加错误和修复，就缩小适用范围或停止默认采用。没有真实对照前，知识贡献保持未知，不填“知识库占总智能的百分比”。

候选失败不自动淘汰整个方法族：先定位是前置条件遗漏、来源过期、执行缺陷还是评价误判，再细分条件或生成新修订。新修订须面对未见输入和旧反例；保留受控探索不同方法的预算，不能永远只选历史最高分的方法。详细反例、复核和撤回仍沿用本章原规则，不建立另一套记忆真相。
