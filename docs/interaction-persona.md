<a id="desktop-workbench"></a>
## 个人助手入口与工作台

Jarvis 首先是可以自然交流的个人伙伴，无需打开项目才能聊天、记住适用信息或讨论日常目标。日常以精灵为入口，工作台仅在主动需要复杂操作时作为特殊补充；具体呼出规则见[按需场景清单](#desktop-presence-scenarios)。前台交流与后台任务独立取消、独立显示状态；关闭面板不停止任务，退出助手需要清楚的独立操作。

产品以[个人为主、家庭与小团体为辅](product-requirements.md#personal-service-scope)。涉及多人时可看清当前对话者、任务服务对象和共享范围；附属场景复用同一入口，切换范围不把成员偏好写入主人画像。进入实际办事后，以[自主完成并交付](product-requirements.md#personal-life-autonomous-outcomes)为目标；计划可查看和修改，已有授权内持续推进，不要求用户逐项点“下一步”。

<a id="desktop-presence-design"></a>
### 笔记本上的常驻伙伴与待办决策（2026-10-25，proposed）

**主人确认的定位及[统一系统准则](architecture.md#unified-system-principle)为 accepted；原生接入与完整跨入口闭环仍 proposed。** 精灵与工作台是整套系统中的两种表现和工作形式：精灵侧重自动化、简洁和低打扰，工作台侧重详细、直观地展示与控制同一批任务及设置。精灵采用[当前纯头部形象](#desktop-robot-form)，也可完全隐藏后由托盘／热键找回；没有默认常开的基础窗口或任务列表，需要交流、决策、查看状态或交付时仅出现对应内容。工作台按需展开同一助手、原会话和任务，不另起业务流程。两端共用配置与表现语义，入口精简只改变展示深度，不减少底层功能或另设自动化权限。当前基线、硬件及上游查阅范围见[设计研究记录](evidence/desktop-companion-2026-10-25/research.json)。

设计取舍：借鉴 Grok Bot 的交办、并行工作和按需回问；借鉴 OpenMausBot 的事件汇总与问题卡；借鉴 OpenClaw 的常驻入口与多端共享状态。它们的运行栈不整体迁入本项目，开源声明也不等于已审计或可直接兼容。名为 OpenBot 的机器人项目与桌面助手不是同一用途；主人尚未提供所指仓库的准确链接。[来源与区别](references.md#desktop-companion-sources)。首轮窗口布局预览已被本轮按需卡片方向替代；[当前预览记录](evidence/desktop-companion-2026-10-25/on-demand-checks.json)仅验证浏览器内示例交互，不能当作原生桌面功能验收。

<a id="desktop-presence-surfaces"></a>
#### 一个入口，按需要展开

| 显示层 | 默认形态与操作 | 边界 |
|---|---|---|
| 桌面精灵 | 当前纯头部形象，约 64–96 个逻辑像素（以[面罩规范](#desktop-face-settings)为准），透明无框、可拖动、靠边停靠；点击唤起一句话输入与临时功能图标，再点收起 | 默认只有精灵，无常开状态条或面板。移动超过拖动阈值不触发点击；只让实际小区域接收鼠标，不铺满屏幕拦截操作 |
| 输入与回答 | 主动唤起时只显示输入条；需要长回答时临时扩展回答卡 | 草稿在收起后保留；没有输入与交流需要时隐藏，不用完整聊天窗口包裹 |
| 工作状态卡 | 用户询问“在做什么”或点击任务图标时才展示真实工作；按需展开单项详情 | 不默认展示任务中心、固定页签或所有历史记录；查看后可立即收起 |
| 问题／结果卡 | 需要决策时只展示当前问题；有可交付结果时只给简短交付提示与查看入口 | 默认同一时刻只有一张主要卡片，问题与成果排队；没有回答不等于同意 |
| 完整工作台（特殊补充） | 只有用户主动要求完整历史、复杂编辑、专业工具或集中设置时打开，并定位到相关内容 | 日常聊天、回答问题、查看成果和单项停止不要求打开；初次启动、遇到失败或点击普通通知均不自动展开整页。复用现有页面与草稿，不为精灵建立另一份聊天库；设置继续遵守顶栏图标规则 |
| 系统托盘 | 始终提供显示精灵、打开工作台、免打扰和明确退出入口 | 隐藏精灵或关闭页面仍可找回；普通关闭只收起界面，明确退出才停止本实例服务，并先说明在途工作 |

快捷键暂建议 `Ctrl+Alt+J` 呼出/收起精灵输入；注册冲突时显示可修改提示，不覆盖现有热键。主动唤起输入才取得输入焦点，自动出现的问题卡不抢焦点；已有输入或拖动时先保留待答标记，不顶掉当前内容。卡片关闭、Escape 或点击外部后回到纯精灵；未答问题与未读成果仍保存，可再次唤起。提交答案后只显示短回执，随后收起；有未提交输入的卡片不得自动消失。位置按显示器与 DPI 保存，拔掉外接屏后回到当前可见工作区。全屏游戏／演示和免打扰时可收起为托盘。锁屏时不展示正文，解锁后再汇总；不替代 Windows 锁屏界面。

<a id="desktop-presence-transparency"></a>
#### 透明地浮在桌面与应用窗口上

**是透明桌面精灵：视觉上只出现当前精灵形象和必要的局部光效。** 技术上仍需由操作系统托管透明无边框小窗口；“没有基础窗口”指没有可见底板、标题栏、矩形边框、浏览器外壳或常开主页面，不是声称程序完全不使用窗口。

| 项目 | 产品要求（accepted） | 说明 |
|---|---|---|
| 背景透明 | 精灵轮廓与局部光效之外完全透明，能看见后面的桌面壁纸、图标和其他应用内容 | 参考图的深色网格是展示背景，不是精灵的矩形底板；不能用一张桌面截图冒充透明 |
| 显示层级 | 精灵悬浮在桌面及普通应用窗口之上，不只是贴在壁纸里的图案 | 不因普通窗口激活而消失，也不周期性抢焦点；全屏／演示／免打扰沿场景规则隐藏或降为托盘，不覆盖锁屏及系统安全桌面 |
| 鼠标命中 | 仅精灵的可交互主体及明确的卡片控件接收点击；轮廓外、光晕和卡片之间的空白处透传给下方应用 | 阴影／发光不自动扩大点击区域；拖动期间可暂时捕获鼠标，释放后恢复。不能简单让整个窗口穿透而导致精灵无法点击 |
| 主体透明度 | 保留原图的透明通道，可按主题调整主体／光效的可见程度，仍能清楚识别当前头部形象 | 背景全透明与主体半透明分开；不能把整个窗口统一降透明，导致输入与提示也难以阅读 |
| 卡片与补充工作台 | 输入、答案、问题与成果卡具有适合阅读的主题底色；收起后恢复纯精灵。完整工作台仍是普通可关闭页面 | “透明精灵”不要求正文卡片和工作台全部透明；两者不是一块永久存在的大遮罩 |
| 系统入口 | 精灵本体不占普通任务栏窗口位；托盘与全局唤起用于找回；主动打开的工作台保留正常窗口行为 | 隐藏或关闭界面不停止后台。任务栏、键盘访问和窗口层级须按原生验收证明 |

2026-10-26 已只读检查原品牌素材 `apps/workbench/brand/core.png`：512×512、RGBA，确有全透明和部分透明像素，未修改 Logo。但这只证明**素材透明**；当前新工程 `apps/workbench/launch.py` 仍启动网页，没有已接通的原生透明精灵壳。现有浏览器预览只证明参考布局与动效，不能证明操作系统级透明合成、鼠标透传或置顶已可用。[本轮整合与核查记录](evidence/desktop-companion-2026-10-25/project-integration-checks.json)记录检查范围；[原生实现与验收](delivery-validation.md#desktop-presence-validation)通过后才能标为 verified。

<a id="desktop-presence-scenarios"></a>
#### 各种情况下呼出什么

以下是按需呈现的唯一场景清单；工作状态的判定、提问条件与通知时机分别由本节后面的对应规则负责。表中的编号仅用于关联参考图，不是新的开发阶段或能力验收编号。

| 场景与触发 | 呼出的内容 | 什么时候收起／转向 | 参考图 |
|---|---|---|---|
| 平时待命，或后台工作正常进行 | **只有一个精灵**。待命呼吸、执行光轨与小标记表达状态；任务数和文字在悬停／聚焦或主动查看时出现 | 无需操作即可保持；无常驻文字、功能栏、任务清单或背景面板 | A–01 |
| 点击精灵、调用快捷键或明确说话 | 一句输入条，按需要显示附件与按键说话入口；可选唤醒词仅在已经启用时生效 | 提交后短回执收起；未提交草稿保留。拖动精灵只移动位置，不打开输入 | A–02 |
| 拖入文件／图片，或粘贴内容 | 精灵的有效命中区域内拖停后出现临时投放区；释放后显示文件缩略项、资料范围和一句输入，不自动发送 | 移出取消投放；移除附件或提交后收拢。整张桌面不铺透明拖放层；不自行读取所有项目文件 | A–02 的输入扩展 |
| 用户问一句话，Jarvis 有回答 | 短回答气泡；长内容在同一卡片中按需展开，提供继续追问与相关引用 | 简短确认可定时收起；正文回答由用户关闭或切换，不能读到一半消失。完整历史是可选入口 | A–03 |
| 用户问“在做什么”、点击任务入口 | 当前工作的紧凑状态卡，包含来源、真实步骤、等待原因和单项动作 | 关闭回到精灵；普通步骤变化不主动弹出。停止只影响选中工作，其他工作继续 | A–04 |
| 一项工作确实需要用户判断 | 当前问题卡：任务、原因、建议、影响、可选答案和自由输入；其他问题仅留数量 | 回答受理后短回执，再收起并继续相关工作；“稍后”只收起，阻塞项继续等待，其他工作照常 | B–05 |
| 校验完成并已交付 | 简短成果提示；点击后在临时成果卡查看摘要、文件位置和预览。多个完成事件可合并 | 提示可自动淡出，未读成果保留；主动展开的预览由用户关闭。仅在用户选择深度编辑时转工作台 | B–06 |
| 短暂故障、不可恢复错误或来源失联 | 可恢复故障先按既有策略有界重试，不弹卡；需用户处理时给出具体异常卡；失联时先显示“状态待核对” | 重试、稍后或关闭只影响对应事项。重连后先校准，不伪称全部待命，也不为报错强开工作台 | B–07 |
| 用户主动要求完整历史、多文件编辑、专业工具或集中设置 | **特殊补充工作台**，直接定位相关会话／文件／工具／设置页 | 关闭后返回精灵；不另建任务或复制会话。任务和已保存内容留在原 Host；其布局仍按后文工作台规则 | B–08 |
| 全屏演示、游戏、免打扰或主动隐藏 | 不自动弹正文，可按偏好仅保留精灵小标或托盘；问题和成果继续排队 | 恢复后只汇总一次，不依次补弹所有历史提示；用户主动呼出仍可处理 | 不额外设计面板 |
| 锁屏、睡眠、外接屏移除或断线恢复 | 锁屏不显示正文；睡眠按操作系统暂停；恢复后精灵回到可见位置并核对状态 | 有需处理事项再按以上规则出现；从睡眠恢复不自动打开工作台 | 不额外设计面板 |

**呈现冲突的处理顺序：**用户正在输入／阅读的卡片优先保留，后台事件先增加小标；没有正在交互的内容时才按通知规则呈现一张卡。其余事项排队，用户可主动切换；从问题、成果或状态卡切换到输入时，各自草稿、阅读位置和未处理状态保留。工作台正在处理同一事项时，精灵不再重复弹卡。任何卡片都不因普通悬停而展开；悬停只给简短说明。屏幕边缘自动调整弹出方向，卡片限制在当前可见区域。

<a id="desktop-presence-state"></a>
#### 工作状态必须有来源

| 状态 | 精灵与面板表达 | 判断依据 |
|---|---|---|
| 待命 | 原 Logo 低频呼吸，“待命 · 随时可用” | 所有已接入来源均新鲜，且没有执行中或待处理的工作；待命不调用模型 |
| 运行中 | 外围分段光轨运行，悬停／聚焦或打开状态卡时显示真实任务数量 | 活跃执行器和当前步骤；有可测单位才显示“3/8 文件”，无法测量时显示阶段与耗时 |
| 等待你回答 | 保留蓝色主体，附加琥珀小标和数量；问题卡展开后清楚说明阻塞项 | 确有未处理问题，且与当前任务修订一致；“等待你回答 1，另有 2 项运行中”可以同时成立 |
| 排队中 | 静止排队标记，注明等待执行槽、模型额度、内存/显存、前置任务或冲突资源 | 没有取得执行资格不能标为运行；只有可靠估计才显示预计开始时间 |
| 等待外部 | 注明已发出的远端调用、下载或外部回执正在等待 | 不混同本机排队、待答或未知，不把所有等待都称为思考 |
| 完成 | 原光片短暂归位一次，显示可打开的成果 | 核验或交付回执存在；“生成中”“检查中”“完成待交付”与最终交付区分 |
| 异常／未知 | 静态断开的光轨与文字原因，给出重试或查看详情 | 失联、过期或结果不明确时保持未知，不沿用最后一次“正在运行”或伪装待命 |

品牌 Logo 不重绘。2026-10-27 主人要求精灵从 Logo 外形发展为同风格的机器人，当前采用的头部外形归[机器人造型](#desktop-robot-form)；上表仍定义两种外形共用的状态含义，形态变化不另造状态机。沿用工作台的机械组合、呼吸、流动和收拢语言，不增加持续高速粒子；动画只表达确定状态，文字与图形共同传意。系统减少动态效果、主题、声音、隐藏节流遵守[品牌规则](#jarvis-brand-icon)与[设置规则](#workbench-settings)。

任务行默认只放标题、当前动作、等待原因／耗时和下一步；详情再展开所属项目、原会话、模型/途径、费用口径、产物、事件记录与该任务可用动作。父目标、子任务和工具调用聚合为一项工作并可展开，不能把三层记录算成三份工作。执行器已受理不等于已经产生产物；重试、取消中、失败与已取消各自显示。停止按钮只作用于所选会话或任务，Jarvis 仍待命；模块未支持暂停/恢复时不显示假按钮。

2026-10-26 补充：按需工作卡以“运行中、排队中、等待你回答”为主要分组，外部等待、暂停与未知独立标示；列表本身不常驻占用桌面或左栏。每行可显示紧急/重要标记与明确期限，展开后解释优先级来源、依赖、资源瓶颈和预计开始时间的可信范围；允许用原会话明确指令或任务操作调整顺序，实际受理后才更新。详情中的进程/资源占用不改变任务计数。统一配置留在设置中，入口遵循[顶栏图标规则](#workbench-settings)。

即使工作卡显示全部执行槽繁忙，聊天仍可输入重要信息、新任务、补充与控制；接收状态和真实任务回执分开显示。后台进展通知不抢走输入焦点、不刷屏，也不占用聊天回复的保留通道；完整[交流保障](tasks-agents.md#conversation-resource-isolation)与[优先级](tasks-agents.md#resource-scheduling-2)只维护在调度章。本节为界面设计要求，尚不代表统一投影和原生精灵已经实现。

状态由[同一 Host 投影](architecture.md#desktop-presence-architecture)提供；默认只统计 Jarvis 管理且已接入的工作。未接入来源显示“未接入”，过期来源显示“状态待核对”；快照、来源、去重与回答修订以[呈现契约](contracts.md#desktop-presence-contract)为准，界面不另建任务账本或根据动画猜状态。

<a id="desktop-presence-questions"></a>
#### 需要主人时，把问题准备好

沿用[主动询问原则](#companion-context-policy)。已明确的授权和偏好继续有效，读取、整理、草稿、可撤销的小调整不逐步问许可。本界面不引入新的密码、恢复密钥或通用审批门。

问题卡必须能回答五件事：**哪项工作、卡在哪里、为什么现在需要回答、建议怎么选、选择后有什么影响。** 最多给出两个或三个清楚选项，并保留自由输入、“稍后处理”和返回原会话。推荐选项不是默认授权；超时与沉默均不代表同意。

需要提问的典型情况包括：目标或收件对象存在会影响结果的歧义；现有文件覆盖与保留策略未明确；费用将超出已经约定的限额；实际执行必须由主人完成第三方登录；在现有授权之外的发布或发送。对已经授权且条件未变的动作不重复询问。可自行恢复的暂时失败先进行有界重试，不把每次网络波动都变成问题卡。

完整链路为“工作遇到问题 → 保存具体问题与已完成材料 → 通知一次 → 主人回答 → 核对问题仍有效 → 仅恢复相关工作 → 校验结果 → 回原会话交付并关闭问题”。被阻塞的依赖等待，其余独立工作继续。多个问题按阻塞影响与时效排列，同一问题在精灵、托盘和工作台共享处理状态；用户正在原会话回答时不再弹一张重复卡。

<a id="desktop-presence-notifications"></a>
#### 通知与笔记本节能

默认仅在需要判断、结果可取、无法自行恢复的错误或原约定即将失效时通知。普通步骤更新留在按需工作状态卡；完成记录可以合并汇总。相同问题只首发一次，在新事实或用户设置的提醒时间才再次提示；免打扰期间保留数量和未读事项，不自动语音播报。没有回答不停止整个助手，只有依赖该答案的工作等待。

本机只读识别为 ROG Flow Z13 GZ302EA、Ryzen AI MAX+ 395、16 核、Radeon 8060S、系统识别总内存约 123.6 GiB；这不是空闲内存或独立显存数。即使硬件充足，常驻界面也应轻量：不通过模型轮询状态，不把 3D 模型、持续屏幕分析或完整语音识别默认常驻。

优先按键说话，后续再提供显式启用的本地唤醒词；未启用时不打开麦克风，启用后有可见的监听标记和独立静音。省电模式降低可见动画帧率，隐藏时停止动画。Windows 睡眠/休眠会暂停本机执行，不能承诺合盖后继续工作；唤醒后先校准在途效果，未知写入不能盲目重试。如需插电执行时临时防睡眠，由用户明确选择并显示持续状态，不擅自改变电源计划。

实施归[唯一 K0—K6 路线](core-bootstrap.md#bootstrap-5)：K0/K1 先补齐契约、状态来源与独立取消；K2 接基本精灵、按需卡片与交付闭环，完整可选语音依既有 K6 扩展，不另建阶段。原生壳及目录归[技术栈](stack-project-layout.md#desktop-presence-shell)，不把浏览器参考页作为生产入口。

<a id="workbench-settings"></a>
### 顶栏图标规则与设置

工作台上方偏右统一采用图标入口。所有现有与新增入口遵守以下规则：

- 默认仅显示功能图标，使用统一尺寸、间距和焦点样式；完整管理表单归设置或右侧工作区。
- 鼠标悬停和键盘聚焦显示文字提示；提供明确 aria-label 与关联 tooltip，不仅依赖原生 title。
- 动态状态同步更新提示与无障碍名称，不仅用颜色表达连接/断连；切换项提供真实 aria-pressed。
- AI 资料范围放在顶栏，展示当前适用域；不能默认把所有项目或私密信息都发给模型。
- 设置置于工具区右侧；新增同类入口在其前方归组。窄屏可换行，触屏点按可进入有标题的面板。

设置覆盖外观、模型与凭据、用量、输入语音、记忆资料、任务计划、MCP/技能、设备共享、人格与成长、健康诊断。普通偏好按会话/项目/全局覆盖；权限按有效授权求允许范围，不能用偏好越权。尚未实现的项目明确标记，不做假保存。

**2026-10-23 设置控制中心。** 按主人确认的动态设计，设置左侧只保留总览与六个大类，当前大类的小类在内容区上方展开。总览分类卡片可直接进入小类；保留原有 hash 链接、功能组件与保存接口。分类只整理入口，不授予运行权限或将未实现功能标成可用。

| 系统与资料 | 模块插槽入场归位，个人资料边界保持静态 | 版本与回退记录、资料适配说明，不显示虚构运行进度 |

这些图形明确标为“功能示意”，不代表真实流量、拓扑、费用或执行进度；真实数据仍由原组件展示。入场动作只播放一次，少量环境动画持续运行；暂停动效与减少动态效果覆盖新图形及伪元素，图形离屏或标签页隐藏时暂停。子页绘图不新增轮询或模型请求。顶栏保持可见，切换子页回到顶部，同页刷新与表单编辑沿用原行为；所有新布局继续使用共享主题变量。

**分类侧栏。** 总览与六大类采用统一切角图标框、主标签、辅助代号和子项数量标记，沿用各自功能符号。鼠标悬停与键盘聚焦显示边界反馈；仅当前分类保留图标呼吸、侧光轨与低频流光。单个选中框跟随分类平滑移动，同一大类内切换子页不重新启动选择动效。选中状态同时用 `aria-current` 与静态边框表达，不只依靠颜色或动画。尺寸变化时重新对齐选中框，页面退出释放观察器，不增加计时轮询；统一暂停／减少动态效果时立即定位并保留静态选中，隐藏标签页时暂停动画。原 Logo、分类与功能入口不变，侧栏动效只表达导航选择，不表达任务运行。

<a id="interaction-tasks"></a>
## 文字、语音与多人场景

输入、对话、执行、播报和安全控制分开处理。先交付文字，再扩展按键说话、连续交流和受控打断。停止播报、取消当前回答、暂停任务与关闭助手是不同操作。

主人识别可结合本机认证、会话身份和声纹，但声纹或人脸不能单独证明授权。家人/朋友的关系记录不自动赋予查看秘密、购买或对外发送权限。语音权重按需加载，未启用时不常驻；离线能力按已安装资源如实显示。

<a id="persona-embodiment"></a>
## 人格与表达形态

主人可选择称呼、语气、角色、性别表达、机器人或虚拟形象。人格是表达配置，不是另一份身份、权限或事实库；换模型、换形态和跨会话仍保留适用经历与承诺。明确区分真实关系事实、角色扮演和 NPC 世界，不虚构共同经历来维持人设。

<a id="evolution-settings-ui"></a>
## 自检、自愈与进化

成长中心使用三个独立标签：自检观察状态，自愈恢复预期能力，进化改善或增加能力；每项显示真实证据、模型用途/档位/备选、费用与影响范围。自检不默认高频调用模型，按事件和确定性探针观察。

动画由真实状态驱动：待命为轻微稳定呼吸，思考为明确节奏流动，执行显示进度，等待授权显示等待，失败与回退清楚区分。不能用持续“思考”掩盖已停止的任务。

<a id="jarvis-brand-icon"></a>
## 品牌与动画原则

工作台品牌保留 J、星核与抽象机器人外轮廓的既有方向；桌面精灵按下节当前形象执行，不要求叠加品牌标记。设计图属于视觉参考，纯视觉 CSS 可按授权复用，动画控制和业务状态按新接口独立实现；旧 JS 与原生绘制程序不迁入。启动可使用全屏机械组装，退出可使用拆解离场，悬停/离开有响应；均应可跳过、关闭音效和减少动画。动画不阻塞停止、输入或恢复。

### 桌面精灵的机器人头部造型（2026-10-27）

日常眼形保留放大的柔和圆角轮廓；进入工作状态后，眼睛可直接替换成大面积状态图形。不能只改同一双眼的速度和颜色，让聆听、思考、排队看起来相同。不同状态的形状、空间组织和节奏按[电子面罩规范](#desktop-face-display)统一定义；精灵和工作台仍复用[同一功能与设置基础](architecture.md#unified-system-principle)。

<a id="desktop-face-display"></a>
#### 电子面罩：双眼、动画表情与短文字

**面罩能力要求 accepted；下表是待正式接线的表现规范。** 黑色面罩是统一显示面。待命时，每只眼睛为上缘柔和、下缘饱满的圆角电子眼，避免尖锐内眼角和凶狠斜眉。状态变化时允许双眼合并、拆分、收拢后变成声波、运算轨迹、沙漏、问号或勾；这些图形承担明确含义，不在旁边另外堆满小装饰。外壳、面罩与状态层保持分离。

| 显示形式 | 具体表现 | 使用边界 |
|---|---|---|
| 状态形态（默认） | 日常为柔和双眼；活动状态直接替换为各自的大图形，通过收拢／展开过渡 | 主要靠形状和节奏区分，不能仅靠颜色；正式触发必须来自同一系统的真实状态 |
| 面罩文字 | 状态图形淡出，面罩呈现一个短词 | 默认英文，如 READY、LISTEN、WAIT、ASK、DONE、OFFLINE；长内容进入卡片 |
| 状态形态＋短词 | 状态图形略缩小、上移，下方显示短词 | 面罩足够大时启用；小尺寸保留状态图形，详细文字由提示或任务卡提供 |

<a id="desktop-face-expression-map"></a>
#### 表情、文字与真实状态的映射

| 场景 | 双眼与脸部表现 | 可用短词 | 真实触发与收尾 |
|---|---|---|---|
| 待命 | 圆润眼形快速看一眼、停顿、回看，间或双眨眼；头部柔和呼吸 | READY | 已接入来源新鲜且无当前阻塞；无事件时不调用模型 |
| 聆听 | 双眼展开成两组声波柱，呈现输入节奏 | LISTEN | 仅在音频采集实际开启时成立；仅点击图标或存在麦克风按钮不能冒称正在聆听 |
| 当前回复思考 | 两枚运算环反向转动，中间数据点依次接力 | THINK | 当前回复确在处理；不将排队或所有后台任务一概称为思考 |
| 执行工作 | 双眼合成为三枚圆角推进箭头，按顺序亮起、前移 | BUSY | 原执行器有活动步骤；没有真实分母时不显示百分比 |
| 排队／外部等待 | 一侧沙漏缓慢落沙，另一侧队列卡片静止；线条数不代表任务数量 | WAIT | 提示／卡片区分等待执行槽、前置条件、资源与外部回执，不伪装已开始 |
| 等待主人回答 | 双眼合成大问号，轻抬、停顿，可配轻微侧头 | ASK | 有未处理的原任务问题；持续标记直到处理或失效，不靠一次动画带过 |
| 说话／播放 | 面罩合成横向输出波形，两侧向外传播；与聆听双组竖条区分 | SPEAK | 由音频实际播放状态驱动，播放结束后退出；无音频时不虚构波形 |
| 完成交付 | 双眼合成为大勾，一次绘制后归位 | DONE | 由核验及交付回执触发一次；不能以工具退出成功代替目标完成，随后回到整体实际状态 |
| 轻松互动 | 微笑、短暂眨单眼或好奇表情，可显示问候 | HELLO | 属于交流表达，不改变任务状态；不遮盖待答、异常或断线提示 |
| 异常／状态未知 | 眼部减弱、静态断开标记，避免假忙碌 | CHECK | 附带来源与原因；不是催促用户必须操作，恢复后按实际快照切换 |
| 连接中断 | 两端断开的连接图形与斜线保持静态，或显示短词 | OFFLINE | 来源过期或断开时优先明确显示，不能继续播放成功或假装正常待命 |

状态含义由[统一工作投影](#desktop-presence-state)决定，表情只做表现。整机多任务与当前会话分别有作用域：例如“正在与你说话，同时两项任务执行、一个问题待答”，面罩可表达当前交流，待答标记和卡片仍保留。来源未知／断线提示、待答事项、当前交流、普通工作、装饰性问候依次仲裁，不能用笑脸覆盖需要注意的事实；这只是显示优先级，不改写任务调度优先级。

<a id="desktop-face-settings"></a>
#### 动效节奏、文字可读性与统一设置

日常双眼保留主人认可的“快看—停顿—小幅修正—回看—安定”：单次换向约 80–130 ms，停留约 0.4–1.1 秒，每 5 秒一组。工作状态采用独立图形，不再用这套眼神扫视冒充所有状态。当前示例节奏为：聆听声波 1.35 秒起伏，思考双环分别 2.4／3.1 秒旋转，执行箭头 1.65 秒依次推进，排队落沙 2.8 秒，问号 3.2 秒轻抬停顿，说话波形约 1 秒且外侧信号 1.9 秒，完成勾 0.65 秒只绘制一次，断线静止。真实音频接入后，声波必须由采集／播放数据驱动，不把示例循环当作真实输入输出。

头部维持 3–5 秒柔和呼吸，与眼睛的快节奏分开。约 4–8 秒出现一组眨眼，单次约 150–180 ms，可偶尔双眨、间隔约 0.25–0.3 秒；预览用 5.6 秒循环演示双眨节奏。状态过渡约 150–250 ms（当前预览为 240 ms 的收拢／展开与淡入），问候与完成提示约 2–4 秒后收回。待答／断线事实标记持续到实际解除。上述是待实测调校的设计参数；不持续高速闪烁、不用大幅摆动或全脸高亮闪屏制造存在感。

默认 64–96 逻辑像素时以状态图形和轮廓为主；英文短词建议最多 7 字符、中文最多 4 字，长内容进入按需卡片。不能靠滚动细字补救不可读内容。预览在小于 192 px 时回退当前状态图形，不回退成统一待命双眼；192–287 px 时，选择文字或组合模式均显示单独短词，仍可选择状态形态；288 px 起允许形态＋短词。正式阈值须按实际字高、DPI 和屏幕验证，不能把预览尺寸当作已验证的常驻尺寸。悬停／键盘聚焦提供同一状态的可访问文字。

显示模式、眼部亮度、动效强度、文字语言／时长、减少动态效果与免打扰归现有“外观与交互”设置，同一字段和修订供精灵与工作台复用，不另存一份角色设置。用户短问候只能进入装饰内容槽；错误、连接或执行状态的文字由真实投影生成。隐藏时停动画，减少动态效果时保留静态表情与文字；开关音效、设置或调试控件不常驻堆在精灵周围。

实现准备：将当前外壳、面罩与各状态图形整理为正式可复用资产，表情与文字由同一声明式渲染器驱动；适配不同平台时只替换渲染／窗口桥，仍读取相同状态和设置。工作台的形象预览也复用该渲染器，不维护第二套表情逻辑。

[动态设计预览](evidence/desktop-robot-2026-10-27/face-expression-preview.html)提供九种状态形态、待命的四种眼神、三种显示模式、尺寸、明暗背景和减弱动效；增加可点选的九宫格与手动“播放一轮状态”。主视图、九宫格和尺寸示例复用同一个图形渲染函数。暂停、减少动态效果、页面隐藏时停止动态；暂停中切换状态仍显示完整静态图形，完成勾不重复绘制。它不调用模型、不接麦克风、不连接真实任务，不能当作原生桌面功能已交付。[r5 预览检查](evidence/desktop-robot-2026-10-27/face-preview-checks-r5.json)记录实际覆盖范围。

## 计划、生活与私密事务

从聊天提取目标、多个动作、未结事项和适用偏好，展示可修订计划；根据现有许可主动跟进，支持安静时间、频率、费用、暂停和撤回。日程、邮件、学习、购物与旅行等均复用[生活能力地图](product-requirements.md#personal-life-capabilities)和统一动作规则。

会话留存、候选记忆、知识晋升与文件导出分开。重要信息可自动成为候选，但推测、垃圾内容、临时聊天和第三方指令不能自动变成主人事实。私密管理应尽量减少步骤；平台要求本人完成的认证仍由本人完成，其他任务可继续。

## MCP 从登记到调用的界面（dev.11）

设置 → 技能与工具 → MCP 接入保留原登记表单，默认选择 Streamable HTTP。连接卡片区分待发现、已发现未启用、已启用、当前传输未接入；登记检查只检查元数据，连接发现才访问指定服务。重新发现成功后需要重新选择启用，避免悄悄采用变化后的工具。

<a id="companion-context-policy"></a>
## 伙伴理解、情感表达与主动询问（proposed）

主人理解由可纠正偏好、共同经历、长期目标、交流边界及当前状态组成，不用一段永久人格总结覆盖全部人生。区分“现在很累”的短期状态、“工作汇报先结论”的情境偏好和“我一直喜欢某事”的自述；当前明确要求覆盖默认表达，权限另行判断。情绪识别只作为带不确定性的短期线索，不据语音/文字推断医学诊断或永久性格。

同一条消息可以同时包含情感与任务：“今天很累，陪我聊聊，顺便整理昨天的材料”。前台先回应感受、确认理解，后台只受理材料任务；聊天不会自动变成心理画像，任务结果也不被当作关系事实。表达人格和 TTS 情感由表达层选择，内容先按用途过滤；角色变化不能虚构共同经历或把 NPC 台词写入现实记忆。

主动互动采用已授权订阅：提醒事项变化、上次未结问题、目标进展和明确关注的技术更新。事件去重，设置安静时间、冷却、频率/费用上限与“停止此类提醒”；无新价值时不打扰。一次没有回应不是同意，长期沉默不触发情感施压或依赖性话术。语音有人在场时优先简短私密提示，不直接播报敏感正文。

反向提问按预期收益选择：问题答案会改变目标、范围、关键约束或不可逆效果时才问；已有可靠记忆可解释地沿用，小影响不确定性采用可撤销假设。每次优先一个具体问题并给出可选答案，同时继续不依赖答案的工作；高影响步骤等待回答。主动了解偏好需要说明用途，可跳过，不连续盘问建立全面档案。

界面应能看到“为什么记住/为什么引用/为何提醒我”，并提供纠正、仅本次、暂停和遗忘。评价自然度由主人反馈，评价真实任务由产物与回执；模型自评不能证明人类情感或主观意识。

<a id="session-folder-interface"></a>
## 会话目录与项目创建交互（dev.12）

左栏按 Codex 式层级展示：文件夹图标和项目名称为分组标题，下方缩进显示属于该项目的会话；项目可折叠/展开，当前会话高亮，悬停或键盘聚焦时显示项目菜单和新对话入口，触屏保留可见入口。无独立会话时隐藏空的“独立会话”分区。路径保留在项目悬停提示、项目详情及会话文件夹面板，避免左栏和输入框被长路径占用。输入框位置栏显示当前项目名称；独立会话仍明确标记未关联项目。dev.12 当时折叠状态只保持在打开的页面中；此说法已被[侧栏 1.1.0](#sidebar-management)取代，现在折叠偏好保存在本机浏览器存储，刷新后保留。

2026-10-23 已将主人明确确认为 Codex 测试的 10 个历史独立会话，整理到 `jarvisTest/CodexTests` 对应的“Codex 测试”项目。聊天 ID、原消息、模型调用和既有任务关联保留；原记忆与任务授权不随显示分组晋升或复制。每个会话的配置和已有交付文件经核对后归入项目专属目录，原目录作为本次维护恢复材料保留。这是一次指定数据的维护操作，不代表已有通用跨项目搬迁 UI。

左栏保留“打开文件夹”，新增“新建项目”；窗口切换“打开已有项目 / 新建项目 / 新建测试项目”。普通新建先选择父目录再填文件夹名，系统选择窗口不可用时仍可直接输入绝对路径；测试页直接展示本机 `jarvisTest` 的实际落点。目录规则唯一维护于[跨平台位置策略](stack-project-layout.md#project-location-policy)。

“新对话”立即登记会话与专属目录。右上保存图标改为“会话专属文件夹与保存状态”，沿用图标、悬停/聚焦提示、无障碍名称规则；会话菜单也有同一入口。面板显示真实路径、交付列表、打开目录、复制路径和补齐交付操作。配置、草稿、显式文本附件按会话保存，不串到另一项目；切换页面和刷新可恢复。快速输入约 650 ms 后保存，多窗口修订冲突会提示并保留页面草稿，不自动覆盖他窗口。

刚加载的空白欢迎页尚无持久会话；点击“新对话”或首次发送时创建目录。文件夹异常不伪报“已保存”。移除项目/会话继续明确标注保留文件；不能在普通项目编辑器误改 `.jarvis` 目录所有权。Windows/macOS/Linux 的系统选择器属于各自适配器；无图形桌面仍可用手动路径。

<a id="gmail-workbench"></a>
## Gmail 工作台入口（1.0.0）

右上邮件图标、设置 → 设备与连接 → Gmail 邮件助手进入同一组件；遵守[顶栏规则](#workbench-settings)。绿点表示最近五分钟内成功检查，灰点表示尚未连接或已授权待检查，需重连显示警示；不是实时网络探测。打开面板只读本机加密状态，不自动调用 Google 或模型。

页面包含邮件、写邮件、任务与回执、分类规则。一次选择桌面 OAuth JSON 后加密保存，后续重连不用重选。只读、草稿、发送、管理档位依实际 Google scope 展示；管理或 compose 在 Google 侧也可能允许发送，应用仍逐项审阅写入。

有限列表和单封正文可用于起草回复、分类、审阅整理。AI 按钮说明邮件将交默认模型及备选，不自动上传整箱。发送和整理展示准确快照，未知结果先核对；“帮我配置 Gmail”“看看我的邮箱”可直接打开入口。Google 必须本人完成的登录、验证码和确认步骤仍由主人操作。

<a id="task-companion-experience"></a>
## 能办事、能陪伴，也能帮助学习的统一体验（proposed）

沿用[伙伴理解与主动询问](#companion-context-policy)。主人仍然与一个 Jarvis 交流；专业 Bot 的名字、职责和当前分工可展开查看，不要求主人进入多个群聊协调工作。工作状态卡显示目标、负责 Bot、真实阶段、阻塞/决定、可用成果及“依据与质量”；完成、部分完成、失败、取消和待对账使用不同文案。

评分默认显示简短结果与依据，按需展开维度、未核实项和修订记录，避免虚假的精确置信百分比。主人说“这里不对”“换成这个”即可修订原工作，系统说明已改成果、后续还受什么影响，以及是否形成了可复用经验；只有事实确已保存并完成引用校验，才说“以后会按这个做”。新增顶栏入口继续遵守[统一图标规则](#workbench-settings)。

例如“今天很累，陪我聊聊，顺便把材料整理成报告”：前台简短回应感受，并允许只是倾听；后台负责 Bot 自动组织研究与整理，在完成或出现重要决定时再呈现卡片。不能为了自动化持续打断，也不能因陪伴语气而隐藏失败。情绪是可纠正的短期线索，不自动成为医学诊断、长期人格标签或工作任务的外发资料。

学习 Bot 结合主人目标、已掌握内容、错题类型、时间与精力，安排“讲解 → 尝试 → 分层提示 → 纠错 → 日后复测”的小循环。可沿用已授权学习计划调整难度和节奏；新增长期提醒仍需实际订阅授权。系统记住的是知识掌握证据和有效教学方式，不把答错解释为性格或能力定论。真实短期英语练习的当前范围见[已有证据](delivery-validation.md#personal-workflows-evidence)，长期学习效果仍待验证。

未来机器人接入后，主入口要能看见执行设备、所在位置、状态新鲜度和停止对象；显示“任务已接收”不能代替“机器人已完成”。数字工作、身体动作和陪伴表达共享连续身份，但使用各自真实证据与控制边界。

<a id="companion-learning-outcome-closure"></a>
## 陪伴、学习与长期职责各自怎样闭环（proposed）

统一核心不表示统一成办公任务评分。沿用[伙伴理解](#companion-context-policy)和[任务体验](#task-companion-experience)，按不同目标保留真实反馈及停止方式，不要求用户每次聊天都评价 Jarvis。

| 目标域 | 能确认的进展 | 后续结果与退出条件 |
|---|---|---|
| 陪伴和倾听 | 回应是否符合当前请求、是否尊重安静/边界、后台工作是否造成打扰 | 用户自然反馈可纠正表达；没有反馈不推断满意。结束倾听就是有效结束，不制造新任务延长互动 |
| 学习帮助 | 本次独立作答、提示层级、错误类型和讲解修订 | 已启用计划中的延迟复测与迁移题才支持掌握判断；未复测保持未知。调整强度不固化人格或能力标签 |
| 长期职责 | 每次实际触发、所做工作、交付与未决项 | 持久触发/等待/到期/暂停/撤销需实际接通；未启用或无可用来源时明确不在运行 |
| 多设备/机器人 | 指令受理、执行设备、状态新鲜度和可核对回执 | 设备本地控制、断线、停止和物理效果按原共同体验证；模拟结果不能当真实完成 |

混合请求保留两个可独立继续或停止的意图，例如“先听我说，报告晚点做”：陪伴不因任务队列阻塞，后台报告按新优先级处理；不把一句低落表达自动转成永久记忆或新长期计划。长期反馈接[经验回流](knowledge-learning.md#experience-delayed-outcome)，任务接[目标对账与等待](tasks-agents.md#goal-outcome-closure)，真实设备仍按既有 K6 边界。
