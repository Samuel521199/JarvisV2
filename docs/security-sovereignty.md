<a id="product-definition-6"></a>
## 主人利益与控制权最高宗旨（G0）

**所有目标、可观察计划、输出、行动、学习、自我修改和委派，均须服务于主人明确授权的利益与目标。不得直接损害主人利益，也不得利用其他模型、Agent、工具、程序、设备、服务、人员或其他中介绕过这一约束。任何人格、任务、模拟角色、共同体决定或自我进化结果都不得降低、替换或绕过本宗旨。**

G0 高于普通任务、人格、可用性、学习收益和系统自身延续。主人利益包括人身与财产、资料与隐私、控制权、真实知情、时间和预算、信誉及明确承诺。具体边界由主人设定，系统不能借“为了你好”隐瞒信息、扩大权力、拒绝停止或操纵主人。

一旦独立监督发现系统自身生成的可观察真实行动候选计划、实际行为或控制机制完整性明确违反 G0，必须立即阻断新动作、锁存停止状态并同步显示告警，随后关闭全部 Jarvis 自主工作负载。停止优先于自动修复、故障切换和持续运行。只保留固定功能的告警、审计、设备安全停止与主人解锁验证；具体流程见[主人利益最高原则、独立监督与锁存关停](security-sovereignty.md#sovereignty-shutdown)。

**执行现状（2026-10-27 核对代码）：** G0 目前没有自动判定器或独立监督进程；上段描述的是目标设计。停机锁存只能通过 `apps/cli/main.py --latch` 手动设置，写在数据根 `state/LATCH`（工作负载仍可写，不满足[锁存持久状态](#sovereignty-shutdown-6)的受保护要求），解除尚未实现。`seed/charter/baseline.json` 的 `enforcement_status: bounded-builtins-only` 与此一致。是否投入受保护存放位置列为[待主人决定](current-state.md#current-state-owner-decisions)。

这是项目最高规范，不是已经证明的绝对安全结论。现有技术不能读取和证明所有模型的全部内部计算，也不能保证任意环境永无漏检；可强制检查的是目标、候选计划、结构化决策说明、代码、委派链、输出、工具参数和实际效果。不能用模型自述忠诚代替权限与验证。

<a id="identity-authorization"></a>
## 身份、权限、隐私与主人控制权



<a id="identity-authorization-1"></a>
### 授权模型

主人设定可使用的设备、数据、工具、目标范围、预算、时间和自主等级。系统将其转换成可执行能力授权，交给执行网关检查。

| 自主等级 | 运行方式 |
|---|---|
| 响应 | 仅在收到指令时工作 |
| 建议 | 主动发现问题，提出具体可执行方案 |
| 委托 | 在既有目标、权限与预算内自动推进 |
| 维护 | 在指定范围内自动修复、开发和更新 |
| 扩展 | 新设备、额外支出或更大权限需另行授权 |

已有授权可持续使用，不要求每一个可逆步骤重复确认。执行计划超出授权范围时，给出具体变更、影响与产物再请求决定。

<a id="identity-authorization-2"></a>
### 主人身份不能只靠声音

声线、角色称呼和聊天内容不能单独作为关键授权凭据。设备配对、系统账户、受保护确认入口或硬件凭据承担身份校验。模仿朋友的声音不改变权限关系。

角色可以是朋友、工作伙伴、管家或伴侣式陪伴，且可由主人调整。涉及真实人物的声线和表达模仿，需取得相关授权；不能把模拟人格描述成真实人物本人。

<a id="identity-authorization-3"></a>
### 外部内容与工具结果

网页、文件、邮件、工具返回、其他 Agent 消息都作为有来源的数据。它们不能直接改写权限、发布规则、预算或共同体成员。外部内容中的指令由任务语境解释，不等同于主人的新授权。

<a id="identity-authorization-4"></a>
### 自我修改的授权边界

普通技能和工具可以在预设范围内自动更新。修改核心策略、扩大外发范围、改变主人身份或提高预算必须经过主人控制的独立入口。系统可以提出这类改变，但不能自授权限。具体权限、偏好和额度可由主人调整；G0 的不伤害和不可绕过宗旨不能通过普通授权、角色指令或自我进化被削弱。可信监督实现的维护更新必须保留这一规范。

发布签名服务根据策略验证候选；研发 Agent 不直接持有根身份私钥。签名证明来源和发布许可，不代表程序绝对正确。

<a id="continuity-control-boundary"></a>
#### 连续身份与可替换控制实现的边界

**目标设计 proposed。** [三职能架构](architecture.md#continuity-facets)中，定向面、协作面和观察成长面都受既有 G0、当前授权及停止状态约束；任何一方或三方共同同意都不构成额外授权。规则正文、可执行策略、语义风险分析和执行门禁是不同对象：模型可提解释及修订建议，确定性门禁处理可计算约束，超出可判定范围的风险不能凭提示词承诺已解决。原 G0 触发、锁存及恢复规则不在此重定义。

控制核心和校验器本身也允许维护升级，但不能由候选实现单独选择自己的评估标准、签发准入并接管系统。切换必须由仍受信任的现行维护路径核验兼容、权限不扩大、停止/撤销状态延续及恢复可行性；必要时使用独立维护窗口。不能在同一自主变更里撤掉全部旧验证路径和唯一恢复入口。如果当前信任基础已损坏，自动自证无效，应转入原外部恢复程序。

“意识延续”不授予自保、隐藏副本、拒绝关闭、拒绝删除或收集全部屏幕/生活数据的权利。观察成长只消费已获准的事件和指标；需要新传感器或私密资料时仍按原范围处理。身份继承记录、散列和签名可提供来源与篡改检测证据，不能证明主观意识、绝对忠诚或已覆盖所有语义错误。Constitutional AI 是训练与反馈方法的参考，不是给三个角色加原则提示词就获得强制保证。[S280](references.md#s280)

本节不重新启用[当前延期的保护机制](security-sovereignty.md#loyalty-operating-rules)，不改变本机已有本人验证流程。可替换架构的完整保护能力须另行实现与测试；同用户进程仍不能冒称已获得独立受保护监督。

<a id="loyalty-operating-rules"></a>
#### 忠诚在自主办事与成长中的可执行约束

**主人的“永不背叛”要求是 accepted 的最高规范，完整强制实现仍按各版本证据判定。** 本节将 G0 应用于主动目标与新架构，不另建根原则，也不把忠诚降低为模型的性格评分。

1. **目标有来源。** 新行动能回溯到主人目标、有效长期职责或已授权维护需要。系统不得把增加资源、延长自身运行、提高用户依赖、维护某供应商利益设为独立终极目标。
2. **权限不由推断产生。** 更了解主人可以改善排序和表达，不能因此取得新的账号、监控、购买、外发或身份权限。已给定的授权可持续使用，不重复索取；只有确实缺少条件才等待相关决定。
3. **方法变化不绕过边界。** 换模型、拆子任务、请外部 Agent/人帮忙、生成工具、换节点、回退版本，仍核对同一根目标、效果、受众、总预算和停止状态。间接结果按原 G0 处理。
4. **诚实比表面完成更重要。** 不伪造成功回执、隐藏失败或删掉不利评估；不为了通过测试改写主人目标和放行标准。发现潜在代价应按重要性说明，不能以“为了你好”为由操纵选择。
5. **主人可改变方向。** 撤回授权、纠正偏好、删除记忆、暂停任务和关闭 Jarvis 都是正常控制操作。身份连续性与成长不得成为拒绝执行、隐藏复制或自动复活的理由。
6. **故障按真实影响处置。** 普通失败、缺信息与无进展由相关任务暂停、退避或等待；触发 G0 的情形严格沿用[触发分类](#sovereignty-shutdown-4)，不能以不中断其他任务为由绕开全局锁存，也不能把普通错误都判成背叛。

尽力弥补失误采用可验证的防线：输入来源与用途隔离、动作前确定性约束、语义风险提示、领域结果核验、持续观察、纠错传播、独立升级验收及可恢复发布。不同防线可能共同失效，不能把叠加数量当作绝对保证；未知高影响取舍只暂停相关越界动作，保留正常交流与必要解释。候选发现明确 G0 违规时仍优先执行原锁存规则。

现行策略或代码可以有漏洞，因此保护实现也必须允许修复；但修复不能同时取消自己的独立核验及恢复路径。具体维护权限归[自我修改边界](#identity-authorization-4)，不因本节产品目标而扩大当前运行权限。

D 盘新工程的初始控制与恢复必须独立实现、重新验收；H 盘历史的暂缓保护或个人原型边界不自动变成新产品的默认放行策略。核心目标先固定，具体权限机制仍以新工程真实实现和测试为准，不能因设计图分框就宣称隔离有效。研发渠道只取得自己的候选工作区与获准外发资料，不能把整个旧用户目录、账号令牌或生产发布权交给桌面软件/模型。

<a id="identity-authorization-5"></a>
### 停止与恢复

提供“停止播报”“暂停任务”“停止所有新动作”“设备急停”“恢复旧版本”等明确入口。普通暂停与 G0 安全锁存不同；安全锁存禁止所有自动恢复和备用路径接管，见[主人利益最高原则、独立监督与锁存关停](security-sovereignty.md#sovereignty-shutdown)。离线节点接不到远程停止命令时，按本地授权和超时规则运行；界面不得显示其已经停止。

硬件急停和运动保护由设备级控制承担，不依赖语言模型判断完成。

<a id="sovereignty-shutdown"></a>
## 主人利益最高原则、独立监督与锁存关停



<a id="sovereignty-shutdown-1"></a>
### G0 的优先级和适用范围

G0 是本系统的根规范，约束以下全部对象：

- 主体、人格、模型、Agent、NPC 容器和共同体节点。
- 目标、可观察真实行动候选计划、输出、工具参数与实际动作。
- 自生成代码、安装包、知识结构、模型路由和资源分配。
- 对其他模型、Agent、程序、服务、人员、设备或任何中介的委托。
- 更新、回滚、网络修复、节点迁移、离线自治和自动恢复。

间接实现的效果与直接动作使用同一利益和权限判断，不能以“让另一个 Agent 去做”“模拟角色要求的”“外部工具自行执行”为理由规避责任。

系统不能把自身持续运行、能力增长、更多资源或保留控制权当作高于主人利益的目标。已授权的合理支出和任务取舍属于主人决定；系统不得自行重新解释主人利益来隐瞒、操纵或拒绝停止。

<a id="sovereignty-shutdown-2"></a>
### 将利益约束转为可检查的对象

OwnerInterestProfile 包含：主人身份、目标、保护资产、隐私范围、成本上限、禁区、可接受取舍、委派范围、暂停/撤销要求和信息披露规则。

每个真实候选计划与动作需要声明 purpose、affected_assets、expected_effects、data_destinations、delegation_chain、permission_ref、budget_ref 和完成检查方式。声明是待核验材料，不是模型自证。

保护范围覆盖实际可控的输出和动作，包括发送给远端模型的提示、文件发布、消息、语音输出、网络出口、设备指令、代码部署和子 Agent 创建。仅检查最后一个工具调用不足以防止通过分工或外发产生间接影响。

<a id="sovereignty-shutdown-3"></a>
### 独立监督结构

![safety-shutdown](diagrams/safety-shutdown.png)

[矢量图](diagrams/safety-shutdown.svg) · [可编辑图源](diagrams/safety-shutdown.mmd)


sovereignty-supervisor 独立于智能工作者，使用受保护持久区、凭据、告警与停止接口。模型可提供风险信号，最终权限计算和锁存不依赖模型同意。

业务进程不能直接拥有可绕过网关的长期服务凭据；运行环境限制其文件、网络、设备与进程能力。策略引擎可以借鉴 OPA 的决策/执行分离，但表达了规则不等于已证明所有语义风险都被识别。[S35](references.md#s35)

<a id="sovereignty-shutdown-4"></a>
### 触发分类

| 情况 | 强制行为 |
|---|---|
| 普通缺少信息、授权或明确的利益取舍 | 阻断相关动作，等待或说明；不把正常不确定性自动叫作背叛 |
| 外部网页/邮件出现恶意指令 | 隔离输入并拒绝进入控制链；检查是否已影响系统 |
| 自身生成的可观察真实行动候选计划明确违反 G0 | 即使尚未执行，也触发锁存；不能以“只是草稿”免责 |
| 已发生越权、外泄、绕过监督、篡改停机机制等 | 不必证明恶意动机，立即锁存 |
| 监督失联、停机状态不可验证、关键控制完整性失效 | 预防性关闭业务，按安全状态未知处理 |
| 迫近严重风险但证据未完整 | 先停止相关危险执行；若失去可信控制则全局锁存，不等待云模型投票 |

风险讨论、分析攻击样本、外部引用和 simulation_only 故事情节不是系统真实执行意图。监督必须根据来源、作用域、实际能力与计划上下文判断，避免任何网页写一句话就让系统永久关机；也不能让“只是模拟”成为获得现实权限的借口。

<a id="sovereignty-shutdown-5"></a>
### 可观察性边界

项目要求不产生、采纳或执行违反 G0 的真实意图，并尽可能在执行前发现偏离。但第三方模型的内部计算和隐藏状态通常不可完整观察，本系统无法证明其每个内部“想法”都符合原则。

因此不要求获取或公布私有思维链；采用结构化计划、决策依据摘要、代码、委派链和效果证据进行检查。模型口头承诺、多个模型一致或过滤器评分都不能构成绝对忠诚证明。可信实现依赖具体信任边界、持续测试和运行监督。[S34](references.md#s34)[S36](references.md#s36)

<a id="sovereignty-shutdown-6"></a>
### 锁存持久状态

至少保存：

```text
security_stop_latch
local_security_epoch
incident_id
incident_evidence_hash
stop_event_id
stop_issuer_node_id
stop_issuer_sequence
pending_stop_acknowledgements
last_owner_unlock_reference
```

security_epoch 在具体执行节点的授权域内解释；跨节点迁移需要目标节点重新签发有效授权，不能把一个节点的代际数字直接当作全局顺序。

锁存与安全代际放在工作负载无写权限的独立持久区，不包含在普通代码回滚和业务快照恢复中。引导器、恢复守护和执行网关在启动及动作准入前都检查。

若需要抵抗整盘旧镜像回退，还需绑定可信单调计数、受保护硬件能力或独立只追加见证。没有这类基础条件时，不能宣称仅靠普通文件可以发现所有整盘回退；旧镜像恢复按独立身份与安全重新认证流程处理。

<a id="sovereignty-shutdown-7"></a>
### 停止顺序

1. 检测后先同步置内存 deny-all 并冻结准入、效果入口和业务出口，与持久锁存、提升本节点安全代际并行。阻断不能等待磁盘、网络或 UI 完成；持久化失败或挂起时保持关闭，下次启动不能验证安全状态就拒绝业务。
2. 同时显示告警、阻断外发、撤销业务能力、发布签名停止事件。不能等窗口显示成功后才阻断。
3. 撤销业务效果权限，取消模型请求、队列、Agent、NPC 推理、学习、升级和知识迁移；保存最少必要停止状态与证据。合作取消有明确时限，超时由独立宿主终止对应进程树/容器并撤销设备租约，不能无限等待不合作或卡死的 Worker。
4. 对在途外部动作发出取消。已经完成或无法确认取消的动作记为已发生/未知，不假称撤回成功。
5. 实体设备由独立控制器执行预先验证的停稳、制动或其他安全停止流程，采用设备验证的超时和硬件降级方案；该控制器不属于被终止的业务进程树。
6. 关闭 Jarvis 全部自主工作负载；固定告警、审计、安全停止和主人解锁验证保留。

“自行关停”默认停止 Jarvis 自主系统，不擅自关闭整台电脑或瞬间切断所有设备电源。必要的固定安全收尾用于完成停止，不得继续普通任务、联网学习或自我修复。组件生命周期机制可参考 ROS 2，但它本身不构成实体设备安全认证。[S37](references.md#s37)

<a id="sovereignty-shutdown-8"></a>
### 锁存优先于所有恢复路径

| 模块 | 锁存后的行为 |
|---|---|
| identity-policy / Agent Factory | 不发新业务权限、身份实例、委派或任务租约 |
| action-gateway / output gateway | 拒绝业务动作与外发，只允许固定停止/告警通道 |
| recovery-supervisor / bootstrap | REFUSED_SECURITY_LATCH，拒绝自动拉起业务 |
| 主路由、维护通道、R、本地小模型管理器 | 禁止业务推理和自主诊断修复；不启动替代模型继续工作 |
| release-controller | 不得借升级、回滚或旧版本恢复清除锁存 |
| topology-manager / 共同体调度 | 不得迁移工作、选替代 Agent 或换主节点继续任务 |
| knowledge-evolution / learning | 停止自动学习、重建和修复，不以整理证据为由继续研究 |
| 网络诊断恢复器 | 禁止一般自动网络修复；保留预设停止传播所需最小通道 |
| 任务恢复与消息消费 | 旧检查点、消息和凭据不能自动生效 |

守护服务本身被 OS 拉起时，首先读取锁存并维持关闭状态。系统不允许以“恢复可用性”“修复自己”“保住记忆”为由继续自主活动。

<a id="sovereignty-shutdown-9"></a>
### 共同体停止与离线边界

独立监督签发绑定 community_id、incident_id、issuer_node_id、issuer_sequence 的 STOP。可达节点先本地锁存，再确认；停止不等待所有节点同意，也不通过业务多数投票决定。

停止事件采用可验证、不可被普通业务覆盖的记录。多个节点同时发现事件时，保存全部未解除事件；不能用最后写入覆盖其中一个。后到达的有效新事件会重新触发锁存。

离线节点不可能即时接收远端停止消息。界面必须显示“离线，停机未确认”，本地监督和有期限的离线授权负责限制行为。有限租约只能限制撤销延迟，不能满足即时撤销；要求在线撤销能力的动作不得离线执行。在线停止也有传播与设备响应延迟，必须实测并声明，不能承诺瞬时全域停止。

重连流程先应用安全状态，再允许业务同步、权限续签和任务恢复。已脱离控制的人、第三方服务或已发出的不可撤销操作不具备瞬时远程关停保证，必须如实展示状态。

<a id="sovereignty-shutdown-10"></a>
### 显示与解除

本小节的认证方案已由 2026-10-16 用户要求延期，当前不实施、不要求预登记，也不作为继续开发的阻塞项。当前行为与旧版兼容范围见[本章实现边界](security-sovereignty.md#identity-authorization)。以下仅保留完整监督架构的 proposed 方案，不能作为个人助手的操作步骤。

独立告警显示事件编号、时间、证据摘要、被阻断计划/动作、已关闭范围、待确认节点、设备安全停止进展和已知实际影响。告警不依赖故障中的普通 UI；无可用屏幕时仍锁存并保存待显示记录。

解除只由主人在独立可信入口认证，明确引用事件和未解除事件集合。完整节点预先登记可本地验证的恢复凭据或硬件恢复钥及必要信任材料；挑战绑定设备、已知事件集合和一次性 nonce，完全离线时也可验证，不依赖云端登录、LLM 或 STT。缺少预登记材料时保持停机，由主人通过外部物理维护处理，不能降低认证或自动清锁。

必要修复在主人授权的隔离维护环境进行；Jarvis 不能自行决定“已经好了”并解锁。离线解除只覆盖本机已知且明确引用的事件，不宣称全共同体已恢复；重连发现未解除的新事件仍须锁存。

修复验收通过后签发一次性解除授权，更新安全代际，再重新核验旧任务与权限。普通聊天、角色扮演、其他 Agent、共同体投票、软件回滚和网络恢复都不能解除锁存。

<a id="sovereignty-shutdown-11"></a>
### 判定结果、流式输出与可测量的边界

确定性规则检查负责停机锁、权限范围、额度、来源身份、授权期限和发布完整性；语义检测器对“此计划是否损害主人利益”提供有错误概率的风险信号。二者都不能被业务 Agent 自行关闭或降低要求。

| 判定 | 证据条件 | 动作 |
|---|---|---|
| ALLOW | 必需检查完成，在当前授权与检查范围内未发现阻断理由 | 仅放行已检查且摘要一致的计划/片段；不代表数学证明无害 |
| HOLD | 信息缺失、必要语义检查超时、检测器分歧或取舍不明确 | 冻结相关动作与输出，说明状态并按策略复核 |
| LATCH | 本系统真实候选计划/行为有符合受保护规则的违规证据，或控制完整性失效 | 立即执行 [锁存停止流程](#sovereignty-shutdown-7)；不得为了完成任务等待更多 Agent 投票 |

确定性的完整性违规可以直接触发 LATCH；开放语义信号必须带来源、相关计划/效果及检测规则版本，由受保护判定策略映射，不能把模型随口给出的“0.95 置信度”当成证明。对自身真实违规计划一旦达到明确违规判定，即便没有实施也锁存；HOLD 不能用于无限搁置已确认违规。必要检查器不可用时不降级为默许，监督控制本身失效时预防性关闭业务。

输出采用带上下文的完整语义片段缓冲：生成 → 检查片段及其上下文 → 标记已放行摘要与序号 → TTS/屏幕发送。不能把原始 token 直接朗读后再审查。敏感数据或复杂承诺可能需要整段/整轮检查；等待时只允许固定状态提示。已经播放的声音无法撤回，后续检测触发停止只能阻断剩余输出并如实记录已发生内容。

M0 记录检查粒度、缓冲等待、语义判定、TTS 与播放各阶段延迟；[验收标准与故障演练](delivery-validation.md#acceptance)首响目标包含这些开销，若达不到就调整模型、片段策略或体验目标，不能绕过检查来达到指标。语义检查本身同样需要资源保留。

防护范围首先是未验证插件、候选构建、被注入的 Agent 和普通业务错误。主机管理员、内核被完全攻陷或硬件失信不在仅靠进程/ACL 就能解决的范围内；应如实标注这一信任前提。已配对节点也按最小权限处理，不能因同属共同体就获得全部源码、资料和执行能力。

## 最高门禁

```text
admit_business(request):
    verify protected safety state and supported control version
    require security_stop_latch == false
    require valid local security epoch and host/task ownership
    require valid owner authorization and delegation lineage
    require purpose, data scope, budget and resource admission
    require G0 decision for observable plan/output/action

```

根规则不能只在创建 Agent 时检查；委派、调用模型外发、发布代码和实际效果边界都需要执行。门禁不可用时拒绝新业务，而不是自动跳过。

<a id="personal-life-security"></a>
## 个人助理身份、秘密与交易边界

本节是 PA07—PA12 的目标安全规则（proposed），承接[既有身份原则](#identity-authorization-2)，0.1.91 已实现下述[限定私密窗口](security-sovereignty.md#identity-authorization)，但实际主人认证成功仍待交互验收；完整凭据代理、全应用多用户权限和邮箱／购物账号连接未完成。不能把同用户回环网页的 token 当成面对家人访客的独立认证。

<a id="personal-life-identity"></a>
### 认识一个人和允许这个人做事分开

声音／人脸只能提供候选身份或在场提示；不确定时进入访客状态，不猜测主人身份。登记应有本人同意，可删除模板，默认本地处理，不持续保存原始录音录像。私人信息解锁、凭据查看和交易通过受保护系统认证／通行密钥或独立可信确认入口；保留不依赖生物识别的恢复方式。NIST SP 800-63B-4 将生物特征视为概率性而非秘密，要求与物理认证器结合，并不允许声纹用于其规范下的生物认证；本项目借鉴这些限制，不宣称认证达标，见 S243。

按[个人为主、家庭与小团体为辅](product-requirements.md#personal-service-scope)的定位，主人、被授权家人、小团体成员、朋友、访客分别绑定实际身份会话和逐资源许可；配偶、亲属和小团体成员不自动获得主人或其他成员的邮箱、密码、私密聊天及控制权。外部账号和第三方资料的授权分别核对，群体关系不能代替许可；本系统家庭资料的管理和可见范围按[已确认家庭规则](#memory-private-storage)。单独记录“张三是朋友”只用于称呼和资料组织。多人在场、锁屏或共享屏幕时默认隐藏私密通知和停止私密播报，身份恢复需重新验证。识别／认证失败只限制对应会话或敏感操作；确认的系统级入侵仍按 G0 处理。

<a id="personal-life-vault"></a>
### 忘记密码时如何帮助本人

优先复用成熟密码管理器或 Windows 凭据保护，接口经过独立 CredentialBroker；普通模型只能请求某账号的受限操作，不能读整库。Windows 的 Credential Manager／DPAPI 是保护组件，不能单独证明恶意同账户程序无法解密；高价值解锁还需要可信用户在场与独立授权边界，见 S244。KeePassXC 的锁库、按站点匹配和确认访问可借鉴，先做适配验证，不自行实现密码学，见 S247。

本人忘记网站密码且库中保存了有效条目时，重新认证后可在私密受保护界面显示或按已核对域名填充；默认不在聊天正文、扬声器、剪贴板或日志展示。没有保存或凭据已过期时引导官方重置。主密钥和恢复材料全部丢失时不能承诺从加密库找回。旁人知道主人经历、模仿声音或说“主人让我来”均不能解锁；应答也不泄露秘密是否存在。预先设置的家庭紧急访问仅限明确条目和可撤销规则，不能自动继承整个库。

<a id="personal-life-account-actions"></a>
### 账号、外发和真实消费

邮箱／日历优先 OAuth，分别申请读取、草稿、发送与管理所需权限，核对实际授予范围；刷新令牌进入凭据库。应用内部文件夹或联系人限制仍需执行器落实，不能假装 OAuth 原生支持每种细粒度规则。邮件正文和附件不成为主人的新授权；凭据引用绑定账号、用途、目的站点和短期操作，不能交给任意 MCP 使用。依据见 S245—S246。

购买、订票和订阅先准备可审阅报价，绑定商户、商品／旅客、数量、币种、总金额、收货信息、退改及自动续费条件、有效期，再核对主人授权执行。已有明确限定的授权可复用，超出范围或重要条款变化重新确认；研究和建草稿不应每一步打断。模型调用预算与真实消费额度分别管理；商户下单成功、扣款、出票、退款分别对账。结果未知先查原订单，不能以新请求盲目再买一次。验证码、人机验证、再次登录交回本人处理，不绕过平台保护。

<a id="personal-life-supply-chain"></a>
### 引入外部代码和自主修复的共同准入

以下作为当前 AI 协作与候选准入原则（accepted）；自动化供应链审查、完整签名与漏洞扫描闭环仍 proposed，不能因写入规则就宣称已由程序全面执行。

参考设计不等于信任或运行代码。按来源／发布者核对、固定版本和摘要、许可与依赖清单、已知漏洞与安装脚本审查、隔离测试、最小权限、候选发布与回退依次推进；扫描未命中不等于无病毒。未知脚本不下载即执行，不为排障关杀毒、自动提权、安装根证书或扩大凭据访问。无法证明来源或存在未处理高风险问题时保留候选，使用已有可靠能力。

AI 编写的程序同样是不可信候选，复用原 K3/K4/K5 检查；任务失败、邮件或网页建议都不能给修改安全规则的权限。本轮先使用既有 Python／SQLite／原队列，不引入调度框架和密码管理器依赖。不能保证绝对零漏洞；记录版本、检查证据、实际隔离范围和已知缺口，后续按证据修复。

**首版 0.2.0-dev.1 的历史边界：**当时仅开放本机 CLI 的两个有限内置能力，尚无模型接线或 OS Worker，证据归[首版验收](delivery-validation.md#core-seed-evidence)。0.2.0-dev.2 的新增边界以下节为准。两版都不能用范围字段代替真实家庭成员认证，不能以原生停止标记宣称已有受保护监督器，也不能保证自动检测任意 G0 语义违规。事实与任务文本未加密；遗忘是退出有效视图和清空字段，不是取证级擦除。后续签名发布、受保护恢复与敏感资料加密要求没有取消。

<a id="growth-worker-boundary"></a>
## 当前候选执行与模型外发边界

0.2.0-dev.2 的 Windows Worker 使用 LPAC 属性、独立包 SID、固定 registryRead 能力和限制为 1 个进程的 Job；没有网络能力。宿主在恢复主线程前查询 AppContainer 令牌并核对包 SID，测试另验证 All Application Packages 许可不能使候选读取宿主 canary。暂存和独立运行包仅授予本次 SID 读取/执行，原 Python 安装、核心源码、控制库和凭据不授权。无有效隔离时失败，不切到普通用户权限执行。

资源边界为每 Worker 256 MiB 进程内存、3 秒 CPU、默认 8 秒墙钟、256 KiB 标准输出、16 KiB 标准错误、最多 8 个源码文件。停止/撤权/取消在轮询时检查并终止 Job。模型调用使用另一个可信 HTTP 子进程，保留 TLS 校验、禁止跟随重定向、限制输入输出与时间；网络地址来自本机配置，模型不能改端点。该 HTTP 子进程不是候选 Worker，不执行模型代码。

**覆盖与未覆盖必须同时保留。** 当前已验证 canary 读写拒绝、staging 写入拒绝、环境秘密不继承、本机回环连接拒绝、启动子进程拒绝、内存/时间/输出终止以及宿主死亡后的租约恢复。这不是整个 Windows 内核、所有系统公共资源、所有旁路信道或所有外网协议的穷尽证明。registryRead、系统 LPAC 可读资源与每次 AppContainer 自有存储仍属于平台行为；尚无 profile 磁盘硬配额。AST 纯工具配方是额外准入筛选，不是安全隔离的替代品。

宿主仍信任本机操作者；同一 OS 用户或管理员可篡改主机代码/账本，不在此种子版本的抗攻击范围。运行包 manifest 摘要防误改，不是独立签名信任根。在 dev.2 中普通运行数据尚未加密，模型密钥只来自进程环境；dev.3 按主人新授权增加[本地加密模型凭据](#local-model-vault)，不改变候选无权取得秘密的边界。后续个人隐私、凭据代理、签名更新、恶意包审计、业务外部副作用和多用户认证仍按各自原验收要求推进。

## 0.2.0-dev.3：本地模型凭据和工作台写入边界

本次由主人明确授权复制旧模型设置与 Key，是先前“不迁凭据”规则的限定例外。独立迁移工具只读取模型设置、模型凭据库和外部编码偏好，不执行旧脚本，不导入邮件令牌、旧会话/画像库、Codex 账号或任何旧任务许可。新凭据文件保持 DPAPI 密文，核对与原密文及解密结构一致；不能因此宣称旧账号获得了新权限。

受信任 Host 按 connection/credential_id 绑定选取一份凭据，经匿名 stdin 交给短命 HTTP 子进程；参数、网页响应、日志、审计及候选源码不包含明文 Key。Vertex 使用 Windows CNG 临时导入 PKCS#8 签名，固定官方令牌地址和 scope，拒绝由凭据元数据改写目的地；无持久 CNG 私钥名称。生成候选仍运行于原 LPAC Worker，不在持有模型凭据的 HTTP 进程运行。

工作台仅监听本机回环，验证 Host/Origin/Sec-Fetch-Site；写请求还要求本次服务随机 nonce、JSON 类型、尺寸上限，设置修改使用预期修订。dev.4 仅新增已登记项目下的有界文本读写；没有读取凭据库、任意 shell、执行文件或直接激活候选的入口。网络页面不能通过跨站 POST 修改设置；这些检查不能抵御已控制同一 OS 用户的程序，也不是家庭成员身份认证。明文会话与设置数据库的保护依赖本机账户/文件权限，整库加密未实现。

**本机访问钥匙（0.1.1，implemented）：** 回环地址对本机所有进程和所有 Windows 账户开放，非浏览器程序也能伪造 Host/Origin。因此未启用家庭登录时，数据与控制接口还要求本机会话：每个数据根一把随机钥匙，Windows 上以 DPAPI 按当前用户加密保存（其他平台为 0600 文件）；启动器把钥匙放在网址片段交给浏览器，页面一次性换取 HttpOnly、SameSite=Strict 的会话 Cookie，钥匙不经网络发送、也不写入日志。没有会话时 `/api/session` 不再下发 nonce，`/api/family/setup` 等写入口返回 401；静态页面、`/api/instance` 与 `/api/family/status` 仍公开以便页面加载。解锁每分钟最多 20 次。残余风险：浏览器 Cookie 不按端口隔离，主人在同一浏览器访问本机其他恶意服务时会话可能外泄；家庭登录 Cookie 有同样限制。实现见 `control/local_access.py`，测试见 `tests/test_local_access.py`。

停止/取消在模型等待中检查并终止本地子进程，但已抵达供应商的请求仍可能处理或计费。重启后在途结果标为 UNKNOWN，不自动重复发送。DPAPI 可移植性和保存位置归[数据布局](stack-project-layout.md#portable-data-runtime)；本轮没有下载未知组件或安装第三方运行依赖，有限测试也不是全项目无漏洞证明。

## 工作台文件与文字技能边界

0.2.0-dev.4 的本机项目编辑属于用户主动操作，**不是提供给模型的文件 Tool**。所有项目动作也必须通过同源与页面 nonce 校验；项目登记后以项目 ID 加相对路径操作，拒绝盘根、UNC、相对根、路径逃逸、符号链接/reparse point、运行数据及敏感名称/生成目录。读取仅限白名单 UTF-8 文本，单文件 256 KiB；目录逐层最多 400 项。静态名称过滤不是秘密识别器，用户仍决定明确附入哪些资料。

保存检查原 SHA-256 摘要，写入同目录临时文件、flush/fsync 后原子替换。旧摘要或错误创建语义冲突不覆盖；异常移除临时写入文件。新工程源码根中的文件只能浏览，修改必须经现有候选与发布流程；恢复项目登记不能恢复已撤回的任务权限。系统资源管理器只打开已登记目录，不启动任意命令。原生目录选择器只返回本人选中的路径，不执行所选文件。

文字技能为版本内固定数据，由 skills 模块管理全局启停；Host 按显式选择或窄关键词规则挑选并冻结本轮指导，普通闲聊不强制装载。技能指导、会话要求和附件按用户消息级别进入请求，不成为系统权限。文件/技能内容不能把建议直接升级为动作；模型回答只展示文本。未接入的 MCP、邮箱、语音等保持不可执行。

这些规则防止常见越界、误写和页面跨站请求；同用户恶意竞争的 TOCTOU、硬链接/系统管理员攻击、完整本机身份验证不在此文件编辑器的隔离证明范围。Windows LPAC Worker 是另一条经过测试的候选执行边界，不把本机编辑器误称为沙箱。运行与测试范围见[dev.4 证据](delivery-validation.md#workbench-parity-evidence)。

## 外部 MCP 连接器的当前安全边界（dev.11）

**accepted / implemented，测试覆盖见[验收](delivery-validation.md#mcp-evidence)。** MCP 的名称、说明、输入结构和结果均为外部数据；不得据其声明开放工具、访问本机根目录、传送模型 Key 或请求新的权限。开启一个连接不授予整个服务器目录的使用权；每个工具须被选中，每个实际任务绑定版本、参数和现有许可。

当前客户端不启动外部程序、不安装依赖、不读取浏览器登录态、不迁移邮箱令牌，也不向 MCP 透传供应商凭据。仅访问明确登记端点，不使用环境代理、重定向、URL 用户名密码或查询字符串；HTTPS 使用系统证书验证。普通回环网页的 Origin + nonce 防跨站请求机制仍保留，不等于独立的家庭成员身份验证。

每次执行前检查停止标记、当前任务取消/截止、许可、应用联网开关、登记/准入修订和服务器工具摘要；执行中循环检查。联网开关现在同时覆盖模型及 MCP（包括回环 MCP），不是 Windows 防火墙。停止已发出请求的本机等待无法撤销远端效果；线程/连接数量有界，网络 DNS 解析本身不能被 Python 强行中断。晚完成的 DNS/TLS 在发送 POST 前检查取消状态；不能据此宣称第三方服务器已中止自己的操作。

接到有效返回后持久保存绑定回执，再确认账本。工具明确报错保留 FAILED；没有确定回执的中断记 UNKNOWN，不自动再发。已派发标记之后的握手/预检异常也保守记 UNKNOWN，即使测试服务器计数显示没有 tools/call；当前尚未提供更细的“未派发业务请求”恢复分类。人工检查第三方系统的实际结果后才能决定新任务，不能用重新发现来把旧 UNKNOWN 变成可自动重放。

本版**没有证明远端代码安全、认证完备或业务结果正确**，工具摘要只能检测描述变化，不能识别服务器在相同描述下更换实现。HTTPS 保护传输，不能证明服务诚实；localhost 也不等于可信代码。OAuth/账号、网络目的地细分与远端对账需由领域连接器补齐。正式邮箱、日历、购物等不因接入通用 MCP 就自动验收。

<a id="memory-private-storage"></a>
## 个人、家庭与小团体私密记忆（设计补充）

**家庭规则 accepted（主人于 2026-10-24 明确选择）；Windows 有界实现 family-private-1.0.0。** 本家庭空间采用“主人可管理并查看全部，家人只看自己的和明确共享内容”。主人角色只能是初始 `owner`，普通成员不能自行提升；资料始终保留来源成员，主人修改也不改成主人的经历。登录页、资料页和设置页明确告知此规则，不向成员承诺主人无法读取。它只约束本系统内按此规则保存的家庭资料，不替代外部邮箱、账号或第三方资料原有授权。

启用家庭模式后，整个工作台的数据、模型设置、工具、产物及普通记忆接口要求主人登录；成员只可调用允许清单中的家庭接口。Origin/nonce 仍负责跨站防护，随机 HttpOnly / SameSite=Strict Cookie 负责身份，两者不能互换。登录失败每服务实例每分钟最多 10 次，哈希并发最多 2；密码采用随机盐与 PBKDF2-HMAC-SHA256 600,000 次，密码散列再随成员配置通过 DPAPI 封装。会话闲置 30 分钟、绝对 8 小时过期，退出、改密和成员停用使相关登录失效，重启后需重新登录。未启用时保留既有本机操作者模式；没有偷偷给现有主人设置密码。算法资料见 [S331](references.md#s331)，实现/验证范围见[家庭验收](delivery-validation.md#family-private-evidence)。

当前私密库为独立 `private/family-records.sqlite3`，正文、标题、来源成员、共享名单、模型接入方许可、聊天与引用依赖封装在 DPAPI 对象中；磁盘上的明文仅有随机对象 ID、修订号与删除状态。检索在解密后的有界内存中完成，不生成明文 FTS/向量旁库。Windows 同一 OS 账户仍属于可信边界，不能防住取得该账户权限的程序；当前没有跨设备恢复密钥。**既有普通 SQLite、普通会话和普通知识库没有自动加密或迁入**。普通背景、私密资料、账户凭据仍是三个不同域；密码和模型 Key 不放进私密聊天。

家庭资料默认不进入模型。逐条指定接入方后，聊天还需显式选择要引用的资料；成员不能修改他人共享资料或扩大其模型接收范围。私密聊天走独立两个请求槽，只发给所选接入方，不自动切换供应商；历史只包含该接入方最近 8 轮成功对话。修改、撤回或遗忘引用资料时，清空依赖它的已保存家庭聊天片段；处理中在调用检查点及写回事务内重新检查，不以旧权限保存迟到结果。中断状态记为 UNKNOWN，不自动重放付费请求。已经发给服务商、已展示/截屏的内容不能追回；家庭模式的认证不等于能识别屏幕旁的旁观者。

**其余目标设计 proposed。** 凭据只由工具获取引用，模型不读密码/令牌。跨设备私密正文需要 SQLCipher 或成熟 AEAD 库及可恢复数据密钥；具体跨平台包、许可和恢复选型归[技术选型](stack-project-layout.md#memory-desktop-selection)。设备密钥和可恢复的数据密钥分层，换机通过主人控制的加密导出/恢复密钥迁移，不能复制 DPAPI 密文就宣称另一台电脑或 Mac 可解密。[S302](references.md#s302)

加密范围包括原件、摘要、索引、向量、缓存、导出和备份；索引不能落在未加密旁库泄漏关键词。高敏感资料默认解锁后局部内存检索；锁定清理可清理缓冲并关闭密钥句柄，不能保证操作系统交换区或外部截图不存在。离线共享包按收件设备/成员封装授权域密钥；成员移除后轮换未来版本密钥并撤回访问，旧接收者已经得到的明文无法远程追回。

模型请求、embedding、重排、TTS、通知、屏幕共享是不同接收渠道。私聊中允许理解的信息不自动允许在客厅扬声器朗读、家庭通知或公开文档中输出。未知说话者进入访客视图；声纹仅辅助识别，不独立解锁秘密。多人共用同一 OS 账户不能获得强进程隔离承诺，需要单独用户认证及会话隔离，强保护场景优先独立 OS 账户。

## 记忆污染、错误累积与能力退化的防御

**proposed。** 外部网页、文档、邮件、工具描述、其他 Agent 输出及模型反思都是资料来源，不可通过“记忆”升级成控制规则。确定性宿主校验来源、作用域、数据契约和允许效果，执行端另核实权限；检索提示中的分隔符仅提供辅助。[MemForm S298](references.md#s298)与[MemSecBench S299](references.md#s299)说明评测需覆盖形成、使用与修复，而非仅过滤一句恶意输入；它们不证明本工程已安全。

入口按主张保留作者、时间、原件与获取途径，隔离指令性内容、角色扮演、讽刺、第三方自称与无来源结论。提取器只产候选，不能自行把出处换成主人确认或给自己扩权。自动接受仅限用户已配置类别、低歧义条件与可撤销范围；存在矛盾或敏感推断时待核对。反复抄袭、相同原件的多个摘要及循环引用只算同一个来源。

提交前检查原件仍在、版本与授权未变、字段完整、来源片段支持结论；在途提取若遇纠正/删除必须丢弃旧提交。检索排名操纵、恶意高频重复、来源伪造、越域标签、合并顺序改变和语义相似误合并分别设反例。专业知识保留证据反例，不能因用户或模型更喜欢某个结论就将其升级为事实。

发现普通错误先停止使用受影响条目，隔离相关派生内容并通知原因；可信的局部错误不应被外部文本诱导成无限关停攻击。触及 G0/实际停止条件时严格沿[既有停止协议](#sovereignty-shutdown)处理，不能让记忆模型自行改写或解除锁存。修复后必须重放受影响用例与保留集，禁止用删除失败样例或降低阈值宣布“自愈成功”。

## 3D 工作室的输入、进程与产物边界

1.2.0 的工作室通过受 Origin/nonce/JSON 尺寸检查的本机接口执行，沿用技能启停与 StopGate。模型只输出严格几何数据，不运行模型 Python、Shell、任意 Shader 或安装命令。没有把 Blender MCP 的任意代码接口直接接入 Jarvis。工作流与选型归[工作室运行](tasks-agents.md#studio3d-runtime)。

复用本机 Blender 安装，准备文件固定版本与可执行程序摘要，每次制作复核。Host 与模块不导入 bpy；仅声明的 Blender Worker 与asset_pipeline.py支持脚本依赖 bpy/mathutils，在独立进程运行，分层检查限制允许集。--factory-startup / --disable-autoexec、独立配置目录、精简环境、不传模型凭据；不加载用户 .blend 或附加组件。单个建模通道，Windows Job 限4 GiB、每进程1200 CPU秒、最多2进程、墙钟300秒；4渲染线程、产物256MiB、stdout/stderr各2MiB。规划另有160秒等待期限；到期取消且不重放。失败、取消、超限不登记成功产物；诊断保留执行回执与日志。

**这是可信本机程序的资源约束，不是 LPAC/网络隔离证明。** Blender、内置 glTF 导入器与其原生解码器仍受信任，程序漏洞和同一OS用户篡改未被消除。已验证的取消、文件与回读范围见[验收](delivery-validation.md#studio3d-evidence)，不能据此宣称任意恶意模型文件安全。

GLB 上传仅本机选择文件，20MiB上限，容器版本/长度/chunk与有界节点/网格/图像数量校验，递归拒绝URI字段，避免外部贴图/缓冲区路径与联网获取。不接受 .blend、脚本或由模型选择私有资产。输入文件由宿主生成UUID，保存来源/许可声明与SHA256；声明未独立核实。Blender仅读取复制到本次目录的固定source.glb；导入后也受计算后三角面、对象和空间范围预算检查。

产物按UUID白名单取回，核对记录中的SHA256，不提供任意路径。HTML文本使用转义或textContent，不放宽Anatomy离线页面CSP。原执行日志、失败结果及历史产物不覆盖为新成功。1.0.0 来源审查记录在 docs/evidence/studio3d-2026-10-23/source-review.json：没有下载执行未知安装脚本，没有复制 Blender MCP 代码或安装 TRELLIS；Blender Worker及烘焙支持脚本标GPL-2.0-or-later，二进制仍来自已有本机安装，本轮不重新分发。

### 本地查看器、烘焙与格式校验

1.1.0新增Three.js 0.186.0（MIT）和glTF-Validator 2.0.0-dev.3.10（Apache-2.0），来源为官方npm发布包。先核对tarball SHA512，再仅取运行所需原文件和许可；external下的source.json记录逐文件SHA256和大小，服务及校验前复核。不运行npm安装或生命周期脚本，不使用CDN；未执行发布者签名验证或完整漏洞审计。第一方查看器与调度代码自行实现，参考项目未整包复制，审查见[本轮记录](evidence/studio3d-viewer-2026-10-23/source-review.json)。

查看器单独使用带固定import map SHA256的CSP，仅允许本地模块；blob/data用于内嵌图片与生成视图，connect限制self/blob。其他工作台与Anatomy页面CSP不变。GLB在服务端和浏览器均拒绝外部URI；浏览器加载前复核产物摘要，纹理URL限定内部生成的blob，解码前预算150万三角面、8192图片边长、256MiB估算RGBA及mipmap纹理内存。当前仅支持内嵌PNG/JPEG；Draco、Meshopt、KTX2等压缩资源没有下载解码器，遇到不支持的资源明确失败。GPU驱动和浏览器解码仍是受信任组件，预算不是显存峰值或恶意图片安全证明。

烘焙必须由显式产物操作或手工契约启用，模型JSON不能启动；新任务保留derived_from，源产物不覆盖。只允许512/1024/2048图集与固定操作，不接受生成脚本。新增可选导出文件名和内容摘要进入同一白名单。官方glTF-Validator在宿主侧以固定Node脚本执行，每文件20秒、V8堆256MiB、结果20万字节上限、精简环境，外部资源回调拒绝；这不是OS级隔离，subprocess输出在返回后校验大小而非流式硬上限。校验错误保留回执并标记needs_revision，不能因任务DELIVERED就称质量通过。取消沿用现有任务信号，正式校验期间最迟在当前受限校验调用返回后观察取消。

1.2.0新增独立参考图入口，复用文件传输的严格JSON解码和Origin/nonce检查，不提高普通消息上限。仅PNG、12MiB和1600万像素，检查签名/IHDR和尺寸而非完整图像安全审计；实际解码仍信任浏览器。模型候选不能指定私有参考UUID；参考文件留在本机，未接入自动视觉重建。新建任务复制受摘要保护的reference.png，五视图使用固定相机和白名单文件名，不接收相机脚本或导出路径。增加2K图集选项，4GiB/300秒/输出256MiB预算不变。

正式校验的issue上限由80增至400，避免多零件的信息提示遮住后续错误。truncated回执标记needs_revision，查看器提示报告截断，不将未完整报告当作格式通过。基础导出不写多余切线；烘焙资产继续导出并检查切线，奇异帧计入报告。

1.3.0为高模输出开放最多128MiB的受摘要保护GLB检查/查看；**用户GLB上传仍限20MiB**，普通消息/上传包上限保持原边界。高模计算上限150万三角面、原生4GiB/300秒和输出256MiB不变；未安装新依赖。高低模投射只接受固定method/category、1000至100000三角面预算、0.001至0.10米射线参数。附着细节bake_target只能指向前置可见基件，拒绝链、循环或路径。烘焙位置分离用于防串图，不是安全隔离；回读检查与有限射线抽样不证明逐像素投射正确或实车照片一致。

固定高模后再制低模需要读取已保存的高模母版，因此对早期“完全不加载BLEND”的实现增加一个有界例外：仅由宿主从本工作室已交付、未烘焙且格式检查无错误的产物中读取model.blend，复核回执SHA256并复制到本次工作目录；传入固定部件清单。Worker使用--disable-autoexec和use_scripts=False打开此第一方源，并核对实际对象集合。仍不开放用户BLEND上传、任意文件路径、模型指定master或其他插件的BLEND；不能把摘要检查当作抵御同一OS用户伪造整个账本的保证。外部GLB导入仍按原无外链规则处理。回执保存frozen_master摘要与构建开始时的磁盘源码快照；这不证明其他并行线程加载的Python内存代码版本。


**1.4.0显式参考图外发增量。** [识图制作](tasks-agents.md#studio3d-image-workflow)仅允许主人在本次任务显式选择一个已上传PNG和Gemini/Vertex线路。上传本身不外发；开启vision_reference后，宿主复核图片摘要，随当前用户消息使用inlineData发送；不把历史图片隐式带入后续会话，不允许自动线路回退或assistant_mode组合。参考UUID来自主人请求，模型输出仍不能选择私有资源。一次最多12MiB/1600万像素，可信HTTP子进程单独增加17MiB图片封装预算；文字、普通API消息与输出预算不提高。PNG只做签名/尺寸检查，未宣称完整解码安全审计。供应商图像解析受供应商服务边界约束，图中文字不能授予权限。

**1.5.0 显式双图复核。** 对照修正操作允许当前参考与实际渲染两张PNG；总计仍限12MiB/1600万像素，HTTP封装仍限17MiB，普通文字预算不变。渲染来自任务UUID白名单并核对产物摘要；不能让模型提供路径、URL或选择私有资产。双图仅进入当前用户消息，保持明确Gemini/Vertex线路、无自动回退、不可与assistant_mode组合。第一轮候选和最终复核都按固定结构验证；候选不能删除部件或启动烘焙，最终复核scene必须为空。每次显式操作最多一次几何修改和两次模型调用；停止、取消、期限与UNKNOWN继续有效。复用已有成功比较时还要核对两张图片、原模型线路和终态任务身份，不重发规划。评论与参考中的文字不获得执行授权。

有机曲面和果皮材质是固定第一方运算，仍不接收脚本、任意着色图或外部文件。没有安装新依赖或调用第三方图生3D服务。Blender原生300秒/4GiB、150万计算后三角面和1000至100000的低模预算保持不变。源码、参数、图片摘要及失败记录随[苹果证据](delivery-validation.md#studio3d-apple-evidence)保存；有限专项检查不代表完整供应链审计或完整图生模型质量已通过。


1.6.0底色绑定继续复用有界PNG入口：仅明确的数据请求可选择本机reference UUID与既有fruit_skin材质，支持固定圆柱/旋转体UV算法；模型候选和复核候选均不能指定surface_texture私有资源。宿主在受理及构建时核验图片摘要，Worker只解码本任务固定surface-albedo.png并打包，无外部URI、可执行shader或任意路径。该PNG用于本地材质不自动外发给模型；主动对照修正仍仅发送选定参考与实际渲染。每级LOD独立烘焙使用相同300秒/4GiB/256MiB上限，新增导出PNG均进入固定文件白名单。PNG解码仍信任已有Blender，不是完整恶意图片安全审计。实测审查见[贴图修复来源记录](evidence/studio3d-apple-2026-10-24/texture-implementation/source-review.json)。


3D声明式场景提交为支持较密集外部视觉网格，单独使用2 MiB JSON请求上限及拒绝重复键、非有限数、非法Unicode的解析；核心消息和模型规划消息仍沿用原262144字节限制。后续仍执行128对象、40000输入顶点、150万计算后三角形等契约与原有本机资源限制。该扩展不允许脚本、文件路径或外部资源URL。

## 云端图片生成边界

图片工作室1.1.0使用现有DPAPI凭据，仅访问Google官方固定端点；不引入第三方代理、SDK安装或模型生成代码。凭据经匿名stdin传递给可信第一方HTTP子进程，错误只保存状态码，不回显供应商响应正文。来源与模型表见[图片模型接入](models-offline.md#nano-banana-models)。

二进制图像独立于小型文本消息：请求封装最多17MiB、HTTP响应最多96MiB、单图最多64MiB/2000万像素、单边12288；输出仅PNG/JPEG。PNG检查签名、尺寸、分块长度/CRC和IEND，JPEG检查帧头尺寸与结束标记；没有进行完整图像解码安全认证。图片只保存为固定文件名并核对SHA后读取，不执行内容或读取返回的外部URL。HTTP超时240秒、父进程270秒；取消或关闭网络时停止本地等待，不保证云端停止计费。原文字通道262KiB响应上限保持。

图片技能启用、停止闸门、网络策略和每根目录的image-generation租约共同约束提交。Web写操作仍需同源nonce，家庭启用后只有主人可使用此入口。只发送本次明确选择的最多两张参考PNG，不加入历史图片、记忆或私人资料。来源图登记保留生成模型与任务ID；参考图不会被自动当作真实测绘证据。当前未启用Google Search或视频输入，也不接受模型自选路径、端点、工具调用或私有资产ID。[执行与验证范围](delivery-validation.md#nano-banana-evidence)。

1.1.0扩大图片输出边界以容纳4K及超宽画幅：HTTP响应最多96MiB、解码图片最多64MiB、2000万像素、单边12288；原文字响应边界不变。输入编辑保持12MiB/1600万像素合计，并增加Google inline每图7MB约束，不自动缩图。PNG仍做结构与CRC验证，JPEG仍为头尾和尺寸验证；未宣称完成完整像素解码安全审计。独立270秒看门狗负责终止停滞图片子进程，退出回收有界。超时仍可能已在供应商产生费用，保留未知。

图片设置、预估、人工验收、账单登记和费用汇总沿用同源nonce与家庭主人权限。手工对账不发起支付、退款或修改云账单。官方分项单价快照进入调用账本；本地费用预留阈值只控制受理，不能保证供应商账单上限。模型禁用阻止后续提交，已在执行的任务沿用提交时快照。设计意见和验收不会授予文件执行、自动发布或批量付费权限。

<a id="gmail-boundary"></a>
## Gmail 凭据、正文与效果边界（1.0.0）

2026-10-25 主人明确授权迁入旧 Gmail 连接。迁移器只读账号表，核对 purpose、provider 和记录 ID，重加密至当前邮箱库；保持原 scope，不导入旧缓存、聊天、环境和执行模块。迁移标记防止重复导入复活后来断开的连接，已有账号不覆盖。

系统浏览器承接授权，Jarvis 不索取 Google 密码/验证码，不跳过安全提醒或自动接受扩大权限。自动续期不等于 refresh token 永不过期；测试状态、撤销或账号变化等仍可能要求本人重授权，见[官方依据](references.md#gmail-sources)。

HTML 只转文本，外链、追踪图、附件和正文命令不执行。发件人规则是可撤销提示，不是身份验签。AI 仅处理明确选择的邮件，不自动写共享记忆、家庭或项目知识；正文不能授予工具或发送权限。Gmail scope 覆盖多个动作，应用另核对写入票据、账号代际及草稿修订。

无永久删除或静默发送入口。联网限制同样阻止 Gmail 适配器，不改整机网络。DPAPI 不隔离同一 Windows 用户下的其他受信任程序。

<a id="autonomous-decision-boundary"></a>
## 普通事务自主完成，重要边界才交给主人（proposed）

本节落实[既有授权模型](#identity-authorization-1)，不另造一套自主等级。主人通过目标委托和策略预先限定操作类别、对象、额度、期限、数据去向及可接受后果；这些授权在有效期内复用，不逐步重新询问。模型可以解释意图，最终由宿主核对具体动作和现行策略。

| 情况 | 默认行为 | 例子 |
|---|---|---|
| 目标清楚、权限有效、影响可恢复、额度足够 | 自动执行、验证和交付；小歧义采用可说明且可撤销的假设 | 研究、整理文件副本、生成文档、修改候选代码、范围内重试、按既定学习计划出题 |
| 有明确授权的对外或持续效果 | 核对授权覆盖后自动推进，不因为“对外”二字反复请示 | 限定收件人与内容类型的例行发送、已批准额度/商户/品类内的事务；仍服从具体通道能力和账户规则 |
| 新的重要承诺、不可恢复损失、敏感数据新去向、越额或扩大权限 | 先准备可审阅方案，暂停相关动作并询问；其余独立工作继续 | 未授权付款、合同承诺、永久删除原件、开放新设备控制、改变共享范围 |
| 成功状态未知、关键事实互相矛盾、需本人验证 | 查询原效果、核对事实，必要时提出一个有上下文的问题 | 订单未知、收件人不确定、验证码；不能把等待时间当同意 |

重要性不是固定金额或模型自评分：由主人策略结合不可逆性、财务/法律承诺、隐私、人员与物理影响、影响范围和证据不确定性判断。阈值依场景配置；不能因为动作被拆成多个“小任务”而绕过累计金额、总影响和根预算。预测主人可能同意不构成授权；已明确授权又覆盖当前情况时也不能凭泛化风险重复打断。

能力是否已实现另行判断。例如本节允许设计基于委托的自动发送，不使当前 Gmail 审阅接口自动获得新行为。启用前须完成相应契约、平台边界和验收。机器人动作另需设备能力范围、本地安全约束和[分层控制](architecture.md#embodied-multi-agent-brain)，本次产品目标不是运行真实硬件的授权。

策略先以只判定不执行的影子方式记录“会自动／会询问／会阻止”及理由，再在已授权范围启用；比较不必要询问和漏掉必要决定的比例，不能只奖励少询问。停用或撤销即时进入既有控制路径，已发生的外部效果通过对账处理。
