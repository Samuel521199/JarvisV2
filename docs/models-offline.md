## 本地嵌入模型的候选与资源边界（proposed）

嵌入模型负责检索向量，与聊天 LLM、STT、TTS、声纹模型分工不同。现有 Qwen3 0.6B 聊天模型并不等于 Qwen3-Embedding-0.6B；候选调研之后，已实现本章后述的[本地模型中心](#local-model-manager-runtime)，下载并实测 E5 INT8；其余候选不因进入目录而视为已启用。优先保证中文、英文与跨语言召回，再比较资源和增强配置。

| 候选 | 官方规格与许可 | 本项目用途与待验证点 |
|---|---|---|
| BAAI/bge-small-zh-v1.5 [S102](references.md#s102) | 约 24M 参数、512 维、MIT | 中文资料优先的小资源候选；英文代码/中英跨语言检索另测，不能由中文成绩推断 |
| intfloat/multilingual-e5-small [S103](references.md#s103) | 384 维、最长 512 token、MIT；检索按模型卡添加 `query: ` / `passage: ` 用途前缀 | 多语言小资源对照；中文同样需要规定前缀，长资料切片不得静默截掉答案 |
| Qwen/Qwen3-Embedding-0.6B [S104](references.md#s104) | 0.6B、100+ 语言及代码、32K 上下文、可配置 32—1024 维、Apache-2.0 | 有更多资源时的增强候选；权重和推理成本明显不属于最小档，长上下文也有实际计算成本 |

这是候选用途，不是本机质量排名。BGE/E5 原始权重、ONNX 或其他量化导出分别锁定修订、许可证、分词器和推理运行时；量化后的中文召回要重测。先用 CPU 得到可重复基线，再按目标机器验证加速后端；开发机的集成显卡不能自动等同 CUDA 环境。实际下载体积、常驻/峰值内存、构建依赖和离线加载成功率均写进测量报告。

向量容量计算与设备预算统一见[记忆资源模型](delivery-validation.md#memory-resource-envelope)，不能当作端到端内存实测。缩小 Qwen 输出维度可以减少向量存储，不会按同一比例减少模型权重内存；减少片段数量也可能丢失召回能力。

模型升级时新旧向量空间隔离，使用独立索引构建并追平增量，验收后切换检索指针；不能把相同维数的不同模型结果混进同一空间。旧模型不可用时回退关键词检索，不阻塞事实写入；退役规则沿用[知识迁移](knowledge-learning.md#memory-selection-design)及[组件生命周期](#local-survival-5)。

<a id="model-routing"></a>
## 双路模型连接与恢复设计



<a id="model-routing-1"></a>
### 结论：需要独立恢复路径，生产与进化还需分配独立资源

“两套路由”分成三个问题处理：

| 维度 | 设计 |
|---|---|
| 业务用途 | 实时交互、后台任务、维护进化分别有队列、优先级、预算 |
| 推理位置 | 每类请求可选择本地、局域网或云端模型 |
| 故障恢复 | 主模型网关之外保留简化、独立的恢复连接 |

不要求常态下运行两套完全相同的智能系统。两套网关若共享唯一配置库、运行环境和故障依赖，仍可能同时失效。

<a id="model-routing-2"></a>
### 通道设计

**A：生产模型通道**

- 服务对话与正式任务，按延迟、模型能力、质量、费用和隐私选择部署。
- A 通道内部进一步区分前台交流与后台正式工作，按[交流保障](tasks-agents.md#conversation-resource-isolation)预留容量与实际配额域；后台 3D 规划、邮件处理等不能因复用生产模型而占用前台专用槽。独立 key/连接不代表独立供应商配额，此要求仍待统一准入实现。
- 支持多个实例、限流、熔断、冷却、健康检查和回退。
- 可使用 LiteLLM 作为可替换实现，外层仍使用项目自己的 ModelGateway 契约。[S15](references.md#s15)

**B：维护与进化通道**

- 服务诊断、代码研发、方案比较与实验。
- 独立队列、预算、并发和超时；生产交互优先占用保留资源。
- 平时可使用同类适配器库；故障处置时不能只依赖已失效的 A 通道。

**R：最小恢复入口**

- 由独立小进程读取最后已验证配置，直接调用本地模型或独立备用部署。
- 不要求主网关、完整记忆服务、Agent 框架或共同体在线。
- 未锁存时的必需能力：状态查询、停止任务、恢复版本、基础文字交互。锁存后只保留固定状态、告警和主人认证，不自动调用任何模型或修复程序。
- 停止、回退和启动由确定性代码完成；没有任何模型可用时仍能使用 CLI 或本地恢复界面。
- R 只接受受限的恢复、状态与基础交互请求，拥有独立配额。生产请求失败后降级或等待，不透明转移到 R 继续运行；故障汇总事件触发诊断，避免恢复资源被普通任务耗尽。

<a id="model-routing-3"></a>
### 路由输入与选择顺序

路由请求包含：任务类型、所需模态、上下文大小、工具/结构化输出能力、延迟预算、费用上限、数据范围、节点资源、允许供应商和当前版本。

顺序：

1. 按权限、数据范围、联网状态与模型能力过滤候选。
2. 检查预算、并发槽和可用显存/内存。
3. 按该类任务的实测质量与延迟选择候选。
4. 请求失败后记录结果，判断能否重试或换部署。
5. 新策略先离线评估和小流量试用，再进入正式路由。

模型自报“我更适合”不能直接替代实测。学习型路由属于后续优化，初期使用可解释规则。

<a id="model-routing-4"></a>
### 流式回答与工具调用

一轮输出绑定 turn_id、generation_id 和已播放/已显示偏移。
- 供应商中断时，不把另一模型的续写无标记拼到已输出文本中；在句段或轮次边界恢复。
- 对话取消只停止对应生成，不自动撤销已经完成的现实操作。
- 模型重试不能重做工具动作；工具调用通过稳定 action_id 查询执行账本。
- 不同模型的工具格式、视觉输入与结构化输出能力不完全一致，适配器需要能力验证。

<a id="growth-model-policy"></a>
### 自检、自愈、进化的模型与档位策略

**0.1.64 implemented：Inspect / Heal / Evolve 各有主选、一个可选备选及各自原生推理档位。** 同用原 ModelGateway、模型目录、凭据与记账；不启动三个模型服务。日常自检不调用模型，只有显式“请模型解释检查结果”使用 Inspect 策略，结果只是建议，不执行输出。后文的多备选、分阶段覆盖、动态升档及总费用硬预算属于更广泛 proposed 设计。

| 用途档案 | 默认调用时机 | 选择依据 | 可进一步细分的阶段 |
|---|---|---|---|
| 自检 | 正常检查不调用；仅开启 AI 诊断后处理未解释异常 | 有足够上下文与结构化输出能力、低延迟；小模型是否足够由诊断集验证 | 诊断、报告解释 |
| 自愈 | 配方无法解决且证据指向代码缺陷时 | 修复与兼容测试实绩优先；复杂度增加时在已设范围内升档 | 定位、修复编码；默认继承本用途档案 |
| 进化 | 主人目标或已接受的能力提案进入研发 | 规划/编码质量与成本、耗时综合比较 | 规划、编码、评审；默认继承本用途档案 |

完整目标中每个档案可设置：启用方式、首选连接/模型、**该模型实际支持的推理档位**、有序备选（初期最多三个）、允许自动切换的故障类别、上下文范围、输出上限、总耗时、请求次数与费用提醒。备选每一行独立设置档位；切换模型后只显示目录核验的合法选项，不把不支持思考的模型伪装成“高”。“省资源 / 均衡 / 深度”可作为界面预设，但保存与任务详情必须展示实际原生档位；自动升档若启用须给出上限和原因，不能擅自选任意最贵模型。

默认模型从本机已启用、能力满足、已有测试证据的目录选择，用户可覆盖；不硬编码“某品牌永远最好”。建议首选与至少一个备选来自不同供应商，减少同家配额故障的关联；同模型两个名字不代表两个故障域。本地模型只在已安装、资源足够且该类任务验收通过时成为可执行备选，不能把 0.6B 自动视为复杂修复的等价替代。外部 Codex 的认证、模型和费用仍按 [CodingProvider 边界](toolchains.md#development-channel-choice)单列。

<a id="growth-fallback-policy"></a>
#### 备选切换的确定规则

新工程必须将用途策略和修订固定到每单，记录请求/实际档位、路线、备选原因及真实用量。重试总额由获准预算约束；UNKNOWN、取消、已派发后断连或外部效果不明时先查询，不盲目切换重发。备选不能暗中扩大费用、资料外发或权限范围。

以下为完整多备选策略目标，超出上述子集的项目仍 proposed。任务开始时冻结用途配置版本。顺序为能力/范围过滤 → 配额与资源准入 → 首选请求 → 分类回执 → 合格备选；单次逻辑请求中每条连接最多派发一次，所有备选共享一次任务的时间、调用和费用预算。发现首选未配置/已禁用/明确不可用时直接跳过并解释，不用付费“探活”维持绿灯。

| 结果 | 自动处理 |
|---|---|
| 明确额度耗尽、模型下线、可分类的限流或供应商不可用 | 标记该连接不可用/冷却；按配置选择下一条合格备选，并显示切换原因；不猜测真实余额 |
| 认证失败 | 隔离这一连接，提醒更新凭据；只有单独启用“认证失败可用其他连接”才继续既有备选，不更改 Key |
| 超时/断连且已派发、UNKNOWN 或结果可能已计费 | 先核对请求记录；保留待核对，默认不自动重发，不能通过换模型抹去未知结果 |
| 参数或接口契约错误 | 停止该配置并报告，不轮流调用所有模型掩盖实现缺陷 |
| 返回完整但测试不通过 | 属于候选质量失败，不谎报供应商离线；在剩余研发次数内可向同模型反馈或按质量升级策略换模型，计入同一实验 |
| 全部备选不可用 | 保留检查报告、可用旧包和研发检查点，显示等待原因；联网恢复/冷却到期只恢复获准任务，不重放有未知效果的步骤 |

熔断按连接和故障类别作用，退避后以一个必要的真实请求半开试探，避免多个模块同时抢着测试恢复。切换后的新文本候选从完整契约重建，不拼接两家模型的半截代码；每次尝试均保留实际连接、模型、原生档位、时间、状态与用量。自检、自愈、进化使用不同策略但共用连接健康事实，不因为自愈模型故障而误报工具损坏。

<a id="growth-budget-policy"></a>
#### Token、费用与普通 PC 的资源预算

**零模型检查为 0 token；AI 诊断、编码、模型评审才计费。** 页面分别展示输入、输出、可获得的思考/缓存用量、实际供应商回执及估算费用；缺失用量显示“未知”，未知价格不填 0。供应商配额与账户余额只采用真实接口/错误回执，不能从调用次数估算出“还剩多少钱”。

按用途与整体分别统计，所有备选和重试归同一逻辑任务预算；先预留再派发，避免并发透支本机配置额度。日/月费用默认可采用提醒模式，主人也可选择硬停止模式；不能把原型的每日四次写死为永久产品规则，也不能迁移成三个各四次而无声扩大总额。原型的有限候选次数保留为防循环默认，界面允许在实现支持范围内调整。费用硬界限只能限制新请求准入，不能保证已在供应商执行的请求立刻停止计费；UNKNOWN 仍占用待核对预留。

先预留聊天和任务资源，再让维护使用剩余额度。受影响对象发布串行，后台研发并发首期为一，确定性观察可并行但每探针有时间/输出上限。设置页动画停止时无需停止后台工作；后台也无需保持任何浏览器标签或本地大模型常驻。详细调度归[自检计划](health-maintenance.md#inspection-scheduling)。

<a id="local-survival"></a>
## 本地小模型、离线生存与网络自恢复



<a id="local-survival-1"></a>
### 目标：在较低资源下仍保留有用能力

每个承诺独立运行的完整节点提前配置离线能力包。小模型负责语言理解、简短交流、分类、检索和选择已验证操作；确定性程序负责网络检查、配置读写、权限判断、停止与恢复。

“足够小且强”通过目标任务的质量、内存、延迟、能耗和工具参数准确率共同选择，不按参数量或文件大小直接认定。小模型做不到的复杂任务保存状态或缩小范围，继续可靠完成可做的部分。

<a id="local-survival-2"></a>
### 本地组件种类

| 组件 | 作用 | 资源紧张时的处理 |
|---|---|---|
| 小型 LLM | 本地交流、理解命令、解释故障、选择流程 | 短上下文、低并发、按需加载 |
| STT/ASR | 本地语音转文字 | 较小模型、按键说话或退到文字 |
| TTS | 本地语音输出 | 轻量声音、减少长篇播报或文字输出 |
| VAD/唤醒 | 检测说话和触发交互 | 使用低耗组件，不强制大模型常驻 |
| Embedding/重排 | 本地资料检索 | 全文检索、缓存或较小嵌入 |
| 视觉模型 | 屏幕/图像理解 | 降低频率、截图按需，或暂停视觉任务 |
| 规则与诊断工具 | 状态、网络、错误码、已验证修复 | 不依赖 LLM 的基础能力 |
| 独立监督与告警 | G0 检查、门禁、锁存与停止 | 不允许为给模型腾内存而卸载 |

llama.cpp 与 sherpa-onnx 提供本地语言与语音推理的基础能力；具体模型、中文质量、平台和离线依赖必须在目标机器实测。[S17](references.md#s17)[S18](references.md#s18)

<a id="local-survival-3"></a>
### 离线能力包内容

至少一个在支持设备 CPU 上经过验证的语言模型及运行时、分词器、模板。
- 主人主要语言的 STT、TTS、必要词典、音素器、声码器和声音文件。
- 已缓存的基础知识、诊断手册、工具和技能依赖。
- 无模型可用时的固定文本控制台、停止入口、状态和检查点查询。
- 当前已验证包、上一可用版本和必要安装文件。
- 当前私人使用保留本机状态与故障诊断入口，无需恢复密钥或密码；完整监督认证延期，见[适用范围](security-sovereignty.md#identity-authorization)。
- 包哈希、来源、许可、兼容性、离线冷启动结果与资源基线。

模型文件存在不等于离线可用。要切断所有外网与共同体后进行冷启动、识别、合成、检索、网络诊断和任务恢复测试。运行时不得因缺依赖而暗中要求在线激活或下载。

设备低于最低资源或所有模型损坏时，仍力争保留确定性控制；不承诺微控制器或任意旧手机都能运行通用 LLM。

<a id="local-survival-4"></a>
### 资源 Profile

| Profile | 工作方式 |
|---|---|
| LP0 deterministic | 不运行通用模型；固定状态、只读诊断、停止控制和任务保存 |
| LP1 survival | CPU 小模型、短上下文、单任务；基础语音按需；暂停学习与大规模模拟 |
| LP2 local-standard | 完整本地交互、有限任务并发与知识检索 |
| LP3 accelerated | GPU/NPU 条件允许时提高模型、上下文、并发或语音质量 |
| LP4 federated | 允许且连接可用时扩展到共同体或云，保留本地回退路径 |

Profile 依据实际可用内存、KV cache、算力、电量、温度、模型预热与延迟实测选择。转换设迟滞、冷却和最大失败次数，防止网络抖动导致反复装卸。

降级顺序一般为暂停低优先级实验/模拟 → 降并发 → 缩上下文 → 换轻量模型 → 减少语音/视觉 → 固定控制台。监督和停止通道始终保留。

<a id="local-survival-5"></a>
### 自主切换与替换

本地模型管理器可以自主选择已批准组件，也可在联网、预算允许时发现候选并下载验证；不要求每次切换都询问主人。新增权限或超出额度仍遵循独立授权。

生命周期为：

```text
discovered → downloading → quarantined → integrity_checked
→ compatibility_tested → quality_tested → ready
→ warming → active → draining → standby / retired
```

来源可信与内容哈希是两回事；不能仅凭哈希一致认为下载内容可信。下载未完成不得激活，最后一套已知可用的离线能力包不得被自动清理。

LLM、STT、TTS、嵌入和推理引擎分别版本化。替换模型时检查格式、运行时、tokenizer、chat template、语言、结构化输出和工具调用；更换 STT 时防重复转写造成重复动作；更换 TTS 时测试停止、打断、数字和指令读法。

模型的 KV cache 一般不能直接搬给另一模型；迁移规范化消息、任务状态和记忆引用，再重建上下文。人格、权限和停机状态不随模型替换。

<a id="local-survival-6"></a>
### 资源不足时如何换模型

容量足够时 B 预热后接收新轮次，A 排空。容量不足时，先保存会话与任务状态、进入固定反馈模式，再卸载 A、载入 B、验证并继续；这可能有局部等待。

严禁同时卸载最后可用模型、唯一恢复工具和监督模块。失败时载入已验证旧版本；若连旧版也无法运行，进入 LP0，不无限重启和下载。

<a id="local-survival-7"></a>
### 网络诊断和修复

![network-recovery](diagrams/network-recovery.png)

[矢量图](diagrams/network-recovery.svg) · [可编辑图源](diagrams/network-recovery.mmd)


检查顺序：链路 → 地址/DHCP → 网关/路由 → DNS → TCP/TLS → 代理/认证 → 模型服务 → 共同体。断网、供应商配额耗尽和共同体不在线是不同故障。

读取网络状态、检查批准端点、连接重试和切换已授权备用服务可在既有范围内自动进行。网卡重启、DNS/代理/路由修改或网络重置需要预先批准的修复策略，并评估是否切断远程管理及能否本机回退。

不得以恢复网络为由关闭 TLS 校验、绕过认证、弱化防火墙或连接未授权网络。断线电缆、运营商故障、未提供的密码、验证码或物理设备损坏可能需要主人或外部处理；模型不能创造不存在的连接。

<a id="local-survival-8"></a>
### 所有恢复从属于 G0

普通故障允许轻量模型接管、切换组件或修复网络。安全锁存禁止这些自动活动，不能以“恢复自己”“小模型备用”“远端替身”继续业务。

锁存后 LP0 仅包含固定状态、告警、审计、设备安全停止和认证验证，不继续网络修复或一般任务。主人认证后的隔离维护是一条单独的、明确授权的流程。

<a id="local-model-lifecycle"></a>
### 文件、运行与使用状态分别管理

| 操作 | 当前实际行为 | 对内存、数据及其他工作影响 |
|---|---|---|
| 登记 | 数据清单覆盖 embedding/LLM/STT/TTS/VAD/声纹/reranker/vision；固定 ID 不允许覆盖修订 | 登记不安装依赖，不执行模型仓库代码，也不自动启动 |
| 下载 / 续传 | HTTPS 受限源、固定 commit、逐文件大小与 SHA-256；`.part` 断点续传；只取所需文件 | 单独后台通道；不调用付费模型；网络禁止时拒绝下载 |
| 校验 / 修复 | 校验全部清单文件；修复只重取缺失或损坏文件 | 已加载模型需先待命；损坏文件不带病启动 |
| 启动 | 校验文件与依赖版本、启动独立 Worker、检查维度和归一化探针 | CPU 2 线程；加载后空闲仍占 RAM；不会自动改默认模型 |
| 待命 | 退出对应 Worker，保留文件与默认选择 | 模型推理进程 RAM/专用显存释放；不表示整个 Jarvis 零内存 |
| 设为默认 / 更换 | 新 Worker 探针成功后才换指针，保留上一默认 | 候选失败保留旧 Worker；短暂双驻留须有足够 RAM |
| 回退 / 解除保留 | 回退前重新校验上一模型；解除保留只移除恢复指针 | 不回滚记忆事实、授权、删除和停止状态 |
| 卸载文件 | 拒绝卸载在用、默认或回退保留模型；只删本模型清单文件与暂存文件 | 不递归清空目录，不删来源登记、知识库或用户资料；可按原摘要重新下载 |
| 取消 / 重启恢复 | 在读写/等待边界取消；宿主重启将未结束操作标为 interrupted | 不自动重做未知任务；启动宿主不自动加载任何模型 |

已接入已核对事实的[记忆检索](knowledge-learning.md#memory-retrieval-runtime)：复用选中且已启动的编码器，前台等待有界，忙时降级；它不是全文知识库或持久向量索引。

后台通道一次只执行一个模型操作，忙时立即返回，不排入无限队列。前台聊天不等候下载或推理完成；仍会共享硬件，不能承诺资源争用绝对为零。启动前用可用内存做保守准入检查，不能代替 OS 硬配额；macOS 未接入同等计数器前不宣称已验证该检查。停止闩锁会取消操作并释放 Worker。

<a id="local-model-resource-runtime"></a>
### 资源、离线与运行依赖

本机实测数值统一在[验收页](delivery-validation.md#local-model-manager-evidence)。1.1.0 的每张候选卡分别显示启动预测、当前实际占用、持久实测记录与多维评价。未下载时也有磁盘/RAM/专用显存规划；未运行只将当前进程占用显示为 0，不抹掉启动预测。缺少平台采样时显示“待测”，不伪造零。磁盘只计配方模型文件，RAM 只计推理子进程 RSS，不包含宿主、索引、Python 环境或全部系统缓存。

当前使用开发机已存在的 ONNX Runtime、NumPy、Tokenizers，版本清单位于 `modules/local_models/runtime.json`；Host 只读取包元数据，不载入推理库。版本缺失或变化后不启动推理，但模型文件管理与云端聊天仍可工作。状态库损坏、数据格式高于当前管理器或清单不可用时，该模块进入 unavailable，工作台继续启动，不通过重建数据库覆盖原资产。没有运行安装器、没有复制旧 Torch 环境；新机器依赖打包、依赖自动修复与 macOS 实机验证仍待完成，文件“修复”不能冒充运行环境修复。

本地推理只读已校验的本地文件；应用网络策略关闭仍能启动/编码。Worker 关闭 ORT 遥测并拒绝 Python socket 连接，不加载 Hub、pickle 或远程 Python 模型代码。这些不是操作系统级网络沙箱证明，恶意 ONNX/本机原生库风险仍须供应链验证。下载源当前限 Hugging Face 官方仓库及其受限 CDN；其他模型站需新增经过验证的下载适配器。

<a id="local-model-calibration"></a>
### 资源校准与多维评价

权威机器配置为 `modules/local_models/assessments.json`，评分规则在同目录 `assessments.py`。它们与不可变下载清单分离：官方资料改版不允许偷偷改写已安装模型的修订、维度或配方。每项保留核验日期、官方链接、仓库元数据修订、精度、短文本/音频负载和估计依据；当前资料核验于 2026-10-23，后续资料更新须再核对来源后修改，尚未启用联网自动刷新评分的后台任务。

**持久修正流程：**下载/修复/校验通过 → 记录已验证文件字节；成功启动/每次编码 → 记录 RSS、进程峰值和已观测 batch/token 范围；本机评测完成 → 保存命中率、排序、延迟与失败项。所有记录写入 `config/local-models.sqlite3` 的 observations，状态模式由 1 加性迁移到 2，保留默认选择、旧模型和任务记录。待命、重启和卸载权重均保留校准；卸载后“当前磁盘”归零，但重装预测保留实际文件大小。

校准按不可变模型清单指纹＋设备散列＋操作系统/CPU＋Python/依赖版本＋推理 Worker 摘要分域。不同精度、版本、设备和运行适配不能共用一条 RAM 结论；旧记录保留为其他配置。当前 RAM 预测下界取已测 RSS 最小值，上界取已观测最大进程峰值再加 15% 规划余量；这是**已经测过负载的预测，不是内存硬上限**。缺失/非法/零 RSS、坏文件和未完成下载不能覆盖有效校准。当前后端只有 CPU，专用显存 0 是配置事实；GPU 尚未适配，不能推断 GPU 加速时也只占 0。Apple 统一内存不得将 RAM 与 GPU 简单相加。

| 维度 | 展示与可复核口径 | 限制 |
|---|---|---|
| 资源友好度 /5 | RAM 预测上界 ≤512 MiB / 1 / 2 / 4 GiB / 更高，对应 5 / 4 / 3 / 2 / 1；旁列磁盘和显存 | 标明估计或本机校准；不等于跨模型性价比总分 |
| 多语言覆盖 /5 | 官方语言数 ≥100 / 30 / 10 / 2 / 1，对应 5 / 4 / 3 / 2 / 1；未知留空 | 覆盖不是每种语言准确率；方言不重复算语言 |
| 本机检索质量 | 固定 20 查询 / 20 文档的 Hit@1、MRR、每项排名；中文、英文、西班牙文、法文、德文、日文及跨语查询 | 公开合成回归集，含易混淆候选；不是领域留出集、通用准确率或事实核验能力 |
| 本机速度 /5 | 同一固定回归集、预热后 batch=1 查询 p50 ≤20 / 50 / 150 / 500 ms / 更慢，对应 5 / 4 / 3 / 2 / 1；另列 p95 | 包含 JSONL 和测量写入，不含检索索引、LLM 或网络；没有实测就留空 |
| 验证覆盖 /5 | 0 目录、1 文件摘要通过、2 启动探针、3 固定回归已运行、4 领域留出、5 跨平台/长时验证 | 这是历史证据覆盖度，3 不代表所有查询命中；当前仅实现到 3 |
| 官方原生指标 | 保留 MTEB 的集合、版本、分数、精度和链接 | 不混成主观总分，不将 FP32 成绩写成 Q8 本机成绩；语音与生成模型另用专用评测 |

“本机评测 / 更新预测”是显式、可取消的独立模型任务，不改默认模型；原本待命则评测后恢复待命，另一模型正在加载时拒绝抢占。只运行固定合成样本；日常编码持久化资源元数据，不存原始用户文本或向量。评测集摘要改变后旧成绩保留，但不再计入当前质量/速度分。未完成或取消的评测不能冒充新成绩。

**当前选型建议：**马上使用选已接通并实测的 E5 INT8；质量优先的下一候选为 Qwen3-Embedding-0.6B，其官方 MTEB Multilingual v2 Mean(Task) 为 64.33，但目录 Q8 尚未接入实测。EmbeddingGemma 原版同口径为 61.15；官方“量化后低于 200 MB RAM”不能套给当前约 1.18 GiB 原始 fp32 包，量化版本应另核验配方后比较。官方分数不是我们自行给出的满意度，也不能只凭一个均值断言所有专业领域更好。来源：[Qwen 官方模型卡](https://huggingface.co/Qwen/Qwen3-Embedding-0.6B)、[Google 官方评测](https://ai.google.dev/gemma/docs/embeddinggemma/model_card)、[Google 量化说明](https://developers.googleblog.com/introducing-embeddinggemma/)。

<a id="local-model-api"></a>
### API 与恢复入口

`GET /api/local-models` 返回带修订号的清单、状态、资源、当前/上一模型、依赖及管理器说明；`POST /api/local-models` 在原工作台同源/nonce 保护下接受动作与预期修订，返回异步任务；`GET /api/local-models/result` 返回本次临时结果。输入文本与向量不写入状态日志，不作为普通聊天上下文发送给云端。页面结果只展示前几维用于调试；没有在本轮建立全文知识索引。

宿主未运行时可在项目根使用 `python -B -m tools.local_models list`，以及 `download/repair/verify/uninstall <模型ID>`、`retire_previous`。CLI 与 Web 共用管理器和租约，不能同时写同一数据根。发布源码仅包含清单、源码、版本约束和来源链接，下载模型不进入 Git；目录归属见[项目结构](stack-project-layout.md#local-model-layout)。

## Nano Banana 图片模型接入（1.1.0）

2026-10-25核对Google官方目录。图片模型在图片工作室独立管理，复用已配置的Vertex服务账户或Gemini API Key，不加入普通文字自动回退链，也不更改当前聊天默认模型。

| 角色 | 名称与模型ID | 发布与当前目录状态 |
|---|---|---|
| 最新主线，默认推荐 | Nano Banana 2.1 · `gemini-nano-banana-2.1` | 2026-10-06 GA |
| 按发布时间次新，轻量分支 | Nano Banana 2 Lite · `gemini-3.1-flash-lite-image` | Gemini Developer API于2026-06-30 GA；只支持1K |
| 上一代主线，兼容对照 | Nano Banana 2 · `gemini-3.1-flash-image` | 稳定版2026-05-28；Google已宣布弃用、尚未公布停用日期 |

“次新”按时间与按主线有不同含义，目录同时保留说明，不把Lite当作质量升级。来源：[模型名与日期](https://firebase.google.com/docs/ai-logic/models?api=dev)、[2.1模型卡](https://ai.google.dev/gemini-api/docs/models/gemini-nano-banana-2.1)、[更新与弃用记录](https://ai.google.dev/gemini-api/docs/changelog)。这些是云端图片模型，不是手机本地Gemini Nano。

接入协议使用官方`generateContent`：Vertex为global区域项目端点、OAuth服务账户；Gemini Developer API为generativelanguage.googleapis.com、x-goog-api-key。原文档也介绍Interactions API，但现有Jarvis复用已接通的Generate Content认证链。单次图片请求显式声明TEXT/IMAGE与imageConfig，解析inlineData；不继承文字聊天的JSON响应模式、推理档位或采样参数。2.1不支持部分采样参数，详见[Cloud模型说明](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/nano-banana-2-1)。

1.1.0已开放以下官方档位，实际参数按模型限制；每次一张，不因切换模型而静默保留无效档位：

| 模型 | 分辨率档位 | 正方形像素 | 图片输出公开价（USD，未含输入和思考） |
|---|---|---|---|
| 2.1 | 1K / 2K / 4K | 1024² / 2048² / 4096² | 0.0336 / 0.0504 / 0.1134 |
| 2 Lite | 1K | 1024² | 0.0336 |
| 上一代2 | 512 / 1K / 2K / 4K | 512² / 1024² / 2048² / 4096² | 0.04482 / 0.0672 / 0.1008 / 0.1512 |

支持14种画幅。K是生成档位，长边会随比例变化：16:9的1K/2K/4K分别为1376×768、2752×1536、5504×3072；4K的21:9为6336×2688、8:1为12288×1536，并非原生8K档位。界面按选择显示规格参考，交付后另记实际尺寸。512的21:9在指南表中写792×168，与比例冲突；宿主以1K尺寸减半得到792×336，等待真实回执验证。[分辨率规格](https://ai.google.dev/gemini-api/docs/generate-content/image-generation)、[Lite模型限制](https://ai.google.dev/gemini-api/docs/models/gemini-3.1-flash-lite-image)。指南存在冲突：Lite表格列512而模型卡限1K；2.1的4K表格列2520Token而两份价表均列3780。宿主分别采用模型卡限制和价表3780计算预估，不隐藏差异；结算按实际回执。

Vertex/global Standard与Developer API Standard本次核对的单价一致，但保留各自来源快照：[Vertex价表](https://cloud.google.com/gemini-enterprise-agent-platform/generative-ai/pricing)、[Gemini API价表](https://ai.google.dev/gemini-api/docs/pricing)。每百万Token，2.1输入/文字与思考/图片为1.5/7.5/30美元，Lite为0.25/1.5/30，上一代2为0.5/3/60。缓存输入独立处理，图片与文字输出不能共用一个输出费率。实际调用冻结价格、来源与本地30天复核期限，过期时阻止新提交；这不是供应商停服日期。统一调用账本与图片总览使用同一估算器。缺少分项、未知结果或历史无快照均保留未知；优惠、税费、合同价及余额不自动推断。手工账单记录另存并保留修订，不覆盖原始估算，当前未连接Google Billing导出。

图片后台持久保存默认连接、模型、分辨率、画幅、设计类别、模型启停和单次费用预留额阈值；修订冲突拒绝覆盖。预留额不是Google硬扣费限额。搜索增强、视频输入和thoughtSignature连续会话编辑仍未接入。编辑仍限两张PNG，每张不超过7MB、合计12MiB与1600万像素；高分辨率输出不代表同尺寸图片一定可直接回送编辑或3D参考。操作与组合规则见[图片工作室](tasks-agents.md#image-studio-workflow)，真实结果见[验收](delivery-validation.md#nano-banana-evidence)。
