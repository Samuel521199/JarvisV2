# 独立英语城市软件与 Jarvis 日用接入验收

**结论：English City 1.0.0 的源码、测试和发布包均在 Jarvis 项目目录之外；Jarvis 接入版 v0.1.13 已日用采用，epoch26、控制器协议9。** 可以在原英语学习入口选择咖啡店、改约沟通或工作通知，自由写答，或录音后确认转写再答；剧情进度、原答、词汇观察、纠错和复习由 Jarvis 统一保存。第一段真实日用咖啡店剧情已经准备，等待本人表达，没有代答或导入开发成绩。

本轮完成的是三个固定场景共七个节点的独立软件及受控适配，不等于通用第三方插件平台、任意新剧情生成、自动英语转写或发音测评。开发模型样本和合成录音只能证明限定流程，不能证明本人英语已经提升。

## 从哪里使用

打开本机日用工作台，在会话“英语城市 · 日常生活”点击“英语学习 · 跨会话记录与复习”，当前咖啡店回合可直接输入自己的表达。也可以在该入口选择“Jarvis建议”或三个场景开始新游戏，并在开始前选择文字或口语模式。口语模式须本人手动开麦，回听并确认实际说出的内容后提交。页面中的“听角色说话（不揭示答案）”只播放NPC，不展示参考答案。

可随时暂停，重新打开仍保留当前问题；软件停用不删除学习记录。重新启用后，已有游戏须显式按原发布包重新核对才能继续。改学习目标会暂停当前剧情，随后本人选择新目标；本版不会自动创造新的饮品或世界分支。

软件本体没有独立用户登录、学习数据库或后台常驻进程。它通过有版本的标准输入/输出JSON协议接受AI系统调用，使用者仍在Jarvis中完成学习；其他AI客户端可实现同一协议。本轮没有为独立软件初始化Git或安装依赖。

## 一次回答如何形成闭环

本地软件给出固定问题 → 原聊天队列显示NPC与任务 → 本人自由写或录音确认转写 → 原模型路由给出内容评价、条件状态及原答引文 → 宿主重验回合修订/软件绑定/STOP/来源 → 软件提出允许的下一状态 → 原学习库在同一事务保存原答评价和剧情推进 → 可继续、补答或暂停 → 原复习与进步页读取有效记录。

引文必须能在当前或同节点有效先前回答中定位，来源ID由宿主绑定。NPC对白不是本人事实。引用校验只能保证来源结构，不能证明模型语义判断正确；原异议入口继续有效。缺信息先补问，补答可沿用首答中的有效信息，首答的低分依旧保留。同一节点最多六次尝试后暂停，UNKNOWN和待定请求不能靠暂停/恢复触发自动付费重试。

三位一体继续分别落实为：本人目标与权限决定“定向”；原任务队列/模型路由调用独立软件完成“协作”；有来源、可异议的原答/词汇观察和保守统计支撑“观察成长”。没有另造一套主人身份、记忆库或学习授权。

## 防止越玩越熟被误记成越学越会

原实现按问题文字去重；游戏补答会增加提示文字，固定场景即使没有改变目标，也可能被当成新变式。本轮确定性时钟反例发现这个问题，随后修复并再次冻结验收、采用。

| 同一个固定关卡重复六天的合成记录 | 修复前 | 修复后 |
|---|---|---|
| 复习阶段 | 5，可能过早延长间隔 | 1，保持同任务练习身份 |
| 可报告的新进步趋势 | 1 | 0 |
| 延迟独立变式 | 未能可靠区分 | 0 |
| 原答与原评分 | 原样保留 | 仍原样保留 |

现在游戏按软件ID、场景、节点识别同一固定任务，普通练习继续沿原问题身份。重复、补答、跨会话再玩相同节点都不能刷成新的变式。此时保守分数或阶段可能低于旧派生结果，这是纠正虚高统计；不能为了让数字上涨而恢复错误口径。[反例与修复结果](fixed-task-review-correction.json)。

到期复习仍复用原普通练习产生新的变式。有效、可比、不同任务的跨日原答才能支持后续进步判断；场景通关和词汇观察本身不授予掌握结论。真实保持、未见迁移与净token收益还没有本人样本。

## 接下来实测什么

| 顺序 | 需要的真实证据 | 决策依据 |
|---|---|---|
| 1 | 本人先完成咖啡店、改约、工作各一次，记辅助、原答和异议 | 优先修复误拒/误放行及体验问题，不能代答补满进度 |
| 2 | 隔天用不同材料、人物和时间条件复习 | 验证真实保持/迁移，固定场景重复只算练习 |
| 3 | 同目标普通练习与游戏交替对照，记录token、时间、完成和压力反馈 | 保留有益部分，效果差时调整教学与反馈，保留原评分和失败 |
| 4 | 单独设计英文ASR与发音/听力评测准入 | 先校验识别误差、本人更正、来源和费用，不以内容评分代替声音能力 |
| 5 | 确认这些流程可靠后扩展更多独立AI软件 | 复用客户端契约和能力/恢复门，软件独立版本，不将第三方任意代码直接加入可信执行 |

本轮闭合的是“独立软件 → Jarvis受控调用 → 真实来源与进度 → 相容回退 → 日用采用 → 有限观察与独立灾备”的工程链。长期学习收益、通用多Bot自主进化、完整机器人主脑及其他历史未达标门继续保留原状态。
