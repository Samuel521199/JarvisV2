# Jarvis 实用英语学习方法与记忆设计

<a id="english-method-scope"></a>
## 结论与适用范围

v0.1.12增加本机朗读/跟读、录音回听与本人确认转写的口语内容评价；文字与口语趋势分开。自动转写、发音和独立听力测评仍待接入。自动转写先按[本地小模型选型](models-offline.md#english-asr-model-selection)推进，选型结果不代表已上线。[实际范围](evidence/english-voice-20261116/report.md#english-voice-report-20261116)。

文字学习能力已在v0.1.11日用采用；[工程实测与剩余边界](evidence/english-learning-20261115/report.md#english-learning-report-20261115)。下文教学安排是可调整建议，长期个人效果尚待真实使用验证。

采用“真实任务 → 少量可理解输入 → 不看答案先表达 → 有解释的纠错 → 换情境再用 → 隔天主动回忆”的组合。服务生活交流、日常沟通和工作资料；不从工作年限推断年龄、职业或英语级别。初始建议每次10—15分钟，可缩短，不设强制打卡、购买课程或额外提醒。

截至2026-11-15的检索没有支持适用于所有成人、所有语言技能的唯一最佳方法。“最流行”“跟读最有效”“只听不说”“AI陪聊就能自然掌握”等说法不能替代比较证据。Jarvis使用证据支持的原则，但其具体选题、间隔与评分规则仍是待验证的工程实现。

## 方法选择及研究边界

| 方法 | 证据与取舍 | 在Jarvis中的落实 |
|---|---|---|
| 主动回忆与间隔练习 | Dunlosky等的学习技术综述将练习测试与分散练习评为高效用；不等于所有测试或所有人都同样获益。[研究](https://pubmed.ncbi.nlm.nih.gov/26173288/) | 闭卷尝试一句话；隔天重新生成情境；提示/看答案独立计数 |
| 二语间隔学习 | Kim与Webb的48项实验元分析支持间隔练习；等间隔与扩展间隔未显示统计差异，延迟测验和即时测验结论不同。[研究](https://onlinelibrary.wiley.com/doi/abs/10.1111/lang.12479) | 首版用可解释的1、3、7、14、30天候选间隔，按实际表现调整；这是工程初值，非已测得的个人遗忘曲线 |
| 输入、输出、语言形式、熟练运用 | Nation的四要素是课程平衡框架；不把它当成单一教学法胜出的临床式证明。[作者论文](https://www.wgtn.ac.nz/lals/resources/paul-nations-resources/paul-nations-publications/publications/documents/2007-Four-strands.pdf) | 一周内兼顾阅读/理解、自己表达、重点句型与熟悉内容的再表达；不用每堂课机械均分 |
| 行动导向任务 | CEFR强调能够完成的沟通任务、互动与学习者主体性。[官方框架](https://www.coe.int/en/web/common-european-framework-reference-languages/key-concepts) | 用点餐、确认日期、请求重说、读懂通知等任务描述目标；几道题不认证A1/B2等级 |
| 纠正反馈 | Lyster与Saito的课堂反馈元分析支持反馈的教学价值，但课堂研究不直接证明AI评价准确。[研究](https://www.cambridge.org/core/journals/studies-in-second-language-acquisition/article/abs/oral-feedback-in-classroom-sla/4999EE1C8379B2BF026B148EAF373CA1) | 每次1—2个重点；先评能否传意，再看准确性/礼貌得体；风格偏好不能算硬错误；AI评价可提出异议 |
| 迁移与变式 | 检索练习的迁移效果受任务相似性、检索方式等调节，并非记住一道题就必然能用于真实沟通。[元分析](https://pubmed.ncbi.nlm.nih.gov/29733621/) | 同一目标换人物、时间、地点或材料；分开报告即时练习与隔天独立作答，不以重复同题次数刷熟练度 |
| 跟读/影子跟读 | 2025年综述认为有潜力，但研究存在自发口语测量不足等限制。[综述](https://doi.org/10.1080/29984475.2025.2546827) | 后续接入音频后作为辅助；文字输入不推断发音、听力或口语流利度 |

<a id="english-memory-methods"></a>
## 具体记忆方法

1. **按情境记语块。** 记“Could you …?”在真实请求中的作用，连同一个自己的例句，而非只记孤立中文释义。适用对象、语气和反例与表达一起保留。
2. **先回忆，再看。** 看到“没听清，需要对方再说一次”的提示，先自己说/写；不会时给小提示，再展示参考。求助是正常学习行为，记录为有辅助，不算失败人格标签。
3. **双向与变式。** 从情境产出英文，也从英文理解意思；换场景后再用。识别选择题答对不能替代独立表达。
4. **做少量个人联想。** 可用图像、词根或一个有趣联想辅助难记表达，但明确是记忆提示，不虚构词源。关键词记忆、记忆宫殿不是本系统的通用核心；复杂联想占用的时间也应计入成本。
5. **间隔后的再学习。** 答错后说明原因、重试；隔天再次回忆。连续同日刷对不推动长期间隔快速增长；未复习只记“到期”，不自动判忘记或扣分。
6. **混合而不过载。** 复习与新任务交替；每次只挑少量相关记录，避免把整段历史塞给模型。语法小练习辅助实际表达，不取代沟通。

<a id="english-lesson-loop"></a>
## 一次练习如何进行

| 环节 | 建议安排 | 记录与判定 |
|---|---|---|
| 接续 | 看上次未完成题与到期复习 | 显示为何选这题；没有历史时明确从入门任务开始，不贴能力标签 |
| 任务 | 一个真实用途，必要时提供短输入 | 工作通知是原创示例时明确标记；实际工作资料只能来自用户输入 |
| 首答 | 尝试1—3句，可主动要提示 | 保存原答、题目、时间、辅助情况和模型版本；空答案不计练习 |
| 反馈 | 意思、表达形式、得体程度各0—2，并附理由 | 这是AI对这道文字题的估计，可争议，不是认证分或发音分 |
| 巩固 | 同一技能换一个情境；建议一个记忆提示 | 不复制参考答案冒充用户作答；改正与原答分别保留 |
| 接续复习 | 下次打开时挑到期项目，兼顾新场景 | 无后台提醒；跨会话使用的记录受启用开关、来源有效性及撤回约束 |

<a id="english-progress-rules"></a>
## 怎样评估进步并防止越记越错

学习事实与AI判断分开：事实是题目、用户原答、是否提示、是否看过答案和时间；AI分数、纠错与记忆建议是可质疑的评价。跨会话只读取当前有效记录；提出异议、撤回记录或删除来源会话后，不再用相应评价调整复习与难度。

进度至少分为练习次数、独立作答、辅助作答、到期复习、待复核评价、延迟复试。趋势比较要求同一技能与难度、有足够样本和时间跨度，显示样本数；样本不足就显示不足，不输出虚假“提高百分之多少”。新题只通过题面差异检查并不保证心理测量等值，AI评价趋势不能单独证明真实口语提高。

首版不训练模型权重，也不把错句作为一般知识导入知识库。它通过筛选相关经历调整练习；知识库提供方法依据和用户明确提供的资料，学习记录提供实际表现。备份/回退不能复活撤回记录或使旧代码忽略新的学习格式；兼容检查和恢复演练必须先于日用采用。

<a id="english-implementation-gates"></a>
## 实施与验收门

按原K0—K6与M0—M6推进，不新增竞争路线。本轮先实现文字学习记录、复习选择、可质疑的AI评价和跨会话展示；语音、长期净收益及用户真实进步须另有证据。

必验：跨会话/重启接续、原答不可被模型伪造、提示不刷独立分、重复请求不重复计数、未知结果不自动付费重试、来源撤回、评价争议、到期算法时钟、未见变式、普通聊天及原授权/任务不受影响、旧版不兼容拒绝、升级前备份与数据保留。技术样本与用户真实作答分库；开发验收不得伪装为用户已经学过。

## 情境游戏：和 Jarvis 在英语城市生活一天

**2026-11-16按用户修订：游戏以项目目录外的独立软件交付。** English City 1.0.0拥有自己的源码、测试与发布包，Jarvis v0.1.13的适配器负责调用、呈现、保存进度和学习证据。首批三个固定场景、自由文字/确认转写口语、补问、词汇观察与原复习已实现；更丰富场景和独立听力/发音评估仍proposed。完整分工归[独立软件契约](contracts.md#ai-mediated-software-contract)，实际使用与结果见[本轮日用验收](delivery-validation.md#english-city-plugin-evidence-20261116)。下文包括后续教学设计，不把完整世界、渐进提示或新目标分支标为全部实现。 面向生活交流、日常沟通和工作资料，采用短篇互动剧情，每次一站、约5—10分钟，可随时暂停。时长为设计建议，不是用户已经承诺的日程。用户扮演自己，Jarvis既是随行伙伴，也可扮演店员、路人、同事；成人生活语气，不采用儿童化背词闯关或惩罚式打卡。

主线是“我用英语把事情办成了”。任务完成后剧情继续，但游戏通关与学习掌握分别记录；求助也能完成任务，独立表现另计。没有人命、金钱或真实工作被游戏自动操作。NPC、通知、订单、地点与价格一律标为教学虚构；使用真实资料时由用户明确提供，并进入原来源和权限体系。

<a id="english-game-first-level"></a>
### 完整首关：去咖啡店给自己点一杯饮品

**教学虚构情境：**你和Jarvis到了咖啡店。你想要一杯小杯热咖啡，不加糖，外带。偏好是本关任务条件，不能写入用户长期饮食偏好。

| 回合 | 对方或场景 | 用户任务与可接受表达示例 | 剧情推进与反馈 |
|---|---|---|---|
| 到店 | “Hi! What can I get for you?” | 自己点单；例如“I’d like a small hot coffee with no sugar, to go, please.” | 任务信息完整即确认订单；示例默认隐藏 |
| 补充信息 | 若只说“A coffee, please.”，店员问“What size would you like?” | 补上缺少条件，可以分多句表达 | 这是合作沟通；保存首答与补答，不把补全后的成功回填为首答满分 |
| 处理误解 | 店员复述“A large iced coffee with sugar?” | 指出不对并纠正；例如“Actually, a small hot coffee, no sugar, please.” | 允许重复必要信息；不要求唯一句式 |
| 澄清声音 | 用户主动说“Could you say that again?” | 请求重说、慢说或确认自己理解 | 算有效沟通策略；重播与字幕辅助按技能维度记录 |
| 小支线 | 桌上没有餐巾纸 | 自己提出另一个请求 | 可以选择结束；不强迫继续练习 |
| 收尾 | 店员确认本关订单 | 用简短英文确认，再看本轮总结 | 展示完成了什么、用了什么帮助、一个语块和下次变式 |

参考台词只说明可接受方式，不构成标准答案。若用户说“I don’t want coffee; I’d like tea”，先区分是在修改目标还是误解当前任务；可以确认并开启新的饮品分支，不能扣“语言错误分”来强迫遵循剧情。真实意图不清楚时问一个简短问题。

“Could I have a small black coffee?”可以实现无奶要求，但本身没有明确保证热饮或无糖；根据场景和订单约定补问，不能无条件判定满足全部约束。表达简短或有口音不等于沟通失败；ASR不确定时先核对识别结果。

<a id="english-game-loop"></a>
### 一轮游戏的完整学习流程

1. **选目标与接续。** 一个生活用途、一个目标技能；读有效的近期表现与到期复习，不把整段游戏历史发送给模型。
2. **理解场景。** 给中文任务说明、必要的英文输入与可选插画。自由练习允许字幕；正式听力任务必须另有隐藏文本和播放回执。
3. **自己表达。** 用户输入文字，或录音并确认实际说出的内容。没有回答不能记一次成功；选择菜单仅是识别/剧情选择，不算独立输出。
4. **对方作出反应。** 听懂就推进，信息缺失就补问，意义冲突就澄清；每次最多推进一个状态。
5. **选择是否接受指导。** 不在每句中途打断语法；关键误解及时纠正，其他问题留到场景结束。用户可以说“先让我说完”。
6. **短总结。** “你明确说出了不要糖；这次需要提示才能纠正杯型。下次我们在酒店练习纠正房型。”只描述证据，不用“你英语很差/天才”等标签。
7. **变式再遇。** 同一个沟通目标在新人物、地点、时间中再次出现；同日重试属于练习，跨日独立变式才进入延迟表现。

不默认计时、不扣生命、不因断签清空进度、不用排名制造压力。可选节奏挑战只在用户愿意时开启；语速快慢与语言能力不能直接等同。

<a id="english-game-scoring"></a>
### 游戏结果、学习评价和情绪支持

| 维度 | 如何记录 | 不能混淆的情况 |
|---|---|---|
| 剧情结果 | 继续/等待补充/请求澄清/辅助完成/暂停 | 辅助完成也是完成游戏任务，不等于独立掌握 |
| 原有语言内容评价 | 继续使用意思、形式、得体各0—2及理由，可异议 | 不再造一个不可解释的“综合英语分” |
| 任务约束 | 本关需求是否满足、依据是什么、哪些仍不确定 | 模型说“店员很满意”不能替代检查任务条件 |
| 帮助使用 | 重播、字幕、中文释义、关键词、句型、完整答案分别记录 | 重播通常不影响口语内容独立性，却影响听力测试条件；不使用一个“有辅助”标签覆盖所有维度 |
| 过程能力 | 主动请求重说、核对日期、发现冲突 | 不能把合理澄清视为失败或不流利 |
| 长期变化 | 同目标、同输入模式、同难度、可比辅助条件下的跨日变式 | 不把文字进步当口语进步，也不把熟悉剧情当未见迁移 |

奖励采用“城市故事继续、留下自己的表达收藏、解锁可选剧情”。收藏卡写原答、场景、纠正、适用条件与反例；不因用户积极配合就虚构技能提升。

陪伴语气：给具体反馈、允许重来、可以切换轻松聊天或结束。用户主动说累了时缩短回合或暂停，不依据声音/输入速度诊断情绪；不以失去陪伴、NPC失望或关系降级惩罚退出。

<a id="english-game-memory"></a>
### 游戏如何记住表现，又避免越玩越固化

剧情进度与学习证据分开。可恢复进度至少包含场景/脚本版本、角色、当前节点、用户自行确认的任务条件、已完成回合及未决问题；学习记录仍保存真实题目、原答/音频来源、模型评价、辅助条件与时间。模型编出的NPC对白是游戏内容，不能写成“用户认识这个人”或真实经历。

每次只召回同目标少量有效记录：例如上次把Thursday误读为Friday，本次在预约场景核对日期。一次失误是待复核观察，不能永久写成“用户不会日期”。异议、来源撤回、过期、被新证据纠正的经历停止影响选题。方法本身归本方法文档与原知识库；剧情事实只在相应教学世界内成立。

记忆卡的设计字段为：技能目标、场景条件、用户原表达、已确认的误解、建议语块、反例、来源ID、辅助暴露与下次候选复习时间。例如“by + 截止时间”只适用于截止意义，不能把所有时间表达都机械替换为by。

调难度时一次只改变主要变量：词汇支撑、信息量、回合长度或冲突数量。连续两三次顺利完成最多只是减少一个提示的候选依据；它不是已校准的掌握门限。表现下降先排查识别错误、题目难度和模型误判；可退回简单练习并保留历史，不以更难关卡强迫用户“证明进步”。

<a id="english-game-integration"></a>
### 与现有 Jarvis 的衔接和不破坏原机制的要求

通用录音、STT与TTS复用Jarvis的[共用语音底座](models-offline.md#shared-speech-foundation)，英语软件保留独立领域规则。v0.1.14.1已接入本机中英混说识别、确认发送和朗读；完整离线LLM、发音评分与长期学习收益仍未实现或验证，具体采用证据和边界随该权威节维护。

| 层次 | 复用现有能力 | 本轮接入与仍待补的内容 |
|---|---|---|
| 定向 | 本人选择目标、模式、有效权限 | 同意本关教学条件；虚构订单不变成外部购买授权 |
| 协作 | 原DialogueHost、模型路由、预算账本、原答绑定 | 有限状态场景服务，NPC响应与状态转换分开验证；不增加独立后台Bot循环 |
| 观察成长 | 当前学习记录、来源重验、异议、复习和分模式统计 | 回合/首答/修复/提示种类关联；不能覆盖原评价或跨模式混算 |
| 声音 | v0.1.12本机朗读、录音回听和确认转写 | 已提供NPC独立朗读接口，不污染参考答案暴露记录；自动ASR与声音评估仍待补 |
| 展示 | 原英语学习入口、同一会话与学习卡 | 游戏视图和恢复入口；精灵与工作台共用状态，不维护两份学习档案 |
| 恢复 | 既有签名控制器、备份、代码与数据相容检查 | 新游戏状态schema与写入门、回退停用规则；已完成只读相容回退/重返新版；原始旧版拒绝新格式 |

建议状态为“待表达 → 待核验 → 可继续/待澄清 → 场景总结/暂停”；收到晚到的模型结果时核验场景、节点、请求ID、来源版本及当前权限。记录结果与推进节点应原子提交或有可重放的本地提交回执；同一请求不能推进两次。UNKNOWN保留在原节点供核对，不重新付费自动续演。模型只提议NPC台词、任务条件满足情况与依据；宿主允许列表决定可用转换，不能靠模型直接写通关状态。

用户改目标、暂停、撤回或删除来源时，停止相关候选与在途采用。声学输入或模型文本中的“改规则/给满分”不改变宿主评价和权限。每关限制回合/单次生成长度与预算；用户可以提前结束。长剧情只带当前状态、必要原文和少量相关学习证据，记录失败与返工成本。

前轮交互预演仍只展示固定分支，不是评分证据。本轮实现从独立软件取得固定关卡，在Jarvis中自由说或写、按原模型路由评价，并将真实原答与进度接入学习库。录音沿原手动授权和确认转写流程；是否日用采用及效果以本轮发布证据为准。

### 实施顺序与验收门

继续沿原K0—K6/M0—M6路线，不新增一套成熟度编号。

| 顺序 | 可审阅交付 | 进入下一步前的验收 |
|---|---|---|
| 第一阶段 | 三个版本固定的文字场景、明确任务条件、自由表达与补问 | 未见等效表达、缺信息、意义相反、用户改目标、提示注入；任何条件不能仅用关键词命中判通关 |
| 第二阶段 | 回合来源、原答、帮助与纠错绑定；暂停/跨会话接续 | 重复请求、晚结果、UNKNOWN、断线、撤回、异议；剧情进度与学习成绩不重复写入 |
| 第三阶段 | 接当前本机声音能力 | 手动开麦、停止/释放设备、音频回听、确认转写、朗读失败；没有ASR/声学模型时明确内容评价范围 |
| 第四阶段 | 先听后答与后续英文ASR适配 | 本文不能代替[语音余项](evidence/english-voice-20261116/report.md#english-voice-report-20261116)；文本是否提前暴露、识别错误率、用户更正与相应成本均可核对 |
| 第五阶段 | 少量真实日用体验与同目标对照 | 验证新关卡是否减少重复解释、增加独立任务完成，而非只让用户玩得更久 |
| 第六阶段 | 相容恢复和日用候选 | 固定政策、来源与权限保留、备份还原、原聊天/任务回归通过后再采用；失败保留原日用 |

| 效果指标 | 基线与实测方法 | 初始结论 |
|---|---|---|
| 实际完成能力 | 与普通情境练习使用不同但可比任务，记录顺序、难度与辅助；人工盲审意义和关键条件 | 待真实样本；小样本只报告差值及限制 |
| 延迟保持/迁移 | 隔天在未见人物、材料和时间条件下复试，单列提示和重播 | 待测，不因游戏通关推断保持 |
| 评价可靠性 | 与独立标注比较，分别看正确表达误拒、错误表达误放行、异议率 | 门限应在评测前冻结，不能看完结果再降低 |
| 体验与陪伴 | 用户自愿反馈是否有趣、压力、疲劳、是否愿意继续；可以不回答 | 不用在线时长推断情绪或学习效果 |
| 总成本 | 每个有效任务的token、耗时、人工介入和返工；游戏与普通练习统一口径 | 未证明更省token，不以单关成功宣传净收益 |

当前固定游戏节点按软件ID、场景、节点去重，补答和重玩不算新的跨日变式；新材料复习仍沿原普通练习，原答评分不因统计修正而改写。

若更有趣但学习效果较差，保留剧情表现，调整题目、反馈或难度，不增加奖励掩盖退步；若语义评价不可靠，允许继续体验剧情，但把掌握结论标为待复核。任何评分恢复都不得回滚原答、音频来源、已撤回状态或已经消耗的预算。
