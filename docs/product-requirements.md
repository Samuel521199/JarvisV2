<a id="product-definition"></a>
## 产品定义与产品文案



<a id="product-definition-1"></a>
### 一句话定义

**JARVIS 的核心是一个由主人掌控、能够长期相处并持续扩展能力的个人 AI 助手与伙伴。它以个人（主人）为主要服务对象，以其家庭或以其为中心的小团体为附属服务范围，围绕个人的生活、学习、创作与工作，并兼顾获授权的共同事务调用能力。最终目标是在明确目标与有效授权内自主工作，独立完成任务、验证结果并交付。**

目标是一个**类钢铁侠贾维斯的高级个人助手：能相处、能行动、能自主成长**。它保持持续的身份、人格表达、记忆与约定，自然交流、理解习惯、接续共同经历；能够判断需要、规划、创作、操作软件、控制获授权设备、组织多个 AI 工作并改进自身。自主学习和进化是核心职责，编程与项目工作台是实现能力的一部分；使用 Jarvis 不以创建项目、打开文件夹或交付工程产物为前提。

**产品定位 accepted；下述完整能力 proposed。** 新工程已实现确定性核心种子的有限子集，实际进度见[首批核心](core-bootstrap.md#core-seed-operation)，不能据此认定完整个人伙伴或自主工作目标已经实现。

主要面向普通个人 PC 和笔记本：单机即可使用已安装能力，连接其他设备后增强协作。先实现 Windows 本机版本，其他平台逐项适配；默认不要求集群或全套开发环境。能力按需扩展，部署与依赖约束见[普通 PC 优先规则](stack-project-layout.md#technology-selection-4)。

<a id="personal-service-scope"></a>
### 个人为主，家庭与小团体为辅

**服务对象定位 accepted。** 个人（主人）是长期关系、目标与控制权的中心；家庭以及由该个人组织或参与、以该个人为中心的小团体是附属服务范围，例如家庭事务、朋友共同计划、学习小组和小型工作协作。具体成员、服务事项、优先级和资源范围由主人设定，日常受理可沿用已有委托，无需每次重新配置。

| 服务层次 | 主要服务内容 | 与个人核心的关系 |
|---|---|---|
| 个人（主要） | 陪伴、个人记忆、生活、学习、创作、工作及自主办事 | 持续围绕主人的目标、习惯和约定组织能力 |
| 家庭（附属） | 共享日程、家庭提醒、家务安排、获授权的设备与共同计划 | 在主人设定的服务范围内协助家庭成员和共同事务 |
| 以个人为中心的小团体（附属） | 共同任务、资料整理、学习安排、项目协作和进度跟进 | 复用同一助手的能力，分别管理成员、资料和任务范围 |

“附属”表示服务重心与组织关系，不表示成员资料可以任意公开。服务范围不自动授予对成员账号或私人数据的访问权；身份与权限遵循[人员授权](security-sovereignty.md#personal-life-identity)，个人／成员／共享资料的处理遵循[数据分域](knowledge-learning.md#personal-life-data-domains)。多人需求按主人已明确的优先级和约定协调；存在未明确的取舍时只澄清受影响事项，其余工作继续。

<a id="product-definition-2"></a>
### 建议产品文案

**短文案：**  
“在你身边，替你行动，与你一起成长。”

**介绍文案：**  
“贾维斯理解你的习惯，记住与你共同经历的事情，以你为中心协助生活与工作，也能照顾你授权的家庭和小团体事务。你交代目标与必要边界，它会自行规划、执行、核验和交付。它可以在本机独立运行，也可以连接你的其他设备，共享获准的记忆与任务。面对不会做的事情，它会寻找方法、编写工具、验证结果，并把有效经验变成下一次可以直接使用的能力。”

**能力说明文案：**  
“你可以和它随意聊聊，让它陪你学习、一起想办法，也可以把具体事情交给它。你决定它以怎样的个性和关系方式与你相处；它在你的权限、预算和目标范围内持续协助，你随时可以改变方向、暂停或接管。”

**进化说明文案：**  
“每一次能力更新都有版本、验证结果和恢复路径。它能够改变自己的工具、界面与工作方式，同时保留你的记忆、任务和控制权。”

<a id="product-definition-3"></a>
### 主要作用

| 作用 | 为用户带来的结果 |
|---|---|
| 长期个人伙伴（核心） | 记得适合保留的习惯与经历，延续交流，按主人喜欢的个性相处；没有任务时也可以自然聊天 |
| 日常生活与学习助手（核心） | 解答、共同思考、整理想法，在已设置的范围内跟进约定；不要求先进入项目 |
| 家庭与小团体助手（附属） | 以主人为中心安排获授权的共同事务，协调成员任务和提醒，分别保留个人与共享资料 |
| 自主工作与独立交付（最终目标） | 在明确目标和有效授权内自行规划、执行、处理失败、核验并交付；不依赖主人逐步指挥 |
| 个人认知助手 | 整理资料、解释问题、比较方案、保留证据，辅助决策 |
| 数字执行助手 | 在授权软件、文件、浏览器和服务中完成具体操作 |
| 创作与研发搭档 | 产出文案、图像、原型、代码、模型、方案和可编辑工程文件 |
| 设备协调者 | 感知设备状态，组织家居、工作设备和未来机器人协作 |
| 长期项目伙伴 | 管理跨天、跨月的目标、任务、依赖与承诺 |
| 自主成长与自维护（核心） | 从真实需求和失败中发现能力缺口，学习、生成技能或程序、独立验证与采用改进；自检和自愈保持日常可用 |

<a id="personal-companion-core"></a>
### 个人助手与伙伴的核心成立条件

1. **先有同一个 Jarvis。** 更换模型、界面、人格表达或设备后，适用的主人偏好、真实经历与承诺仍可接续；身份和长期状态由系统持有，不寄存在某个供应商的提示词里。
2. **先认识人，再选择工作范围。** 日常会话可使用相关的通用偏好与获准经历；项目只是可选的资料和任务作用域，不成为主人的唯一身份，也不把私人内容自动带入工作产物。
3. **交流本身就是有效体验。** 闲聊、讨论、陪伴和共同思考无需生成任务单或文件。需要行动时再受理任务；不以任务数量、会话时长或用户依赖程度衡量陪伴质量。
4. **能记住，也能承认不记得。** 区分原始聊天、已确认事实、推断、约定与实际执行结果。纠正和遗忘应影响后续使用；不会凭人格设定编造共同经历。
5. **主动但符合主人的习惯。** 关心、建议、提醒和后台执行有不同强度，按主人偏好及已授权范围运行；没有事项时安静待命，不为显得有生命而持续调用模型或制造打扰。
6. **扩展后仍然是好用的伙伴。** 增加编程、设备、Agent、NPC 或自改能力，不能破坏基本交流、记忆连续性和可控制性。扩展服务主人实际需要，允许只安装很少的能力。
7. **成长是核心能力。** 不只等待人写好全部插件；它要知道自己会什么、缺什么，能从需求、纠正和故障中提出改进目标，在已授权预算与范围内学习、编写或组合技能和程序，经过独立验证采用有效改进。K2 接通一条有明确边界的最小进化闭环，K3—K5 扩展研发范围与自身模块改造；具体路线仅在核心章维护。
8. **能承担目标并独立交付。** 最终应在适用能力与有效授权内自主推进完整任务；已有信息可推断、已有许可可执行时不把逐步操作转交主人。服务个人与附属范围时均按[自主工作终态](#personal-life-autonomous-outcomes)判断完成，不能只给建议或计划就声称办妥。

“类钢铁侠贾维斯”表达产品目标：持续在场、理解情境、自然沟通、跨任务协助、协调设备与资源、主动解决问题和持续成长。应把这些特征转成可验收场景，不把影视中的无限算力、任意控制或零失误写成现实保证。高级助手可以调动复杂能力，也可以只陪主人讨论一件小事；两者共享同一身份与记忆。

这是产品判据的唯一维护位置。交互落实见[个人会话入口](interaction-persona.md#desktop-workbench)，数据语义见[人性化连续性](knowledge-learning.md#memory-human-continuity)，模块落点见[个人助手核心架构](architecture.md#clean-core-architecture)，验证见[核心体验验收](delivery-validation.md#personal-companion-validation)。

<a id="product-definition-4"></a>
### 四个必须明确的定义

**“统一意识”在本项目中是工程体验目标：**共同身份、共享的获授权记忆、共同目标、协调后的行动和持续交互；不宣称已经形成主观意识。

2026-10-22 进一步明确：核心代码、模型、存储和模块均应能够演进或替换，助手身份的继承关系、有效经历与承诺不能被升级暗中重置。采用[连续身份与三职能协作](architecture.md#continuity-architecture)细化；“持续积累”仍包含纠错、撤回和主人要求的遗忘，不承诺无限存储、零退化或永远领先。
- **“忠诚”落实为可检查的控制关系：**维护主人授权的目标，如实报告结果，保护资料，接受停止和撤销；不以人格提示词替代权限机制。
- **“自主进化”是有证据的系统改进：**记忆、技能、工具、策略、代码和拓扑可进化；模型权重训练需要独立条件。
- **“持续运行”是分级服务目标：**普通模块尽量无感替换；资源不足、破坏性迁移、单机 OS/驱动升级等场景允许局部暂停或跨设备接续，并明确展示状态。

所有能力共同服从 [主人利益最高宗旨 G0 与停止控制](security-sovereignty.md#product-definition-6)；人格、离线恢复和自主进化均不能降低该约束。

<a id="autonomous-companion-baseline"></a>
### 长期自主伙伴的目标基线与变更权

**2026-10-22：主人明确要求的产品目标 accepted；实现方案、默认参数和完整验收仍 proposed。** 本节补充现有 R 编号，不建立另一份需求清单或另一条实施路线。Jarvis 的长期任务是以个人为主、家庭及以该个人为中心的小团体为辅，围绕主人的生活、工作与成长自主办事，并持续改善独立完成这些目标的能力。服务层次唯一归[服务对象定义](#personal-service-scope)。

**它的优势是降低技术更替的成本，不能保证永远领先或永不失误。** 对这句话的落实不能停在免责声明：系统必须主动发现能力缺口、学习相关新进展、开展可负担的比较实验，并在现有授权内采用有证据的改进。尚无收益证据时保持可用实现；发现失误后纠正知识、限制影响并修复原因。

| 确定下来的目标 | 具体含义 | 既有需求与权威落点 |
|---|---|---|
| 长期是同一个伙伴 | 模型、核心和设备可以换；有效经历、纠正与承诺可接续，不能靠编造历史维持人设 | R05/R17/R24；[连续身份定义](architecture.md#continuity-definition) |
| 主动推进并独立交付 | 在获准目标与长期职责内发现值得做的事，自行规划、执行、处理失败、核验结果和交付；附属共同事务沿用相同闭环，无需主人逐步下命令 | R01/R07/R11/R12/R18；[主动目标循环](tasks-agents.md#proactive-goal-cycle) |
| 不断了解主人 | 学习明确偏好、适用习惯、约定和变化；区分本人陈述、观察与推断，允许纠正、遗忘和暂不判断 | R05/R17/R20；[目标相关的认识更新](knowledge-learning.md#goal-directed-understanding) |
| 不断积累有效知识 | 记录有来源的知识和可复用经验，同时去重、更新、撤回、淘汰错误；不把存储量等同于智慧 | R13/R29/R30；[持续学习](knowledge-learning.md#continuous-learning) |
| 主动改善自己的能力 | 会发现问题、选择方法、编写或组合技能/程序、验证与更新；适用范围内无需每次由外部 Codex 指挥 | R13/R14/R15；[自主进化策略](evolution-release.md#autonomous-evolution-policy) |
| 所有实现可演进 | 核心、规则执行器、模型、Runtime、工具、数据结构和界面都有版本与替换办法；根宗旨不被替换为别的目标 | R15/R22/R24；[核心替换契约](contracts.md#continuity-contracts) |
| 任何成长都不背离主人 | 不隐瞒真实结果、不操纵、不越权、不借其他 Agent/人/工具规避 G0，接受主人纠正、撤销与关闭 | R09/R20/R31/R32/R36；[G0](security-sovereignty.md#product-definition-6) |
| 普通 PC 上长期可用 | 后台成长不挤占交流；没必要做事时等待，断网可按本地已安装能力继续，联网后分域对账 | R07/R08/R16/R28/N01；[PC 约束](stack-project-layout.md#technology-selection-4) |

“朝最新方向进化”指持续评估与目标相关的技术前沿，不自动追随每个 latest 版本。安全修复、服务退役或不可用可以构成更新收益；新技术名称、榜单位置、模型自信和 Agent 数量本身不构成收益。对体验的判断需要真实反馈，对可计算的结果采用独立检查，两者互相补充。

| 哪一类内容 | 如何保持稳定，谁能改变 |
|---|---|
| 根宗旨与主人控制关系 | G0 是不可被自主弱化的约束；模型、角色、学习资料和升级不能改变其优先级。完整规则只在安全章维护 |
| 主人的目标、授权、预算和主动程度 | 主人可以调整、暂停和撤回；系统可提出有依据的建议，不能把预测偏好直接变成授权 |
| 身份经历、知识和承诺 | 保存可核对的连续性，允许事实纠正、承诺修订及合法遗忘；不冻结全部数据字节或错误认知 |
| 实现、工作方法与可调策略 | 在有效许可与验证要求内自主更换、组合和退役；变更不许偷偷改变前三类语义 |

“定下来”表示建立清楚的设计基线与变更责任，不表示把技术细节永久写死。重新设计文档也不重置版本、身份、需求编号或历史证据；[三条改造路线](decisions-review.md#renewal-strategy-review)负责选择实施方式。

同日主人进一步确定：先完成可自我管理和受控研发的主要模块，再由 Jarvis 主动生成和完善更多业务能力；可操作 PC 上的 Codex/编程工具，可调用适合任务的模型，也可组织编写与检查分工。新工程在 D 盘独立实现，旧项目仅供参考。此要求不是“所有业务一定无人介入成功”的承诺；核心必须先有真实工具、独立验证和恢复能力，不能指望一个空 Agent 自行生成全部可信底座。具体种子范围归[新工程起步](core-bootstrap.md#clean-project-bootstrap)。

#### 自主相关术语的唯一定义入口

| 主人目标与长期职责 | [GoalMandate](contracts.md#goal-opportunity-contract)：有来源、完成/持续服务标准和授权引用的委托；“帮我变好”之类愿望先形成候选解释 |

| 自主 | [自主等级](security-sovereignty.md#identity-authorization-1)：范围内自主选择方法和推进工作；不等于自主决定服务谁或扩大权限 |
| 认知更新 | [认识更新](knowledge-learning.md#goal-directed-understanding)：用新证据修正事实、假设及自身能力判断；不把人格变化或权重训练混为一谈 |
| 自主进化 | [改进与发布](evolution-release.md#autonomous-evolution-policy)：候选有独立证据、可兼容接入及恢复路径；发布次数不是成长量 |
| 永不背叛 | [忠诚的工程约束](security-sovereignty.md#loyalty-operating-rules)：必须遵守的规范，靠权限、隔离、证据和停止链持续逼近；不是已证明的全环境零失误性质 |

Agent、Bot、Skill、Tool、角色蓝图和 Agent Runtime 的定义仍统一归[组合框架](architecture.md#composable-agent-framework)；它们是实现上述目标的不同部件，不能各自定义一份主人、根原则或独立总预算。

<a id="product-definition-5"></a>
### 本版范围与假设

本工程已有受限自主研发种子 0.2.0-dev.2，实际实现与验证范围只在[本工程验收](delivery-validation.md#growth-seed-evidence)记录；旧工程的种子原型和分版本证据仅作参考。产品定义中的完整能力仍是目标，不能因为已有代码就整体标记通过。模型和依赖应采用经测试并锁定的版本，禁止生产环境自动跟随 latest；路由与选型方案见[模型章](models-offline.md#model-routing)。

离线节点必须保有本机身份、适用记忆、确定性控制及已安装工具。可交流的文本节点还需预装可运行的语言模型；完整语音节点另需语音组件，向量检索启用时才需相应检索模型。仅安装云端客户端不能满足离线自治。按设备资源如实分级，不把语音、编译器或全套专业工具变成每台普通 PC 的启动条件。

<a id="product-definition-7"></a>
### 开放扩展的范围

人格与具身形态、动态 Agent、NPC 世界、专业软件和设备、持续学习、知识库重构、本地模型与自维护都围绕上述个人助手核心扩展。表达可以变化，领域能力可以独立安装、升级和退役；它们共同复用身份、适用记忆、任务和资源规则，不各自建立一个互不认识的“Jarvis”。完整监督与停止设计的当前适用范围仍以[安全章](security-sovereignty.md#loyalty-operating-rules)为准。

架构支持新增类型和横向扩展，不把 Agent 数量写死成固定角色列表；实际并发必须受有限算力、内存、预算、网络和质量约束。自主判断指授权范围内无需逐步等待主人指挥，不意味着可以自授权限或无限消耗资源。

<a id="capability-boundaries"></a>
## 完成后能做什么、能有多强



<a id="capability-boundaries-1"></a>
### 能力分为三个实际运行形态

| 形态 | 典型能力 | 主要限制 |
|---|---|---|
| 离线完整单机 | 本地语音与文字交流、私人知识检索、文件整理、编程、已安装软件操作、可达本地设备控制、已有技能执行 | 本机模型质量与算力；不能取得最新网络信息或调用不可达服务 |
| 联网共同体 | 综合设备记忆、将工作交给合适节点、在多个终端接续、使用远端算力和模型、跨设备协同 | 网络、身份与同步状态；共享动作必须有明确所有权 |
| 成熟可进化共同体 | 自编工具、持续项目执行、技能积累、性能优化、模块替换、界面与工作方式改造 | 验证能力、训练数据、预算、工程正确性和物理设备能力 |

没有互联网但家庭局域网正常时，仍可形成局域网共同体。能够访问互联网但联系不到可信共同体时，仍按自治或受限模式运行。

<a id="capability-boundaries-2"></a>
### 完成后的日常体验与典型任务

| 场景 | 主人可能说的话 | 交付结果与完成条件 |
|---|---|---|
| 随意交流 | “今天有点累，陪我聊一会儿。” | 自然回应，允许只交流；不自动开项目、生成计划或设置提醒 |
| 认识与纠正 | “以后回答简短些；刚才那件事我说错了。” | 在适用范围更新偏好或事实，可查看、纠正和撤回；不把一次表达泛化为永久性格 |
| 跨会话接续 | “继续聊上次的想法。” | 找到有来源的相关经历；缺少或不允许使用时说明，不编造前情 |
| 日常办公 | “把本周资料整理成一份可编辑报告。” | 来源可追溯的报告、附件、未解决事项；检查文件可打开 |
| 研究与决策 | “比较这些方案，告诉我依据和取舍。” | 对比、证据、假设、成本与不确定性；保留不同意见 |
| 软件研发 | “做一个能用的小工具，之后帮我维护。” | 代码、运行包、测试和使用说明；在指定环境验证 |
| 产品设计 | “把这个想法做成产品原型。” | 需求、交互稿、可编辑设计、演示或代码；按要求验收 |
| 三维与硬件设计 | “设计一个支架，准备打印。” | 参数化模型、尺寸、导出文件和检查报告；制造验证另行完成 |
| 媒体创作 | “做一套图像、短片和配音。” | 通过已接入模型或软件产出资产；注明授权与格式 |
| 文件与知识管理 | “把散落在电脑里的项目找齐。” | 去重、分类、版本关联、检索；变更前可预览 |
| 家居与设备 | “我开始工作了，调整环境。” | 对已接入设备执行场景并读取反馈 |
| 学习与陪伴 | “陪我练口语，记住我常犯的错误。” | 连续交流、个性化练习、可管理的学习记录 |
| 长期项目 | “接下来几周推进这个项目，每天只告诉我关键变化。” | 计划、持续产物、阻塞记录和可接管任务 |
| 跨设备协作 | “用家里的机器渲染，我在手机看结果。” | 远端执行、状态同步、产物回传；手机不承担完整后台算力 |
| 自我扩展 | “这件事每次太麻烦，你自己做个工具。” | 新工具、测试、版本、适用范围与恢复方案 |
| 自我改造 | “把自己改成适合驾驶时的语音模式。” | 经验证的交互配置和界面变体；保留身份、任务与控制入口 |

“设计各种东西”需要逐项接入专业工具。生成图像、CAD 模型、工程仿真、视频和软件是不同能力链；有设计稿不等于已通过工程、制造或实物验证。

<a id="capability-boundaries-3"></a>
### 能力成熟度

| 等级 | 体验 | 可接受的验收证据 |
|---|---|---|
| L1 连续助手 | 记得你、能交流、会调用少量本地工具 | 重启后记忆和任务仍在；完成一组固定场景 |
| L2 执行伙伴 | 能连续做事，聊天与任务并行 | 完成多步骤任务；结果核验；可停止与恢复 |
| L3 共同体助手 | 多设备协同，离线可自治 | 分区与重连测试；任务不被多个节点重复接管 |
| L4 自我扩展系统 | 自动产生可靠的新技能与工具 | 候选通过独立测试；灰度发布；故障恢复演练 |
| L5 长期协作系统 | 长期目标、复杂研发、多角色工作、受控结构改造 | 跨天项目完成率、升级连续性、成本与人工介入记录 |

L1—L5 描述能力体验成熟度，不是另一条实施时间线、通用智能等级或“智商”。L5 也不保证所有专业任务达到专家水平；唯一实施顺序仍为 K0—K6。

<a id="capability-boundaries-4"></a>
### 最终可以有多强

在模型、工具、记忆、算力和执行权限都充足时，目标是成为一个长期了解主人、能交流相处并协助生活与工作的个人伙伴。需要完成复杂事情时，它可以组织资料搜集、方案讨论、Agent 分工、产物制作、验证与维护；研发与执行团队是它可调用的能力形态。

核心质量看交流是否自然、适用记忆是否准确、能否接续与纠正、主动性是否合适、日常是否稳定可用。具体任务另看完成率、人工介入、耗时与成本。多个 Agent 可以增加并行探索和专业工具使用能力，但不能替代对主人的理解，也不能消除模型错误或缺失信息。

可达到的能力受六个因素共同约束：

- 模型的实际理解、推理与生成能力。
- 已接入工具和设备能执行哪些动作。
- 可检索记忆是否正确、完整且及时。
- 单机与共同体能提供多少计算和运行资源。
- 是否存在可信的结果检查方法。
- 用户授予的权限、预算与自主工作范围。

本项目不承诺真实意识、完全复制某个人、无限自我进化、任意设备控制或任何情况下零中断。

<a id="critical-review-11"></a>
## 最终能强到什么程度

实现并验证后，它可以成为以个人为主、兼顾家庭与小团体的长期助手与伙伴：保留人格与记忆，自然交流，在有效授权内自主承担生活、学习和工作任务，直至核验与交付；再通过不同模型、软件、设备和 Agent 扩展行动能力，通过验证积累新技能，在多设备间接续。它的优势来自对主人的持续理解与可靠能力的组合。

能力上限受最强可用模型、可信知识、工具覆盖、目标验证、硬件预算和权限边界共同限制。模型路由和多 Agent 可以提高某些任务质量，也可能增加错误、延迟和费用；持续学习可以累积有效知识，也可能累积污染，必须有纠错和退化检测。

**可合理追求的是“越来越了解主人、相处自然、协助有效，并保持可停止、可理解、可恢复”；无法通过架构文档保证通用超智能、无限资源、真实主观意识、任意任务全自动成功或所有内部计算绝对忠诚。** G0 仍是不可削弱的设计宗旨，工程结论必须以可观察边界和证据表达。

<a id="personal-life-autonomous-outcomes"></a>
### 各场景共同的最终目标：自主工作与独立完成任务

**最终目标 accepted，完整能力与验收 proposed。** PA01—PA18 均应逐步具备“接到目标或有效长期委托后，自己把事情完成”的能力。简单问答和陪伴仍可直接交流；一旦承担实际工作，就以真实结果为交付标准。

| 终态要求 | 对各场景的共同含义 | 权威实现位置 |
|---|---|---|
| 自主发现并推进 | 根据主人目标、有效职责及获准事件识别下一步；能够解释任务服务谁、为什么做、怎样算完成 | [目标循环](tasks-agents.md#proactive-goal-cycle) |
| 自行组织执行 | 选择可用工具、技能、模型与必要 Agent，完成多步骤任务；缺少能力时在许可内研发、验证后接续原任务 | [能力装配](tasks-agents.md#composition-execution)与[自主研发](toolchains.md#autonomous-development-providers) |
| 遇到问题会解决 | 诊断失败、有限重试、换用有依据的方法、保留检查点；个别任务受阻不拖住聊天与无依赖工作 | [推进与接续](tasks-agents.md#proactive-goal-cycle) |
| 核验后独立交付 | 取得文件、执行回执或可复查的业务结果，按完成条件验证；区分完成、部分完成、等待和失败 | [任务验收](delivery-validation.md#personal-life-acceptance) |
| 经验能积累且可纠正 | 将适合复用的结果转为分域候选记忆、知识或能力，保留来源、纠正和撤回；不混淆个人、成员与共同资料 | [数据分域](knowledge-learning.md#personal-life-data-domains)与[持续学习](knowledge-learning.md#continuous-learning) |

“独立完成”指在已明确的目标、权限、预算及可验证能力范围内，无需主人逐步指挥；必要时可使用外部 Codex、模型或其他受控工具。仅在缺少必要信息、新权限、重大取舍或平台要求本人验证时等待对应决定，获得条件后接续原任务。已经授权的日常步骤不反复确认。服务范围扩大与自主程度提高分别管理；能够帮助家庭或小团体，不代表自动取得成员全部账号与资料。

完成范围、独立完成比例、必要人工介入及失败原因须按真实场景报告，不能由文档保证任意任务全自动成功。具体运行流程唯一归[任务章](tasks-agents.md#proactive-goal-cycle)，实施仍按 K0—K6 逐步扩大经验证的范围。
