Jarvis共用离线语音：实现与本机验收

结论与交付范围

已自动日用采用v0.1.14.1/epoch30、控制器10：同一Jarvis语音底座服务工作台、精简对话窗和英语学习；中文、英文、中英混说使用Jarvis模型中心管理的本地CPU小模型。实际语音就绪、三分钟观察和原数据对照已通过。 English City源码、引擎及发布包继续在项目目录外，不携带语音权重。正式采用回执。

正式第一次自动采用v0.1.14时，进程健康通过但语音服务在交接starting阶段被请求写入门拒绝。实际功能复核发现后，已只回退兼容代码，没有恢复数据库；不能把健康观察当语音可用证明。修正版v0.1.14.1分开初始化和请求准入，三项生命周期测试、原11项语音回归、215项固定独立检查及真实受管启动/兼容回退演练通过，随后再次自动采用及功能复核通过。原失败、修复与边界。

默认建议为 FunASR Nano CTC INT8导出版。它在本轮中文和英文样本上错误较少，SenseVoice WSYue变体的混说错误略少。仅各语言12段公开录音，不能断言通用最优；英文和混说误差仍明显，保留回听、编辑及确认发送。本人暂未提供录音，没有本人识别准确率、发音评分或长期学习收益结论。

改进本轮实际效果保留的限制
共用录音、STT、TTS端口三个入口实际录音后自动转写；中文/英文/混说本机朗读实际生成音频打开页面、刷新均不监听；尚无持续唤醒、可靠流式对话或自动交替说话
语音确认回接原对话同一请求只入原队列一次；沿当前模型、记忆、任务和权限处理转写文本可能按原路由交给在线LLM；本地LLM尚未接通，不称全离线聊天
原音、原识别、确认文字分开ASR错误更正保留痕迹，只有确认后的原话用于内容评价无法自动识别用户是否将原话改写成更好答案；仍需如实标记辅助
口语接学习与剧情原学习记录、错题、延迟复习、口语趋势和剧情接续复用来源评价是内容估计，未评价音素、发音、流利度或听力；合成测试不计本人学习
撤回、暂停与UNKNOWN迟到识别不采用；撤回后评价退出统计，依赖它的剧情停止接续不自动恢复已撤回的来源，也不重放不确定业务请求
按用途选择模型STT独立默认/上一模型/回退，不覆盖原embedding默认初期单路CPU；内存准入不是OS硬上限，仍可能争用CPU/RAM
新格式与恢复桥speech1、English4、模型选择3实际受管回退/返回通过；日用原数据对照通过恢复桥暂时禁用语音/学习输入，不恢复旧库；进程健康不保证任意业务质量

使用方式：本地模型管理中选择语音识别用途默认 → 工作台麦克风/语音对话按钮，或英语学习切换口语并开始场景 → 开始录音 → 停止后自动转写 → 回听及核对 → 确认发送/提交实际作答。模型在明确打开语音入口后可预热，不预先打开麦克风。文字入口和手动确认录音保留。

同样本本机实测

Windows、Ryzen AI Max+ 395、CPU两线程、ORT 1.24.3、NumPy 2.4.6；不使用CUDA或专用GPU。纯模型文件约237/264 MB，不能据此推断全部内存。

公开CAiRE/ASCEND main/test：先从前300条中筛2–15秒录音，按固定seed及ID的SHA排序，冻结中文/英文/混说各12段，再依次测试两模型。完整音频与参考转写保存在仓库外的验证数据目录；Git仅保留ID、摘要、指标和协议。上游训练是否见过这些录音未知，不称模型训练留出或本人样本。冻结协议、输入摘要、完整数值结果。

规范化固定为NFKC、小写、忽略标点；汉字按字符、英文/数字按词，混说合并单位计编辑距离。不改写数字、不做评测后提示优化。可用重算程序与仓库外转写重算；72个录音/模型配对的编辑数全部吻合。公开样本小，不能给各模型建立稳定排名或外推长句、噪声、远场与本人日常口音。

特征前端由本项目独立编写，与既有torchaudio Kaldi参考做固定随机输入数值比对，98×80矩阵最大绝对误差0.000164以内，结果。Nano采用CTC导出路径，不是完整0.8B自回归模型等效成绩。SenseVoice源实际标记WSYue变体，英文合成探测中语言标签曾输出粤语，因此语言/情绪标签不用于身份、评价或事实判断。

尚待验证与下一步

1. 本轮正式受管检查、备份、自动采用、三分钟观察、兼容恢复和原数据对照已完成；真实系统重新登录的自启尚未通过重启电脑验证。后续新业务仍需功能验收，不能仅靠进程健康。

2. 有本人录音后再做生活交流、沟通和工作资料各类准确率/数字否定/口音/噪声验收，先冻结参考和阈值。本人可以在实际使用时自愿积累并纠正，不自动收集环境声音。

3. 用跨日独立变式和延迟回忆验证学习提升；内容评价与识别错误分开，不用合成或同题重答抬高成绩。

4. 专门补可离线回答的本地LLM，再验“说→理解回答→发声”完整离线链；现阶段在线回答依然遵循原路由。

5. 后续再评流式识别、可靠VAD、回声/打断、更自然TTS及OS级网络隔离。当前最小静音能量判断不能冒称完整VAD，STT不能冒称发音评测或身份认证。
