<a id="studio3d-learning-scope"></a>
## 目标、范围与当前状态

用户于 2026-10-27 授权先保存具体步骤，再依本文实施。目标 accepted；下列工作包按实际证据分别登记；1.0.0 已实现受限工具闭环，完整美术学习与迁移收益仍 proposed。本文是 Studio3D 领域实施手册，复用 [K0—K6 主路线](core-bootstrap.md#bootstrap-5)、[经验编纂](knowledge-learning.md#experience-consolidation)与[知识贡献验收](delivery-validation.md#knowledge-value-ablation)，不建立第二套核心架构。

第一版服务于游戏用火炮及相似硬表面部件的外观制作、可见装配、材质、动画分组和交付验证。原始参考及高模母版保持可追溯；高模用户验收前不进行低模、投射烘焙或 LOD。AAA、历史精确复原及长期学习收益分别需要证据，不能由格式检查或面数替代。

现有 leFH18 经验来自一个资产，数十次候选不算数十个独立学习样本。其折叠侧翼属于当前资产要求；通用审查不得把这一要求强加给其他资产。知识内容、图片和模型输出均为资料，不能扩大工具权限。

<a id="studio3d-learning-runtime"></a>
## 接入位置与运行契约

- 领域知识和经验生命周期复用 `modules/context_knowledge` 的职责；Studio3D 经验使用明确的领域记录，不混入现有纯文本方法并假装兼容。
- 制作流程、参考策略和方法绑定归 `modules/skills/studio3d`；实际场景操作归 `adapters/studio3d` 的固定第一方工具。
- Host 负责启用状态、停止、路径与文件身份、工具执行、预算和收据；CLI 与工作台共享同一领域服务。
- 通用知识治理仍由[条件经验路由](knowledge-learning.md#conditional-experience-routing)与[迟到结果](knowledge-learning.md#experience-delayed-outcome)维护；领域实现记录版本、适用条件和未实现范围。

一次工具输入至少包含：资产身份、源模型摘要、方法版本、检查/修复范围、对象语义 ID、可动归属及有界参数。一次输出包含：实际源/结果摘要、改变对象、检查结果、渲染证据、工具版本、阶段耗时、费用已知/未知项与未解决问题。

工具先执行只读检查，再按已授权范围局部修改；禁止全场景随意重写。部件关系需区分组织父子关系、真实可见支撑关系和动画归属。缺少接触证据时保持未知，不用包围盒相交宣称装配正确。多轮没有改善时诊断停滞并退出本次有界运行，不无界重试。

<a id="studio3d-learning-methods"></a>
## 方法卡和可复用经验

方法卡包含：稳定 ID、版本、问题现象、适用条件、排除条件、原因及证据、检查工具、修复工具、验证要求、来源、反例和生命周期。区分事实、用户要求、推测和已验证方法。运行检索先判断范围/版本/条件及来源 SHA256 是否仍一致，再选择少量相关卡片；不把全部聊天反复发送给模型。

首批经验覆盖：多视图矛盾、相机误判、过度细分、表面投影与 UV 错误、悬空附件及删除残留、禁止零件复活、实际导出版本、可动部件合并、漆面与金属分区。`3DModels/leFH18/metadata/optimization-recipe.json` 继续维护该资产的具体要求；通用方法只引用来源和提炼后的条件，不复制全部资产规则。

晋升顺序：候选→本资产验证→跨资产验证。只有符合事前标准的独立资产结果才能扩大范围；迟到反例停用相关方法，保留历史采用记录。停用不能自动撤销用户当前资产，后续使用必须重新核对。格式通过、检查器通过、视觉近似、用户批准分别记录。

<a id="studio3d-learning-review-loop"></a>
## 比较与局部修复闭环

1. 固定参考来源、资产变体及用户纠正；记录图间冲突与未覆盖区域。
2. 建立部件身份、附件归属、材质和运动关系；检索匹配的方法。
3. 校准相机、构图、灯光和动画时刻，保存设置与摘要。
4. 渲染同一模型的五视图和指定局部；需要时输出对象 ID、法线和深度辅助定位。
5. 将差异分为相机、几何、材质、灯光；优先修复少量证据明确的问题。
6. 对改变对象及依赖部件复查，检查其他视图回归；失败保留前后证据并回退候选。
7. 对实际导出并重新导入的文件重复检查；确认预览文件身份。
8. 保存经验采用、工具动作、结果、人工介入及成本。完整高模仍需用户验收，之后才可低模与 LOD。

第一版允许部分检查仍需人工或视觉模型，必须明确显示未测；不得用生成图片重绘结果冒充真实模型渲染。

<a id="studio3d-learning-curriculum"></a>
## 24 项练习和收益评测

先登记 12 个制作学习任务、6 个开发验证任务、6 个留出验收任务，按独立资产/参考来源分组。训练覆盖折弯板与孔洞、轮毂、摇轮及支撑、附件归属、涂装金属、UV 与法线、运动分组、组合体和完整高模。开发/留出保留相近难度并包含不同变体，防止只会重复一个造型。

正式练习必须有独立目标参考和质量验收。工具回归小样、人工植入缺陷和同模型的多视图单独登记为诊断用例，不计入 24 项正式练习。留出结果一旦用于改方法，该任务退出留出组，另补未见任务。

比较固定模型/工具/硬件/参考/预算：基础流程、加事实、加条件方法、加执行技能。记录重大错误、轮廓与关键部件差异、重复错误、人工介入、修复轮数、阶段耗时、输入/输出 token、API 费用及失败尝试。未知费用保留 null；本地工具无 API 调用不代表设备、电力和作者成本为零。不能把各方法收益相加成“智能提升百分比”。

<a id="studio3d-teacher-demonstration"></a>
## Blender 示范、独立复做与经验验证方案

**2026-10-28 方案 v1，proposed；用户要求先形成完善方案，再进入实施。** 本节细化 S3DL-04—07，不另建实施路线。推荐采用：作者直接操作 Blender 制作有质量的局部示范，Jarvis 当轮读取真实前后证据，整理条件方法，再从修改前状态独立复做；成功后改变条件练习，最后用未参与教学的独立资产验收。该组合有望比继续扩大固定配方参数更有效，但速度与质量收益尚未实测，不能称为已证明的最优方案。

<a id="studio3d-teacher-baseline"></a>
### 当前瓶颈与方法选择

本轮只读核对的 PaK38 基线是 r25，212,208 个三角形；`metadata/current-model.json` 中近似目标门与用户批准仍为 false。补充实渲已经生成，视觉审查因 `model_timeout` 留有 UNKNOWN，控制器为 INTERRUPTED_OR_FAILED，未持续制作。已知账本为 309 次模型调用、1,646,552 token、约 2.865474 美元 API 估算，另有两项未知 API 成本；作者与本机成本未知，不能将该小计当作全部投入。这些是本轮读取快照，实时状态仍取资产回执。

当前 `production_loop.py` 让 Jarvis 从预写参数和造型变体中选择，每次最多四项；关键造型代码由作者编写。这能验证局部比较、回退与工具调用，却不足以让 Jarvis 自行补出工具尚不能表达的结构。24 项正式练习仍为 0/24；同一资产的多轮版本不构成跨资产学习证据。

| 方法 | 能产生的价值 | 主要不足 | 本方案用途 |
|---|---|---|---|
| 固定配方反复调参 | 已有形状的尺寸和变体调整，可测回归 | 未提供的形状与判断不会因循环次数增加自动出现 | 保留为成熟步骤的快速通道 |
| 只给 Jarvis 完成模型和总结 | 提供质量样本及术语 | 很难还原修改原因、操作顺序及失败边界 | 作为结果参考，不能单独证明会做 |
| 作者示范，记录动作和前后证据 | 同时提供目标、执行方法和实际结果 | 示范也可能错误；观看成功不等于独立执行 | 作为第一阶段主要投入 |
| 示范后独立复做、变题、反例与留出测试 | 能发现不会执行、过拟合与误用，并验证迁移 | 需要真实操作和可靠评价 | 作为是否获得能力的判断依据 |

研究提供的是方法依据：Reflexion 研究了不更新权重的文字反馈与经历记忆；Voyager 将可执行技能、任务安排与执行反馈组合；交互式模仿学习指出只观察专家轨迹可能在自己执行时累积错误。这支持“示范后亲自操作并纠错”的设计，但这些研究不证明 Blender 或本 Jarvis 的效果。[Reflexion](https://arxiv.org/abs/2303.11366)、[Voyager](https://arxiv.org/abs/2305.16291)、[Ross 与 Bagnell](https://proceedings.mlr.press/v9/ross10a.html)。

<a id="studio3d-teacher-tools"></a>
### 作者和 Jarvis 必须使用同一套可调用工具

作者负责最初的造型判断、示范与困难修正；Jarvis 负责观察差异、检索经验、选择操作、执行、检查和整理。Blender 负责实际几何与渲染；Host 继续掌管文件身份、资产锁、资源、停止和回执。经验管理复用现有领域存储，CLI 与工作台共用服务。换用其他推理/视觉模型时保持同一工具契约，重新做能力回归；不承诺任意模型都能达到同等质量。

“直接操作 Blender”优先使用可记录的 Blender Python 数据接口与第一方操作器，必要时才用界面。鼠标录像可辅助理解，不能替代精确动作记录。不能只在作者私有的 MCP 会话中做完，再留给 Jarvis 无法调用的文字；每项关键动作必须落到 Jarvis 自己可调用的接口或经过检查的固定脚本。界面手工编辑无法重放时，标记为手工步骤，另补可复现操作后才进入技能库。

首批补齐以下六类接口，名称和参数在实施时冻结；当前表格不是已上线的 API 清单：

| 接口职责 | 最小输入与结果 | 复用或修改位置 |
|---|---|---|
| 场景观察和局部定位 | 模型摘要、语义部件 ID → 变换、材质、连接关系、对象 ID 实渲；可明确返回定位未知 | `learning_contract.py`、`render_inspection.py` 及 inspection Worker |
| 检查点和示范记录 | 源文件、目标问题、作者身份 → 前后 BLEND、动作及回执；源摘要不一致拒绝执行 | `host/studio3d_learning.py` 扩展；拟增 `demonstration.py` 契约 |
| 可组合的局部建模 | 部件局部坐标系、轮廓/选区、受限参数 → 实际轮廓、挤出、旋转体、曲线、倒角等网格操作 | 现有 Worker 增加第一方操作器；保留 `semantic_patch.py` 的未改部件约束 |
| 材质与表面处理 | 部件/面域、材质角色、映射方式 → 漆面/露出金属/橡胶分区及 UV、法线检查 | 复用材质和导出模块，先做区域明确的工具 |
| 比较、验收与回退 | 前后资产、相机、问题单 → 技术检查、实渲、回归结果与采用/拒绝 | 复用 paired review、inspection、导出回读与现有状态机 |
| 经验整理与采用证明 | 原始证据 ID、动作、结论 → 候选方法、适用范围、拒用条件、实际采用回执 | 扩展 `Studio3DExperience`，沿现有来源校验和反例停用规则 |

可组合操作解决“永远只能选择预写造型”的限制，但不把它扩成任意模型生成 Python 立即执行。缺少操作器时，形成精确失败用例，由作者实现第一方工具并验证，再由 Jarvis 调用；作者介入照实记账。选择对象使用稳定语义身份与局部坐标系，不能把易变的面索引或对象序号当成跨资产常量。

目前桌面 Blender 正打开其他资产；PaK38 示范使用明确绑定该资产副本的专用 Worker/实例，不接管无关场景。连接、目录、操作和回执都以 PaK38 身份核对，不因发现 Blender MCP 工具就假设它已连接正确场景。

<a id="studio3d-teacher-record"></a>
### 示范保存成可验证的操作案例

一个案例针对一个可判断的局部问题，例如“轮组轮廓与层次不足”或“金属边缘出现错误斑点”。每次语义修改保存检查点，不为每次鼠标移动复制大模型。几何、材质、相机尽可能分开改，避免无法分清哪项产生效果。

| 记录项 | 必须保存的内容 |
|---|---|
| 问题和依据 | 用户目标、参考来源及摘要、区域、可见差异；事实、艺术目标、假设分别标注 |
| 修改前状态 | BLEND 和依赖材质清单、语义部件图、相机/灯光/色彩/姿态设置、真实渲染 |
| 实际动作 | 操作器及版本、目标语义 ID、参数与局部坐标系、前置条件、结果回执、作者/模型、时间 |
| 判断说明 | 简短可检查的选择理由、预期可见效果、已发现的失败原因；不伪造未记录的思考或操作历史 |
| 修改后状态 | BLEND、预览导出、同条件渲染、实际改动对象/材质、未改部件检查 |
| 检查和学习 | 检查通过/失败/未知、视觉对比、反例、候选经验版本、后续实际采用记录 |
| 全成本 | Jarvis 调用与 token、估算/实付分开、作者介入、本地与排队耗时、未知费用 |

拟定资产内路径：`metadata/demonstrations/<episode-id>/` 保存 `episode.json`、`actions.jsonl`、`checks.json`、`before/` 与 `after/`。同一二进制仅存一份，以摘要引用；关键前后 BLEND 和渲染不能只留易失的临时路径。大文件留在资产目录，不提交 Git。已有 leFH18 历史仅收录可核实的真实操作，无法还原的步骤明确写“缺失/推断”，不能倒填成录制证据。

文件摘要证明文件身份；跨运行复现验收比较实际几何、材质、层级与画面容差，不要求 BLEND 二进制或随机渲染逐字节一致。保存 Blender/工具/依赖版本和随机种子；容差在执行前固定。

<a id="studio3d-teacher-first-loop"></a>
### 第一轮怎样边做 PaK38 边教会 Jarvis

按以下顺序推进已有 S3DL-04/05，每个阶段都有可检查结果；不先搭一个庞大的学习平台再开始改善模型。

1. **冻结起点和问题。** 读取最新版本、进程、锁和未知请求；保留 r25 作为回退点。核对五参考的一致性，固定对照相机及三处优先问题。参考不一致处先形成决策记录，不能让每一轮追逐不同结构。未知付费请求只核查原记录，不重发；不因此阻断独立的本地示范准备。
2. **先打通一个真实案例。** 从轮组或涂装表面中选一项证据最清楚、效果最可见的局部。补齐最小记录器后，作者直接在 Blender 修改，保留前后文件和实渲；Jarvis 当轮观察并提出候选方法。示范本身须达到该局部的质量要求，失败也保存，不能因为作者做的就标优秀。
3. **立即检验能否独立复做。** Jarvis 从修改前副本开始，读取已确认案例与同一工具说明，自行选择参数、执行、渲染、复查；作者不补操作。机械重播完全相同参数仅证明可重放；由 Jarvis 自己组成步骤完成，才算该案例的独立复做。记录复制步骤与自主决策各占哪些部分。
4. **改变条件并测拒用。** 改部件命名、整体位置/尺度、外观轮廓或材料角色，至少包含一个不应套旧方法的例子；不得只换随机种子或视角。验证它能调整局部坐标和参数，并拒绝错误经验。PaK38 内的这种变题属于开发诊断，不计独立跨资产样本。
5. **再教下一处，逐步撤去帮助。** 从作者示范，过渡到只提供目标与关键纠正，再到 Jarvis 独立执行。优先扩展轮组、操作轮外观与支座、支架端部/附件、涂装材质。结构大错先修；重复紧固件只在承载面与尺寸确认后阵列，不能靠加铆钉或面数假装细节合格。
6. **合回候选并检查整件。** 每完成一个局部保存真实模型与可查看版本，检查五视图和相关局部回归。完整 PaK38 继续按高模目标制作；用户批准前不进入低模、投射烘焙或 LOD。完整独立新资产的 S3DL-07 验收仍留待后续指定，不自动开始新型号。

第一轮完成的定义是：**一个确实改善的局部示范、一份有来源的候选方法、一次 Jarvis 实际读取并执行、一次条件变化检查，以及可回退的完整证据**。其中任何项缺失，都不能报告“Jarvis 已经学会”。一个局部成功不代表整炮或其他型号合格。

<a id="studio3d-teacher-memory"></a>
### 经验怎样进入下一次行动

学习产物分成四种：原始操作案例用于追溯；条件方法用于选择；可执行技能用于稳定完成步骤；质量检查器用于发现错误。仅增加知识条数不算能力增长。生命周期、来源和反例治理继续归[方法卡](#studio3d-learning-methods)与[条件经验路由](knowledge-learning.md#conditional-experience-routing)。

每次 Jarvis 计划前先检查资产类型、当前问题、材料角色、工具版本和否定条件，再读取少量相关方法及必要案例裁图；开始时上限三条方法，冲突时保留未知或回到参考。记录“检索到、采用、调用成功、结果改善”四种不同事件。每个动作绑定所用方法版本与证据；复查时同时检查其预期后果和受影响区域，证明方法确实进入了行动。

方法正文采用“何时使用→怎样识别→操作与参数规则→怎样检查→何时拒用→失败回退”。例如“错误斑点”可能来自 UV、材质索引、法线或重叠面；应先用纯色、法线和材质分区实渲区分原因。只有切换材质就消失且几何检查支持时，才保留相应材质修复结论，不能归纳成“所有端面换一种材质”。这是一项拟验证的方法示例，不是本轮已定位的故障原因。

Jarvis 可自动整理和在明确范围内试用候选，晋升仍需证据审核。原始示范只能支持本资产；复做支持可重复执行；独立任务与反例支持扩大适用范围。发现反例时隔离相关方法版本、标记依赖案例并重新检查，保留失败，不把它简单删掉。经验没有带来改进时允许不入库；知识摘要不能偷偷删除限定条件或把推测改成事实。

这里首先获得的是**系统的可复用经验与工具能力**，不会通过看文件自动改变底层模型权重。少量案例阶段不启动微调；只有可复用技能仍不足、已积累有许可且一致的独立轨迹、并有留出基线时，才另行评估权重训练是否值得。模型替换与知识贡献分开测试，不能把更强模型的收益算成经验收益。

<a id="studio3d-teacher-evaluation"></a>
### 质量、独立性和速度分别验收

先冻结每处问题的目标参考、关键轮廓/部件、不可退化区域和检查方法。轮廓与比例、可见装配、细节形态、材质、游戏可动归属分开评价，不用一个“相似度 95%”掩盖严重缺陷。相机不一致的像素差不能当成几何真值；视觉模型评语和两个模型相互同意都不是独立事实证明。

三层核验：第一层由确定性检查确认文件身份、网格/材质/选区及未改区域；第二层使用实际同条件 Blender 渲染和局部对照，必要时用对象 ID/深度/法线辅助；第三层由不看作者结论的评审先列观察证据，再判断，并保留用户最终高模验收。严重穿插、悬空、错误面片、关键形状缺失、明显投影纹理错误及可动部件被错误合并均须解决或明确为未通过，不得被总体美观评分抵销。单次接触距离和几次姿态只证明所检查范围。

独立性分级记录：可自动重播 → Jarvis 自行复做 → 条件变化仍可完成且能拒用 → 未见独立资产通过。任何教师临时修形、手选参数、补脚本或指出位置都算介入；有介入的结果仍可交付，但不记为该阶段独立成功。生成器更复杂与学习更强分开报告。

收益实验沿[ABL-0—5](delivery-validation.md#knowledge-value-ablation)执行。最小先比较：相同工具的无历史经验流程、读取条件方法的流程、读取方法并使用验证技能的流程。复现相同任务不允许直接读取答案模型；一旦从结果得到纠正，它就成为开发案例，不再是留出题。新工具在所有比较组中同样可用；测试技能组合价值时单独标明调用方式差异，避免把工具扩充混算成记忆收益。模型、参考、质量门、硬件和预算固定。

先用少量开发变题检验机制能否运行，之后按[24 项独立练习](#studio3d-learning-curriculum)检验迁移。至少报告每题结果和样本数；小样本只支持初步观察，不承诺“做几个模型就学会”。质量达标后再比较端到端时间、调用/费用、重复错误、返工与作者介入；记录首轮教学建设成本和后续复用成本，不能只展示第二轮更便宜。若每次复用节省为正，可用初建成本除以同口径每次节省估计回本次数；没有实测节省时不预测回本。

<a id="studio3d-teacher-efficiency"></a>
### 让首轮更快及失败后如何推进

复用已装 Blender、现有 Jarvis 调用、语义部件、实渲和领域存储；第一轮不换建模软件、不训练权重、不新增数据库体系。先把一个局部案例跑通，再扩工具范围。修改大轮廓时用低采样实际预览；局部检查用原生高分辨率渲染区域，不能把低清图片放大充当细节证据；保留版本做五视图与关键局部，最终再提高完整表面渲染质量。

首轮控制参数为拟定默认值：一次只改一个语义问题及必要依赖对象；每问题最多三次自主修正；连续两次没有已确认改善就保留最佳版本并定位缺口。工具不支持则补工具，相机错误则校准，参考冲突则回到依据，不能换一段相同提示继续收费。停止该失败分支后仍可处理其他独立问题。检查器和渲染按文件、参数、相机与规则摘要缓存，任何相关输入变化均失效；质量门不因预算紧张而降低。

新付费调用沿当前资产的预算、未知请求和幂等规则执行，调用前核对实际剩余额度；不因增加教学自动上调预算。超时保持 UNKNOWN 并核查原请求，未核清不重放。作者示范和必要的本地检查可继续；独立 Jarvis 学习调用若受阻，准确显示等待原因。示范作者成本、本机计算、模型费与未知项均记账。

实时查看复用 `current-model.json` 的版本身份；实现和验证“跟随最新保留版本”及工作候选入口，显示文件摘要、更新时间、阶段、哪些检查已完成。页面无新模型时显示真实停止/等待状态，不能让轮询文字冒充正在建模。保留版与未验证工作版分开，渲染和 GLB 要绑定同一版本；不承诺逐次 Blender 鼠标编辑即时广播。

首轮不提供未经计时的完成时限。先报告一个局部案例的实际制作、录制、复做与核查耗时，再估计剩余部件；若录制整理成本超过重复利用价值，减少到关键语义步骤，不牺牲前后结果和失败证据。
